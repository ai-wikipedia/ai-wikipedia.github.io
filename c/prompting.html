프롬프팅

AI에게 원하는 답을 얻으려면 "무엇을 묻느냐"만큼 "어떻게 묻느냐"가 중요합니다. 같은 모델이라도 질문을 어떻게 설계하느냐에 따라 결과물의 품질이 몇 배씩 갈리기 때문에, 프롬프트를 다루는 기술은 하나의 독립된 분야가 됐습니다. 처음이라면 프롬프트 엔지니어링에서 전체 그림을 잡고, 모델이 단계적으로 생각하게 만드는 사고의 사슬(CoT), 모델의 기본 성격을 정하는 시스템 프롬프트로 넓혀가는 순서를 권합니다. 퓨샷·제로샷 같은 예시 제공 전략, XML 프롬프팅 같은 구조화 기법, 프롬프트를 코드처럼 버전 관리하는 프롬프트 매니지먼트까지 — 모델을 정확하게 다루기 위한 기법들을 모았습니다.
  • 감정 프롬프팅 Emotion Prompting프롬프트 끝에 "이건 정말 중요해" 같은 감정 섞인 문장을 붙여서 LLM이 더 신중하게 답하도록 하는 기법이다. 코드 리뷰나 글쓰기처럼 꼼꼼함이 결과를 좌우하는 일에 가볍게 써 볼 만하다.
  • 메타 프롬프트 Meta-PromptLLM에게 좋은 프롬프트를 대신 써 달라고 요청하는 프롬프트다. 시스템 프롬프트 초안을 빠르게 만들거나 이미 쓴 프롬프트를 다듬을 때 쓴다.
  • 사고의 사슬 Chain-of-Thought답을 바로 내지 않고 풀이 과정을 먼저 쓰게 해서 정확도를 높이는 프롬프팅 기법이다. 수학·논리·코드처럼 여러 단계를 거쳐야 하는 문제에 쓴다.
  • 셀프 컨시스턴시 Self-Consistency같은 질문을 여러 번 풀게 한 뒤 가장 많이 나온 답을 고르는 프롬프트 기법이다. 수학 계산이나 분류처럼 정답이 하나로 떨어지는 문제에서 정확도를 높이고 싶을 때 쓴다.
  • 시스템 프롬프트 System Prompt대화가 시작되기 전에 AI에게 역할, 규칙, 말투를 미리 정해 주는 지시문이다. 사용자가 무엇을 묻든 늘 지켜져야 하는 규칙을 정할 때 쓴다.
  • 역할 프롬프팅 Role PromptingLLM에게 "당신은 보안 전문가입니다"처럼 역할을 줘서 그 관점과 말투로 답하게 하는 기법이다. 답의 톤이나 관점, 집중할 부분을 정하고 싶을 때 쓴다.
  • 자동 프롬프트 최적화 Automatic Prompt Optimization사람이 프롬프트를 하나씩 고치는 대신, 예시 데이터와 채점 기준을 주면 시스템이 여러 후보를 시험해서 가장 좋은 프롬프트를 찾아 주는 방식이다. 정답이 분명한 작업을 반복해서 돌릴 때 쓴다.
  • 제로샷 Zero-Shot Prompting예시 없이 지시만으로 모델에게 작업을 시키는 프롬프팅 방식이다. 평소 ChatGPT나 Claude에 질문하는 방식이 대부분 여기에 해당하며, 새 작업을 시작할 때 가장 먼저 시도한다.
  • 출력 포맷팅 Output FormattingLLM의 답이 JSON, 마크다운, 정해진 템플릿처럼 원하는 형식으로 나오게 하는 기법이다. 사람이 읽을 글은 형식을 정리할 때, 프로그램이 받아 처리할 데이터는 파싱이 깨지지 않게 할 때 쓴다.
  • 컨텍스트 스터핑 Context Stuffing참고 문서를 골라 넣지 않고 통째로 프롬프트에 넣어, 필요한 부분은 LLM이 찾아 쓰게 하는 방식이다. 문서가 컨텍스트 창에 들어갈 만큼 작고 자주 바뀌지 않을 때 RAG 대신 쓴다.
  • 컨텍스트 엔지니어링 Context EngineeringLLM이 답하기 전에 보는 지시문, 도구 정의, 검색 결과, 대화 이력 같은 정보 전체를 무엇을 얼마나 언제 넣을지 설계하는 방법이다. 여러 단계를 스스로 처리하는 에이전트를 만들 때 특히 중요하다.
  • 트리 오브 쏘트 Tree of ThoughtLLM이 여러 갈래의 생각을 펼친 다음 각 갈래를 평가하고, 유망한 쪽만 더 파고드는 문제 풀이 방식이다. 퍼즐이나 계획 세우기, 설계안 고르기처럼 여러 길을 시도해 봐야 하는 문제에 쓴다.
  • 퓨샷 Few-Shot Prompting프롬프트에 원하는 입력과 출력의 예시를 몇 개 넣어, 모델이 그 패턴을 따라 답하게 만드는 기법이다. 파인튜닝 없이 답의 형식·어조·기준을 빠르게 맞추고 싶을 때 쓴다.
  • 프롬프트 엔지니어링 Prompt Engineering원하는 답을 안정적으로 얻으려고 AI에게 주는 입력을 체계적으로 짜는 요령이다. 요약 조건 지정, 출력 형식 고정, 에이전트 규칙 설정처럼 AI에게 일을 맡길 때마다 쓴다.
  • 프롬프트 체이닝 Prompt Chaining큰 작업을 여러 단계로 나눠 LLM을 여러 번 부르고, 앞 단계의 결과를 다음 단계의 입력으로 넘기는 방식이다. 한 번에 시키면 품질이 떨어지고 순서가 정해진 작업에 쓴다.
  • 하네스 엔지니어링 Harness EngineeringAI 모델 자체가 아니라 모델을 감싸는 맥락·도구·가드레일·검증 구조를 설계하는 일이다. 같은 모델인데 프로젝트마다 결과가 들쭉날쭉하거나 에이전트에게 긴 작업을 맡길 때 쓴다.
  • XML 프롬프팅 XML Prompting프롬프트 안의 지시, 참고 자료, 예시, 사용자 입력을 XML 태그로 감싸서 서로 섞이지 않게 나누는 방법이다. 프롬프트가 길고 여러 종류의 내용이 함께 들어갈 때 쓴다.
