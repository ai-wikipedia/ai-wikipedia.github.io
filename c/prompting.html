프롬프팅

AI에게 원하는 답을 얻으려면 "무엇을 묻느냐"만큼 "어떻게 묻느냐"가 중요합니다. 같은 모델이라도 질문을 어떻게 설계하느냐에 따라 결과물의 품질이 몇 배씩 갈리기 때문에, 프롬프트를 다루는 기술은 하나의 독립된 분야가 됐습니다. 처음이라면 프롬프트 엔지니어링에서 전체 그림을 잡고, 모델이 단계적으로 생각하게 만드는 사고의 사슬(CoT), 모델의 기본 성격을 정하는 시스템 프롬프트로 넓혀가는 순서를 권합니다. 퓨샷·제로샷 같은 예시 제공 전략, XML 프롬프팅 같은 구조화 기법, 프롬프트를 코드처럼 버전 관리하는 프롬프트 매니지먼트까지 — 모델을 정확하게 다루기 위한 기법들을 모았습니다.
  • 사고의 사슬 Chain-of-Thought답을 바로 내지 않고 풀이 과정을 먼저 쓰게 해서 정확도를 높이는 프롬프팅 기법이다. 수학·논리·코드처럼 여러 단계를 거쳐야 하는 문제에 쓴다.
  • 시스템 프롬프트 System Prompt대화가 시작되기 전에 AI에게 역할, 규칙, 말투를 미리 정해 주는 지시문이다. 사용자가 무엇을 묻든 늘 지켜져야 하는 규칙을 정할 때 쓴다.
  • 제로샷 Zero-Shot Prompting예시 없이 지시만으로 모델에게 작업을 시키는 프롬프팅 방식이다. 평소 ChatGPT나 Claude에 질문하는 방식이 대부분 여기에 해당하며, 새 작업을 시작할 때 가장 먼저 시도한다.
  • 퓨샷 Few-Shot Prompting프롬프트에 원하는 입력과 출력의 예시를 몇 개 넣어, 모델이 그 패턴을 따라 답하게 만드는 기법이다. 파인튜닝 없이 답의 형식·어조·기준을 빠르게 맞추고 싶을 때 쓴다.
  • 프롬프트 엔지니어링 Prompt Engineering원하는 답을 안정적으로 얻으려고 AI에게 주는 입력을 체계적으로 짜는 요령이다. 요약 조건 지정, 출력 형식 고정, 에이전트 규칙 설정처럼 AI에게 일을 맡길 때마다 쓴다.
