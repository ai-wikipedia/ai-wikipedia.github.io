데이터

AI가 최신 정보나 내 문서를 근거로 답하려면 데이터를 잘 다뤄야 합니다. 모델은 학습 시점 이후의 일을 모르고 회사 내부 문서도 본 적이 없기 때문에, 필요한 지식을 검색해서 모델에게 건네주는 파이프라인이 필요합니다. 그 뼈대가 RAG이고, 문서를 검색 가능한 형태로 바꾸는 임베딩, 그것을 저장·검색하는 벡터 DB, 문서를 적절한 크기로 자르는 청킹이 각 단계를 담당합니다. 검색 품질을 끌어올리는 리랭킹·하이브리드 검색, 지식을 그래프로 연결하는 GraphRAG까지 — 검색과 지식 연결에 관한 개념들을 순서대로 모았습니다.
  • 그래프 RAG Graph RAG문서에서 사람·조직·개념 같은 엔티티와 그 관계를 뽑아 지식 그래프로 만든 뒤, 그 그래프를 따라가며 답을 찾는 RAG 방식이다. 여러 문서에 흩어진 정보를 엮거나 "전체 주제가 뭐냐" 같은 큰 질문에 답해야 할 때 쓴다.
  • 데이터 레이블링 Data Labeling학습 데이터에 정답이나 평가를 붙이는 작업이다. SFT용 모범 답 작성이나 RLHF용 선호 비교처럼, LLM을 파인튜닝하거나 정렬할 데이터를 만들 때 쓴다.
  • 데이터 증강 Data Augmentation학습 데이터를 조금씩 바꾸거나 LLM으로 비슷한 예시를 만들어 양을 늘리는 기법이다. 특정 분야의 데이터가 부족해 파인튜닝이나 모델 학습 성능이 잘 나오지 않을 때 쓴다.
  • 데이터 큐레이션 Data Curation데이터 큐레이션은 모델 학습이나 RAG에 쓸 데이터를 모으고, 정리하고, 좋은 것만 골라내는 과정이다. 파인튜닝 데이터를 준비하거나 RAG 문서를 정리할 때, 모델을 바꾸기 전에 먼저 하는 일이다.
  • 데이터 파이프라인 Data Pipeline데이터를 원천에서 가져와 정리·검증한 뒤 필요한 곳에 넣어 주는 자동화된 처리 흐름이다. AI에서는 학습 데이터를 준비하거나 RAG 지식 베이스를 최신으로 유지할 때 쓴다.
  • 데이터 플라이휠 Data Flywheel데이터 플라이휠은 서비스를 쓰면서 쌓인 데이터로 모델을 개선하고, 나아진 서비스가 다시 더 많은 데이터를 모으는 선순환 구조다. 사용자 반응을 모을 수 있는 AI 서비스라면 설계 단계부터 반영해 두면 좋다.
  • 리랭킹 Reranking1차 검색으로 가져온 후보 문서를 더 정밀한 모델로 다시 채점해 순위를 새로 매기는 단계다. RAG에서 LLM에 넘길 문서를 고를 때, 답변 품질을 손쉽게 높이고 싶을 때 쓴다.
  • 멀티모달 임베딩 Multimodal Embedding글, 사진, 오디오처럼 형식이 다른 데이터를 같은 벡터 공간에 숫자로 표현하는 기술이다. 글로 사진을 찾거나 사진으로 비슷한 상품을 찾는 것처럼 형식을 넘나드는 검색에 쓴다.
  • 멀티모달 RAG Multimodal RAG텍스트뿐 아니라 이미지·표·차트가 섞인 문서에서도 정보를 찾아 답하도록 넓힌 RAG다. 도표나 그림에 핵심 정보가 담긴 PDF·발표 자료·매뉴얼을 다룰 때 쓴다.
  • 문서 파싱 Document ParsingPDF, 워드, 스캔 이미지 같은 문서에서 텍스트와 표·제목 같은 구조를 뽑아 LLM이 읽을 수 있게 바꾸는 작업이다. RAG를 만들 때 가장 먼저 거치는 단계이고, 여기서 나온 결과의 품질이 검색 정확도를 좌우한다.
  • 벡터 DB Vector Database임베딩 벡터를 저장해 두고 의미가 가장 비슷한 항목을 빠르게 찾아 주는 데이터베이스로, 값이 정확히 일치하는 것을 찾는 일반 데이터베이스와 달리 뜻이 가까운 것을 찾는다. AI가 사내 문서를 참고해 답하는 RAG에서 검색 엔진으로 쓴다.
  • 비정형 데이터 Unstructured Data비정형 데이터는 이메일, PDF 계약서, 회의 녹음, 리뷰처럼 행과 열로 정리되지 않은 데이터다. 문서 속 정보를 LLM이나 RAG로 검색하고 활용하려면 먼저 이 데이터를 AI가 다루기 좋은 형태로 바꿔야 한다.
  • 시맨틱 캐시 Semantic Cache질문의 뜻이 예전 질문과 비슷하면 LLM을 다시 부르지 않고 저장해 둔 답을 돌려주는 캐시다. FAQ처럼 비슷한 질문이 자주 반복되는 서비스에서 비용과 응답 시간을 줄일 때 쓴다.
  • 온톨로지 Ontology특정 분야의 개념과 그 관계를 기계가 읽을 수 있게 정의한 지식 설계도다. 지식 그래프를 만들거나 LLM이 문서에서 그래프를 뽑을 때 기준이 되는 틀로 쓴다.
  • 임베딩 Embedding텍스트·이미지·코드를 숫자 목록(벡터)으로 바꾸는 기술로, 뜻이 비슷할수록 벡터끼리 가까워져 겹치는 글자가 없어도 같은 뜻의 문서를 찾을 수 있다. 키워드가 아니라 뜻으로 찾아야 할 때 쓰며, RAG 검색, 추천, 중복 문서 찾기가 모두 이 원리로 돌아간다.
  • 지식 그래프 Knowledge Graph사람·회사·제품 같은 대상과 그 사이 관계를 점과 선으로 저장한 데이터베이스다. 여러 단계의 관계를 따라가야 답이 나오는 질문에 쓰고, AI에서는 RAG 검색을 더 정확하게 하거나 LLM 답변을 사실로 받쳐 주는 데 쓴다.
  • 청킹 Chunking청킹은 긴 문서를 벡터 DB에 넣기 전에 검색하기 좋은 작은 조각으로 쪼개는 전처리로, RAG를 만들 때 반드시 거치는 단계다. 어떻게 자르느냐가 검색 품질의 상한선을 정한다.
  • 컨텍스트 압축 Context Compression긴 대화 이력이나 문서에서 지금 필요한 정보만 남기고 나머지는 요약하거나 덜어내는 기법이다. 대화가 길어지는 에이전트나 검색 결과가 긴 RAG에서 비용을 줄이고 답의 정확도를 지킬 때 쓴다.
  • 하이브리드 검색 Hybrid Search하이브리드 검색은 단어가 똑같은 문서를 찾는 키워드 검색(BM25)과 뜻이 비슷한 문서를 찾는 벡터 검색을 함께 돌려 결과를 합치는 방식이다. RAG에서 모델명·에러코드 같은 정확한 단어와 바꿔 말한 질문을 둘 다 잘 찾아야 할 때 쓴다.
  • 합성 데이터 Synthetic Data실제로 모은 데이터 대신 AI나 알고리즘으로 만든 인공 데이터다. 데이터가 부족하거나 개인정보 때문에 실제 데이터를 쓰기 어려울 때 학습 데이터를 늘리는 데 쓴다.
  • RAG Retrieval-Augmented GenerationLLM이 답하기 전에 외부 문서나 DB에서 관련 내용을 찾아 프롬프트에 넣어 주는 기술로, 모델에게 오픈북 시험을 보게 하는 방식이다. 바뀐 사내 규정이나 회사 DB에만 있는 정보처럼 모델이 배우지 못한 내용을 근거와 함께 답하게 하고, 지어내는 답(환각)을 줄이고 싶을 때 쓴다.
