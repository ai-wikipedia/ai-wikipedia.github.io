데이터

AI가 최신 정보나 내 문서를 근거로 답하려면 데이터를 잘 다뤄야 합니다. 모델은 학습 시점 이후의 일을 모르고 회사 내부 문서도 본 적이 없기 때문에, 필요한 지식을 검색해서 모델에게 건네주는 파이프라인이 필요합니다. 그 뼈대가 RAG이고, 문서를 검색 가능한 형태로 바꾸는 임베딩, 그것을 저장·검색하는 벡터 DB, 문서를 적절한 크기로 자르는 청킹이 각 단계를 담당합니다. 검색 품질을 끌어올리는 리랭킹·하이브리드 검색, 지식을 그래프로 연결하는 GraphRAG까지 — 검색과 지식 연결에 관한 개념들을 순서대로 모았습니다.
  • 리랭킹 Reranking1차 검색으로 가져온 후보 문서를 더 정밀한 모델로 다시 채점해 순위를 새로 매기는 단계다. RAG에서 LLM에 넘길 문서를 고를 때, 답변 품질을 손쉽게 높이고 싶을 때 쓴다.
  • 벡터 DB Vector Database임베딩 벡터를 저장해 두고, 의미가 가장 비슷한 항목을 빠르게 찾아 주는 데이터베이스다. AI가 문서를 참고해 답하는 RAG에서 검색 엔진으로 쓴다.
  • 비정형 데이터 Unstructured Data비정형 데이터는 이메일, PDF 계약서, 회의 녹음, 리뷰처럼 행과 열로 정리되지 않은 데이터다. 문서 속 정보를 LLM이나 RAG로 검색하고 활용하려면 먼저 이 데이터를 AI가 다루기 좋은 형태로 바꿔야 한다.
  • 온톨로지 Ontology특정 분야의 개념과 그 관계를 기계가 읽을 수 있게 정의한 지식 설계도다. 지식 그래프를 만들거나 LLM이 문서에서 그래프를 뽑을 때 기준이 되는 틀로 쓴다.
  • 임베딩 Embedding텍스트·이미지·코드를 뜻이 담긴 숫자 목록(벡터)으로 바꾸는 기술이다. 키워드가 아니라 뜻으로 문서를 찾아야 할 때, 특히 RAG 검색에 쓴다.
  • 청킹 Chunking청킹은 긴 문서를 벡터 DB에 넣기 좋은 작은 조각으로 쪼개는 전처리다. RAG를 만들 때 반드시 거치며, 자르는 방식에 따라 검색 정확도가 크게 달라진다.
  • RAG Retrieval-Augmented GenerationLLM이 답하기 전에 외부 문서나 DB에서 관련 내용을 찾아 프롬프트에 넣어 주는 기술이다. 사내 문서나 최신 정보처럼 모델이 배우지 못한 내용으로 근거 있는 답을 받고 싶을 때 쓴다.
