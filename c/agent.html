에이전트

스스로 판단하고 도구를 써서 일을 끝까지 처리하는 것이 AI 에이전트입니다. 한 번 묻고 한 번 답하는 챗봇과 달리, 에이전트는 목표를 받으면 계획을 세우고 도구를 골라 쓰고 결과를 확인하며 여러 단계를 돌립니다. AI 에이전트 항목에서 기본 그림을 잡은 뒤, 생각과 행동을 번갈아 반복하는 ReAct 패턴, 여러 에이전트가 역할을 나누는 멀티에이전트, 작업 기억을 유지하는 에이전트 메모리로 확장해보세요. 에이전트끼리 통신하는 A2A 같은 프로토콜, 브라우저를 조작하는 컴퓨터 유즈, 에이전트를 평가하는 방법론까지 — "알아서 일하는 AI"를 이해하는 키워드를 모았습니다.

  • 에이전트 핸드오프 Agent Handoff에이전트가 자기 역할 밖의 요청을 받았을 때, 그 일에 맞는 다른 에이전트에게 대화의 주도권과 맥락을 함께 넘기는 방식이다. 상담원이 기술 문의 전화를 기술팀으로 돌리듯 사용자가 같은 말을 되풀이하지 않게 하며, 고객 지원처럼 담당 분야가 뚜렷하게 나뉘는 멀티에이전트 시스템에서 쓴다.

  • 에이전틱 OS Agentic Operating System운영체제가 프로그램에 메모리와 파일을 나눠 주듯, AI 에이전트에게 기억·도구·권한·작업 조율을 한곳에서 관리해 주는 운영 계층이다. 에이전트가 금방 길을 잃어 맥락을 매번 다시 알려줘야 하는 문제를 줄이고, 며칠짜리 작업을 이어서 맡기고 싶을 때 쓴다.
  • 에이전틱 RAG Agentic RAG에이전틱 RAG는 기본 RAG처럼 한 번 검색하고 끝내지 않는다. AI 에이전트가 무엇을, 어디서, 몇 번 검색할지 스스로 정하고 결과까지 검증하는 방식이다. 결과가 부족하면 질문을 바꿔 다시 찾고 여러 자료를 비교하므로, 한 번 검색으로는 답이 나오지 않는 복잡한 질문에 쓴다.
  • 오케스트레이션 패턴 Orchestration Pattern여러 AI 에이전트가 누가, 언제, 어떤 순서로 일할지 정하는 설계 방식으로, 실행 순서와 중간 결과를 넘기는 방법, 실패했을 때의 처리까지 미리 정해 둔다. 한 에이전트로는 감당하기 어려운 큰 작업이나 단계가 뚜렷하게 나뉘는 일을 역할별로 나눠 처리할 때 쓴다.
  • 오픈 멀티 에이전트 Open Multi-Agent목표 한 줄을 주면 할 일을 작업 그래프(task DAG)로 자동 분해해 여러 에이전트에게 나눠 맡기는 오픈소스 실행 프레임워크다. 멀티 에이전트에서 "누가 무슨 일을 어떤 순서로 할지"를 손으로 엮지 않고, 목표 입력부터 결과 취합까지 한 번에 돌리고 싶을 때 쓴다.
  • 오픈클로 OpenClaw오픈클로는 내 컴퓨터에서 돌아가는 오픈소스 AI 비서다. 일반 챗봇처럼 질문에 답만 하지 않고, 텔레그램·왓츠앱·슬랙 같은 메신저로 말을 걸면 파일 정리·브라우저 조작·메일과 일정 관리 같은 실제 작업을 직접 해 준다.
  • 오픈태그 OpenTagOpenTag은 Slack이나 Teams 채널에서 AI를 멘션해 일을 맡기면 결과를 같은 스레드에 올려 주는 'AI 동료'형 에이전트다. Claude Tag와 쓰는 방식은 같지만 특정 모델에 묶이지 않아, 작업마다 모델을 고르거나 더 좋은 모델로 갈아 끼우거나 직접 서버를 운영하고 싶을 때 쓴다.
  • 이브 Eve (Vercel Agent Framework)eve는 Vercel이 오픈소스로 공개한 에이전트 프레임워크로, 지시문 마크다운과 도구 TypeScript 파일을 정해진 위치에 넣은 폴더 하나가 곧 에이전트 설계도가 되어, 중단돼도 이어서 실행되는 운영용 서비스로 Vercel에 배포된다. Vercel 위에서 Slack 봇이나 정기 리포트 같은 에이전트를 직접 연결 작업 없이 빨리 띄우고 싶을 때 쓴다.
  • 자기학습 에이전트 Self-Improving Agent일을 마칠 때마다 결과를 돌아보고 잘된 방법은 스킬로, 실패는 교훈으로 저장해 쓸수록 더 잘하게 되는 에이전트다. 정해 둔 도구와 프롬프트 안에서만 움직이는 일반 에이전트와 달리 새 능력을 스스로 만들어 쌓기 때문에, 비슷한 작업을 자주 맡기는 반복 업무나 오래 쓰는 개인 에이전트에 잘 맞는다.
  • 자율 에이전트 Autonomous Agent목표와 완료 기준만 주면 스스로 계획하고, 도구를 쓰고, 결과를 확인하며 끝까지 일을 처리하는 AI 에이전트다. 단계마다 지시하는 방식보다 빠르지만 잘못된 방향으로 가도 중간에 잡기 어렵다. 그래서 테스트 작성처럼 결과를 바로 검증하고 되돌릴 수 있는 작업을 맡길 때 쓴다.
  • 컴퓨터 사용 Computer Use컴퓨터 사용(Computer Use)은 AI가 화면 캡처를 보고 마우스와 키보드를 움직여 사람처럼 컴퓨터를 조작하는 기능으로, Anthropic이 Claude 3.5 Sonnet과 함께 처음 공개했다. API가 없는 오래된 프로그램이나 웹 화면 작업을 자동화할 때 쓴다.
  • 코드 에이전트 하네스 Code as Agent HarnessLangGraph·CrewAI 같은 전용 프레임워크 대신 Python·JavaScript 같은 평범한 코드로 에이전트의 실행 순서와 분기를 직접 짜는 방식으로, 이렇게 짠 코드가 그대로 여러 에이전트를 조율하는 하네스가 된다. 흐름을 끝까지 직접 통제하고 코드를 그대로 읽으며 디버깅하고 싶을 때 쓴다.
  • 코드 인터프리터 Code InterpreterAI가 격리된 실행 환경(샌드박스)에서 코드를 직접 짜서 실행하고, 오류가 나면 스스로 고쳐 다시 돌린 뒤 그 결과로 답하는 기능이다. 글로만 답하면 틀리기 쉬운 계산, 데이터 분석, 그래프 그리기, 파일 변환처럼 정확한 결과가 필요할 때 쓴다.
  • 크루AI CrewAICrewAI는 역할·목표·배경을 가진 여러 에이전트를 팀처럼 묶어 함께 일하게 하는 파이썬 오픈소스 프레임워크다. 앞 에이전트가 낸 결과를 다음 에이전트가 이어받아 최종 결과물을 만드는 구조라, 조사→작성→검토처럼 단계가 분명한 일을 자동화할 때 쓴다.
  • 크리틱 패턴 Critic Pattern답을 쓰는 AI 옆에 채점하는 AI를 두어 점수나 피드백을 주게 하는 구조로, 답변이 너무 많아 사람이 다 검토할 수 없을 때 품질을 자동으로 재고 고치는 데 쓴다. 채점만 따로 쓰면 LLM-as-a-Judge라고 부르고, 생성·평가·수정을 반복하면 평가자-최적화자(evaluator-optimizer)라고 부른다.
  • 태스크 분해 Task Decomposition큰 작업을 AI가 하나씩 처리하고 점검할 수 있는 작은 단계로 나누는 방법이다. 여러 단계가 얽힌 코딩·조사·문서 작업을 에이전트에게 맡길 때 가장 먼저 할 일이다.
  • 툴 콜링 Tool CallingLLM이 외부 함수나 API를 어떤 인자로 부를지 호출 요청만 정해진 형식으로 적어 주고, 실제 실행은 개발자 코드가 맡는 기능이다. 최신 정보 조회, 계산, DB 검색, 파일 수정처럼 모델 혼자서는 못 하는 일을 맡길 때 쓴다.
