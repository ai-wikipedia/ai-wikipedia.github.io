인프라

AI 시스템을 실제로 안정적으로 굴리려면 뒷단의 기반이 필요합니다. 데모에서는 잘 되던 것이 실서비스에서 무너지는 이유는 대부분 이 계층에 있습니다. 모델이 한 번에 기억할 수 있는 양을 정하는 컨텍스트 윈도우, 응답 품질을 수치로 검증하는 평가(Eval), 같은 질문에 대한 비용을 아끼는 프롬프트 캐싱, 여러 모델을 하나의 창구로 묶는 LLM 게이트웨이가 대표 개념입니다. GPU 클러스터·배치 추론·레이턴시 최적화처럼 서빙 성능에 관한 용어, 관측가능성·트레이싱처럼 운영 품질에 관한 용어까지, 운영과 확장에 관한 개념들을 모았습니다.
  • 내구성 실행 Durable Execution내구성 실행(Durable Execution)은 코드가 실행되는 동안 단계마다 결과를 저장해 두는 방식이다. 프로세스가 죽어도 처음부터 다시 돌리지 않고 마지막으로 끝낸 단계부터 이어서 실행한다. 결제나 오래 걸리는 워크플로우, AI 에이전트처럼 중간에 끊기면 안 되는 작업에 쓴다.
  • 라마파일 llamafileLLM 모델과 실행 엔진을 파일 하나로 묶은 Mozilla의 오픈소스 도구다. 설치 없이 파일만 실행하면 내 컴퓨터에서 AI를 돌릴 수 있어, 로컬 LLM을 처음 써 보거나 오프라인 환경에 모델을 가져갈 때 쓴다.
  • 런에이아이 NVIDIA Run:ai (Kubernetes GPU Orchestration)쿠버네티스 위에서 여러 팀이 GPU를 나눠 쓰도록 할당과 스케줄링을 자동으로 처리하는 엔비디아의 플랫폼이다. 노트북 실험, 학습, 추론 작업이 같은 GPU 클러스터를 두고 경쟁할 때 쓴다.
  • 레이턴시 최적화 Latency OptimizationLLM이 첫 글자를 내놓기까지 걸리는 시간과 답을 끝내기까지 걸리는 시간을 줄이는 방법 모음이다. 채팅이나 음성 비서처럼 사용자가 답을 기다리는 서비스에서 쓴다.
  • 모델 서빙 Model Serving모델 서빙은 학습된 모델을 서버에 올려 사용자 요청에 실시간으로 답하게 하는 일이다. 오픈 모델을 내 서버에서 돌리거나, 데이터를 밖으로 보낼 수 없어 API 대신 직접 운영해야 할 때 쓴다.
  • 배치 추론 Batch Inference급하지 않은 LLM 요청을 많이 모아 한꺼번에 맡기고, 결과는 나중에 받는 방식이다. 문서 분류·대량 번역·야간 리포트처럼 바로 답이 필요 없는 대량 작업에서 비용을 줄일 때 쓴다.
  • 벤치마크 Benchmark벤치마크는 AI 모델에게 같은 문제를 풀게 해 점수로 성능을 비교하는 표준 시험이다. 모델을 고를 때 대략적인 기준으로 쓰고, 실제로 도입하기 전에는 내 업무로 만든 평가로 다시 확인한다.
  • 비용 최적화 LLM Cost OptimizationLLM API 비용을 품질은 그대로 두고 줄이는 방법들이다. 프롬프트 캐싱, 모델 라우팅, 배치 처리, 토큰 줄이기를 상황에 맞게 섞어 쓴다.
  • 스트리밍 Token StreamingLLM이 답을 다 만들기 전에, 토큰이 생성되는 대로 바로 보내 주는 방식이다. 채팅 화면처럼 사람이 직접 읽는 곳에서 기다리는 느낌을 줄이려고 쓴다.
  • 에비던스 게이트 Evidence GateAI 에이전트가 만든 코드를 다음 단계로 넘기기 전에, 에이전트에게 보이지 않는 기준으로 서버에서만 평가하는 검문소다. AI가 코드와 테스트를 함께 쓰는 파이프라인에서, AI가 통과 기준에만 맞춰 점수를 따는 것을 막을 때 쓴다.
  • 연속 배칭 Continuous BatchingLLM 서버가 끝난 요청 자리에 대기 중인 새 요청을 바로 넣어 GPU를 쉬지 않게 하는 스케줄링 방식이다. 길이가 제각각인 요청이 많이 몰리는 챗봇·API 서비스에서 처리량을 크게 높일 때 쓴다.
  • 온디바이스 AI On-Device AIAI 모델을 클라우드 서버가 아니라 스마트폰·노트북 같은 기기 안에서 직접 돌리는 방식이다. 인터넷 없이 써야 하거나 데이터를 밖으로 보내면 안 될 때 쓴다.
  • 옵저버빌리티 LLM ObservabilityLLM 앱이 어떤 프롬프트로 무엇을 답했고, 시간과 비용이 얼마나 들었는지 호출 단위로 기록해 보여주는 시스템이다. 답이 이상하거나 에이전트가 중간에 꼬였을 때 원인을 찾는 데 쓴다.
  • 추론 최적화 Inference Optimization추론 최적화는 이미 학습된 LLM이 답을 만들 때 더 빠르고 싸게 돌아가게 하는 기술을 통틀어 부르는 말이다. 모델을 직접 띄워 서비스하거나 로컬에서 돌릴 때 양자화, 추측적 디코딩, KV 캐시 최적화를 함께 쓴다.
  • 컨텍스트 윈도우 Context Window컨텍스트 윈도우는 LLM이 한 번에 볼 수 있는 토큰 수의 상한선이다. 긴 문서나 코드베이스를 한꺼번에 맡기거나 긴 대화를 이어갈 때 이 한도와 실제로 품질이 유지되는 길이를 따져 봐야 한다.
  • 텐서 병렬화 Tensor Parallelism모델의 큰 가중치 행렬을 여러 GPU에 나눠 각 GPU가 연산 일부를 맡게 하는 분산 기법이다. GPU 한 장에 다 안 들어가는 큰 모델을 학습하거나 서빙할 때 쓴다.
  • 토큰 경제학 Token EconomicsAI가 읽고 쓰는 토큰을 비용과 생산성의 기본 단위로 보고, 사용량을 재고 줄이고 예산을 짜는 관점이다. 코딩 에이전트처럼 토큰을 많이 쓰는 작업에서 비용을 관리할 때 쓴다.
  • 토큰 예산 Token Budget토큰 예산은 추론 모델이 답하기 전에 "생각"하는 데 쓸 수 있는 토큰의 최대치를 정하는 설정이다. 어려운 문제에는 크게, 단순한 작업에는 작게 잡아 답의 품질과 비용·속도를 맞출 때 쓴다.
  • 토큰맥싱 Tokenmaxxing토큰맥싱은 AI 토큰을 얼마나 많이 썼는지를 성과로 보고 사용량을 일부러 늘리는 행동이다. 빅테크가 사내 리더보드로 AI 활용을 독려하면서 생긴 직장 문화 현상이다.
  • 파일럿피시 PilotfishPilotFish는 서로 다른 시스템 사이에서 데이터 형식을 바꿔 주고 알맞은 곳으로 보내 주는 데이터 통합 플랫폼이다. 오래된 사내 시스템이나 의료 시스템을 새 AI 서비스와 연결할 때 중간 연결 레이어로 쓴다.
  • 펠리컨 벤치마크 Pelican on a Bicycle Benchmark사이먼 윌리슨이 만든 비공식 LLM 테스트로, 모델에게 "자전거 타는 펠리컨 SVG를 그려라" 한 문장만 주고 결과 그림을 비교한다. 새 모델이 나왔을 때 코드 생성 능력과 공간 감각을 빠르게 훑어볼 때 쓴다.
  • 프로토콜 전쟁 AI Protocol WarsAI 에이전트를 도구에 연결하고 에이전트끼리 대화하게 하는 표준을 두고 MCP·A2A·ACP가 벌인 경쟁이다. 지금은 도구 연결은 MCP, 에이전트 협업은 A2A로 역할이 나뉘었고, 에이전트를 만들 때 무엇을 쓸지 고르는 기준이 된다.
  • 프롬프트 캐싱 Prompt Caching매번 똑같이 보내는 긴 프롬프트 앞부분을 서버가 잠시 저장해 두고 다음 요청에서 다시 쓰는 기능이다. 같은 문서나 시스템 프롬프트를 반복해서 보내는 챗봇·코딩 에이전트에서 입력 비용과 응답 지연을 크게 줄일 때 쓴다.
  • 픽스파이프 PxPipe (Image-Based Token Compression)이미지를 모델에 넣을 때 생기는 시각 토큰 수를 줄여 비용과 응답 시간을 낮추는 압축 방식이다. 고해상도 이미지나 긴 영상, 긴 문서를 컨텍스트 안에 넣어야 할 때 쓴다.
  • AI 칩 AI Custom ChipAI 칩은 AI 모델의 학습과 추론에 필요한 대규모 행렬 계산만 빠르고 싸게 처리하도록 만든 반도체다. 개발자는 보통 클라우드에서 GPU 대신 TPU나 Trainium 같은 인스턴스를 고르는 방식으로 쓴다.
  • AI 평가 EvaluationAI 모델이나 서비스가 얼마나 잘 동작하는지 미리 만든 시험지로 점수를 매기는 과정이다. 프롬프트를 고치거나 모델을 바꿀 때마다 돌려서 정말 좋아졌는지 확인할 때 쓴다.
  • AI API 게이트웨이 AI API Gateway앱과 여러 LLM 공급자 사이에 두는 단일 진입점으로, 라우팅·폴백·캐싱·비용 통제를 한곳에서 처리한다. 모델을 두 개 이상 쓰거나 여러 팀이 LLM API를 나눠 쓸 때 쓴다.
  • GPU 클러스터 GPU ClusterGPU 클러스터는 수십에서 수천 개의 GPU를 빠른 네트워크로 묶어 하나처럼 쓰는 컴퓨팅 인프라다. GPU 한 대로 감당할 수 없는 대형 모델의 학습이나 대규모 추론에 쓴다.
  • LLMOpsLLMOps는 LLM을 쓰는 앱을 개발·배포·운영하면서 프롬프트 버전, 응답 품질, 토큰 비용을 관리하는 방법이다. 시제품을 넘어 실제 사용자에게 서비스할 때 필요하다.
  • MLOpsMLOps는 머신러닝 모델을 만들고, 배포하고, 운영하는 과정을 자동화하고 표준화하는 방법론이다. 모델을 한 번 만들고 끝내지 않고 계속 다시 학습하고 배포해야 하는 서비스에서 쓴다.
  • vLLMvLLM은 오픈소스 LLM을 GPU 서버에 올려 여러 사용자가 동시에 쓰는 OpenAI 호환 API로 만들어 주는 서빙 엔진이다. 팀이나 서비스에서 같은 모델에 많은 요청을 빠르게 처리해야 할 때 쓴다.
