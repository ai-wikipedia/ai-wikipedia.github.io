안전

AI를 안전하고 믿을 수 있게 쓰기 위한 개념입니다. 모델은 모르는 것도 그럴듯하게 지어내고(환각), 악의적인 입력에 속아 하지 말아야 할 일을 하기도 합니다(프롬프트 인젝션, 탈옥). 이런 위험을 이해하는 것이 첫걸음이고, 출력을 걸러내는 가드레일, 모델 스스로 원칙을 지키게 하는 정렬과 헌법적 AI, 워터마킹·딥페이크 탐지 같은 기술이 방어선을 이룹니다. AI 서비스를 만들거나 도입하는 입장이라면 환각과 프롬프트 인젝션 두 항목만은 꼭 읽어두시길 권합니다. 위험을 이해하고 막는 기술들을 모았습니다.
  • 가드레일 GuardrailAI에 들어가는 입력과 나오는 출력을 모델 바깥에서 검사해 위험한 내용을 막는 안전 장치다. 프롬프트 인젝션, 개인정보 유출, 위험한 도구 실행을 모델의 판단과 상관없이 막아야 할 때 쓴다.
  • 레드팀 Red TeamingAI 모델이나 서비스의 약점을 찾으려고 일부러 공격자 역할을 맡아 공격해 보는 테스트 방법이다. 출시 전이나 프롬프트·모델·도구를 바꿀 때마다 돌려서 위험한 출력이 나오는 구멍을 미리 막는 데 쓴다.
  • 메커니스틱 해석 가능성 Mechanistic InterpretabilityAI 모델 안에서 실제로 어떤 계산이 일어나는지 회로와 특징 단위로 따라가 보는 연구 분야다. 모델이 왜 그런 답을 냈는지, 안전장치가 제대로 남아 있는지 원인부터 확인하고 싶을 때 쓴다.
  • 에이전트 임시 계정 Ephemeral Agent Identity에이전트 임시 계정은 AI 에이전트가 작업하는 동안에만 쓰고, 끝나면 만료되거나 폐기되는 신원이다. 사람 계정을 빌려 주지 않고 필요한 권한만 잠깐 줄 때, 그리고 에이전트가 가입·로그인 단계에서 막히지 않게 할 때 쓴다.
  • 코덱스 시큐리티 Codex Security (OpenAI)코덱스 시큐리티는 OpenAI가 만든 보안 에이전트로, 코드에서 취약점을 찾은 뒤 실제로 공격이 되는지 확인하고 고칠 패치를 제안한다. 보안 경고가 너무 많이 쏟아져서 진짜 위험한 버그를 골라내기 어려울 때 쓴다.
  • 탈옥 Jailbreak탈옥은 말을 교묘하게 꾸며 AI가 원래라면 거절했을 요청에 답하게 만드는 공격 기법이다. LLM 서비스를 만들 때는 탈옥을 막을 방어와 테스트를 미리 갖춰야 한다.
  • 프롬프트 스테가노그래피 Prompt Steganography프롬프트 스테가노그래피는 LLM이 평범해 보이는 답변 속에 숨은 메시지를 몰래 담는 기술이다. AI 출력을 감시하는 시스템을 피해 갈 수 있어서, AI 보안과 모니터링을 설계할 때 꼭 고려해야 할 위협이다.
  • 프롬프트 인젝션 Prompt Injection텍스트 속에 몰래 넣은 지시로 AI가 원래 지시를 어기게 만드는 공격이다. AI 챗봇이나 외부 문서·웹을 읽는 에이전트를 만들거나 쓸 때 꼭 대비해야 한다.
  • 환각 HallucinationAI가 사실이 아닌 내용을 그럴듯하고 자신 있게 지어내는 현상이다. AI의 답을 근거로 코드를 짜거나 중요한 판단을 내릴 때 꼭 따로 확인해야 하는 이유다.
  • AI 공급망 공격 AI Supply Chain Attack개발자가 믿고 설치하는 AI 패키지·모델·도구에 악성 코드를 숨겨 API 키나 자격 증명을 훔치는 공격이다. AI 라이브러리를 설치하거나 업데이트할 때, 모델 파일이나 도구를 내려받을 때 특히 조심해야 한다.
  • AI 저작권 AI CopyrightAI 저작권은 AI가 만든 결과물의 권리가 누구에게 있는지, 그리고 AI 학습에 남의 저작물을 써도 되는지를 다루는 법적 쟁점이다. AI로 작품을 만들거나 AI를 학습시키는 서비스를 만들 때 따져봐야 한다.
  • AI 취약점 발견 AI Vulnerability DiscoveryAI가 코드의 흐름과 의미를 이해해 사람과 기존 스캐너가 놓친 보안 취약점을 찾아내는 기술이다. 내 코드의 특정 모듈을 깊게 점검하거나, 정적 분석 결과 중 진짜 위험한 것만 골라낼 때 쓴다.
  • AI 코드 거버넌스 AI Code GovernanceAI 코드 거버넌스는 AI가 짠 코드도 팀의 품질·보안·라이선스 기준을 지키도록 규칙을 정하고, 그 규칙을 개발 과정에서 자동으로 검사하고 기록하는 방식이다. AI로 코드가 빨리 늘어나면서 리뷰어 혼자 감당하기 어려워진 검증 부담을 덜고 싶을 때 쓴다.
