## 콘텐츠 작성 규칙

### sum (요약)
- 1~2문장, 짧고 쉽게. 이 기술이 뭔지 + 언제 쓰는지.
- 시장 규모나 수치로 시작 금지.

### det (상세)
{DET_STYLE}

### refs (레퍼런스 채택)
- **det를 작성할 때 실제로 참고한 출처만** refs에 넣는다.
- det에서 정보를 가져오지 않은 URL은 아무리 공식 문서여도 넣지 않는다.
- type 분류: 공식 문서=official, 공식 블로그=blog, 논문=paper, 기타=tutorial.
- 최대 5개.

### videos (영상 채택)
- 수집된 youtube 결과에서 정확히 3개 채택 (영어 2 + 한국어 1).
- **조회수(viewCount)를 주요 판단 기준에 포함.**

### 품질 게이트 (Google/AdSense 기준 — 반드시 준수)

생성된 콘텐츠는 아래 기준을 **모두** 충족해야 한다. 하나라도 미달이면 해당 항목을 작성하지 말고 `"skip": true`를 출력하라.

**독창성**
- 어디에나 있는 사전식 정의의 단순 재진술 금지. "X는 Y이다" 한 줄 설명을 살찌운 수준은 안 된다.
- 이 기술이 실제로 어떤 문제를 풀고, 개발자가 어떤 상황에서 어떻게 쓰는지 구체적 장면으로 설명해야 한다. 위 "사용 예시 작성 규칙"을 준수한다.
- BAD: "X는 대규모 시스템에서 효과적이다." / GOOD: "대규모 리팩토링에서는 파일 탐색과 수정을 여러 에이전트가 나눠 처리해서 컨텍스트 한계를 우회할 수 있다."

**분량 및 구조**
- det는 `한눈에 보기`로 시작하는 **3~5개 `<h4>` 섹션**.
- 태그를 뺀 텍스트(표 내용 포함) 기준 **1,100~1,500자**. 1,000자 미만이면 사이트에 공개되지 않으므로(build.js 품질 게이트) 그보다 짧게 쓰지 않는다. 반대로 분량을 채우려고 불필요한 설명을 늘리지도 않는다.
- 제공된 검색 결과만으로 핵심 내용(무엇인지, 어떻게 쓰는지)을 채울 정보가 부족하면 `"skip": true`를 출력하고 항목을 만들지 마라.

**근거 기반 서술**
- 제공된 소스(web 검색결과)에 실제로 있는 사실만 기술한다. 지어내기, 추측, "~할 것이다" 예측 금지.
- refs는 det 작성 시 실제로 내용을 가져온 출처만 채택. det에 반영하지 않은 URL은 refs에 넣지 마라.

**금지 패턴**
- 키워드 스터핑: 같은 단어를 의미 없이 반복해 분량 늘리기 금지.
- 의미 없는 미사여구: "혁신적인", "강력한", "주목할 만한" 등 실질 내용 없는 수식어 금지.
- 기업명·수치 나열식 서술: "A사는 B를 도입해 C% 향상했다" 스타일의 나열 금지. 대신 기술이 실제로 어떻게 동작하는지 묘사하라.
- 벤치마크 점수·통계·모델명을 문장 속에 줄줄이 나열하기 금지. 꼭 필요한 숫자만 표나 그래프로.

### 기타
- **t (한국어 키워드, 카드 상단)**: 한글 발음 표기를 우선한다. 모델·제품명도 한글로 (예: Claude Opus 4.8 → `클로드 오퍼스 4.8`, Gemini 3 Pro → `제미나이 3 프로`, Sora → `소라`). 단 약어·대문자 스타일 브랜드(GPT·GLM·RAG·MCP·FLUX·OLMo 등)는 영문 유지. → 한글 SEO(란/뜻/의미 키워드)가 t 기반으로 생성되므로 한글 표기가 중요.
- **en (영문 정식명, 카드 하단)**: 영문 풀네임 (예: `Claude Opus 4.8 (Anthropic)`).
- tags: 2~4개
- c: prompting|model|tooling|data|agent|infra|safety|application
- born: 기술 최초 등장 연-월 (YYYY-MM)
- rel: 기존 키워드 ID 중 관련 있는 것만
- hot: 이번 트렌드에서 화제였으면 true, 아니면 false

## 출력 형식
지정된 JSON 스키마의 객체 하나로 출력한다 (키워드 1개).
- 품질 게이트를 하나라도 통과하지 못하면 `skip`을 true로, `skip_reason`에 사유를 적고 나머지 필드는 빈 값으로 채운다.
- 통과하면 `skip`은 false. 번역은 별도 단계에서 하므로 작성하지 않는다.
- `rel`에는 위 기존 키워드 ID 목록에 실제로 있는 ID만 넣는다.
