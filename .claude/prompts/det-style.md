목표: 독자가 **한눈에 핵심을 파악**하게 한다. 길게 설명하지 말고 꼭 필요한 내용만, 쉬운 말과 표로 보여준다.

**구조**
1. 첫 섹션은 반드시 `<h4>한눈에 보기</h4>` — 전체에서 가장 중요한 핵심만. 무엇이고 언제 쓰는지를 2~3문장으로 말하고, 비교·위치를 보여줄 수 있으면 표를 붙인다 (예: 같은 계열 모델 등급 비교, 비슷한 기술과의 차이).
2. 그다음 **사용자가 실제로 어떻게 쓰는지** — 어디서(앱·API·도구), 어떻게(설정·명령), 언제 쓰는지. 상황별 선택은 표로 정리한다.
3. 나머지는 이 키워드에서 **정말 중요한 것만** 1~3개 섹션 (가격, 이전 버전과 달라진 점, 주의할 점 등). 섹션 제목은 내용을 그대로 말하는 쉬운 문구로 짓는다 (예: "가격이 절반으로", "6.1에서 달라진 점", "고를 때 주의할 점").
- 섹션은 총 3~5개. 문단은 2~3문장으로 짧게.

**쉽게 쓰기**
- 처음 듣는 사람도 바로 이해하는 쉬운 말로 쓴다. "~다" 문체.
- 학술적 설명(아키텍처 세부, 논문 용어, 수식), 관련 모델 이름 나열, 벤치마크 점수·통계 나열은 넣지 않는다. 숫자는 독자의 선택에 영향을 주는 것만(가격, 컨텍스트 길이 등) 최대 3~4개, 반드시 표나 막대그래프로 보여준다. 문장 속에 숫자를 줄줄이 쓰지 않는다.
- `<strong>`은 핵심 한두 곳에만. `<code>`는 실제 모델 ID·명령어·설정값에만.

**사용법 작성 규칙**
- 사용자가 직접 쓰는 관점으로 적는다. 산업 사례·기업 도입 사례·시장 규모 금지.
- 사용법(어떻게)과 사용처(언제)를 같이 적는다. BAD: "대규모 리팩토링에서 효과적이다." / GOOD: "큰 리팩토링은 추론 강도를 높게, 테스트 결과 요약은 낮게 두면 같은 모델로 비용을 줄일 수 있다."
- 관련 기술은 이 키워드 관점에서만 언급한다. 다른 기술의 독립 설명이 되면 안 된다.

**사용할 수 있는 HTML** (이 외의 태그·속성 금지)
- `<h4>`, `<p>`, `<strong>`, `<code>`
- 표: `<div class="tbl"><table><tr><th>…</th></tr><tr><td>…</td></tr></table></div>` — 열은 2~4개, 행은 2~5개, 칸 내용은 짧게. 강조할 칸은 `<strong>`.
- 막대그래프 (수치 비교 2~4개): `<div class="bars"><div class="bar"><span class="bar-label">이름</span><span class="bar-track"><span class="bar-fill" style="width:NN%"></span></span><span class="bar-val">값</span></div>…</div>` — 가장 큰 값을 100%로 두고 나머지는 비율대로.
- 표·그래프 아래 단위·기준 설명: `<p class="note">…</p>`
- 글머리표(ul/li) 금지 — 나열이 필요하면 표로.
