에이전트 프로토콜

Agent Protocol

AI 에이전트가 다른 에이전트나 앱과 메시지를 주고받는 방식을 정한 공통 규약이다. 서로 다른 프레임워크나 회사가 만든 에이전트를 따로 연결 코드를 짜지 않고 이어 붙일 때 쓴다.

한눈에 보기

에이전트 프로토콜은 AI 에이전트끼리, 또는 앱과 에이전트가 같은 방식으로 일을 주고받게 정한 규약이다. 에이전트마다 입출력 형식이 다르면 하나를 붙일 때마다 연결 코드를 새로 짜야 하는데, 공통 규약을 따르면 어떤 프레임워크로 만든 에이전트든 바로 이어 쓸 수 있다. 하나의 표준이 아니라 여러 규약을 함께 부르는 말이고, 각각 맡는 구간이 다르다.

규약무엇을 연결하나이럴 때 쓴다
MCP에이전트 ↔ 도구·데이터파일, DB, 외부 API를 에이전트에 붙일 때
A2A에이전트 ↔ 에이전트다른 팀·회사의 에이전트에게 일을 맡길 때
Agent Protocol (REST)앱 ↔ 에이전트 서버화면이나 오케스트레이터가 에이전트를 제어할 때

연결 코드를 한 번만 짜면 된다

에이전트가 늘어날수록 서로 맞춰야 할 연결이 빠르게 늘어난다. 모두가 같은 규약을 따르면 각자 규약 하나만 지키면 되므로, 에이전트를 바꾸거나 새로 붙여도 나머지는 고칠 필요가 없다. LangChain으로 만든 에이전트와 AutoGPT 에이전트가 한 작업에 협력할 수 있는 것도 이 덕분이다.

쓰는 순서: 소개하고, 맡기고, 받는다

A2A에서는 에이전트가 자기 이름, 할 수 있는 일, 접속 주소, 인증 방법을 적은 '에이전트 카드'를 공개한다. 다른 에이전트는 이 카드를 읽고 맞는 상대를 고른 뒤 작업을 보내고, 진행 상황과 결과를 돌려받는다. 오래 걸리는 일은 중간 결과를 스트리밍으로 받을 수 있다.

REST 방식 Agent Protocol에서는 에이전트 서버가 정해진 주소를 연다. /agent/tasks로 작업을 만들고 /agent/tasks/{id}/steps로 단계별로 실행하고 결과를 받는다. 프론트엔드는 내부 구현을 몰라도 같은 방식으로 어떤 에이전트든 부를 수 있다.

언제 쓰고, 언제 안 써도 되나

상황판단
에이전트 하나가 도구만 쓴다MCP면 충분하다
한 프레임워크 안에서 에이전트 몇 개를 돌린다프레임워크 기본 기능으로 충분하다
다른 팀·벤더의 에이전트와 협업한다A2A 같은 규약이 필요하다
여러 에이전트를 같은 화면에서 관리한다REST 규약을 따르면 편하다

규약은 아직 정리되는 중이다

비슷한 목적의 규약이 여러 개 나와 있고 내용도 계속 바뀐다. 상대 에이전트가 어떤 규약과 버전을 지원하는지 먼저 확인하는 게 좋다. 외부 에이전트에게 일을 맡기면 데이터가 밖으로 나가므로 인증과 권한 범위도 꼭 정해야 한다.
