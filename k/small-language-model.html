소형 언어 모델

Small Language Model

수십억 개 이하의 파라미터를 가진 소형 언어 모델. 모바일·엣지 기기에서 실행 가능하고, 특정 도메인에서 대형 모델에 준하는 성능을 낸다.

작지만 쓸 만해진 언어 모델

소형 언어 모델(Small Language Model, SLM)이란 파라미터가 대략 수억에서 수십억 개 수준이라 노트북, 스마트폰, GPU 한 장에서도 돌아가는 언어 모델을 말한다. 수천억 개 이상의 파라미터로 데이터센터에서만 돌아가는 프론티어 LLM과 대비되는 개념이다. 정해진 경계선은 없어서, 70개 SLM을 조사한 2024년 서베이는 1억~50억 파라미터를 기준으로 삼았고 실무에서는 10B 안팎까지 소형으로 부르기도 한다. Microsoft의 Phi, Google의 Gemma, 알리바바의 Qwen 소형 라인업, Meta의 Llama 3.2 1B·3B, 그리고 아이폰 안에서 도는 약 30억 파라미터짜리 Apple 온디바이스 모델이 대표적이다. Gemma 3는 2억 7천만 파라미터짜리 버전까지 내놓아, 특정 분류나 추출 작업에 미세조정해 쓰는 초소형 용도까지 겨냥했다.

몇 년 전만 해도 작은 모델은 문장을 그럴듯하게 잇는 수준이었다. 달라진 첫 번째 이유는 데이터의 질이다. Microsoft의 phi-3-mini는 38억 파라미터에 불과하지만, 강하게 걸러낸 웹 데이터와 합성 데이터로 3.3조 토큰을 학습해 MMLU 69%로 GPT-3.5, Mixtral 8x7B와 비슷한 점수를 냈고 휴대폰에서 돌아갈 만큼 작았다. 두 번째는 오래 학습시키기다. 작은 모델에 계산상 '최적'보다 훨씬 많은 토큰을 읽혀 크기 대비 성능을 끌어올린다. 세 번째는 큰 모델의 답을 작은 모델이 따라 배우는 증류다.

여기에 가중치를 16비트에서 4비트, 심지어 2비트로 줄이는 양자화가 더해져 실제 메모리 사용량이 크게 줄었다. Apple은 온디바이스 모델을 양자화를 고려한 학습으로 가중치당 2비트까지 압축했고, 뒤쪽 레이어가 앞쪽의 KV 캐시를 재사용하는 구조로 메모리를 더 아꼈다.

내 기기에서 돌려 보기

가장 쉬운 길은 Ollama다. ollama run gemma3:4b 한 줄이면 4비트로 양자화된 모델을 내려받아 맥북에서 바로 대화할 수 있고, 로컬 HTTP API도 열려서 기존 코드의 API 주소만 바꿔 붙일 수 있다. 더 세밀하게 다루려면 llama.cpp의 GGUF 포맷이나 Apple 실리콘용 MLX로 양자화 수준을 직접 고를 수 있다. 4비트 양자화라면 파라미터 10억 개당 대략 0.5GB에 대화 길이에 비례하는 KV 캐시가 더해진다고 보면 메모리 감을 잡기 쉽다. iOS 앱이라면 Apple의 Foundation Models 프레임워크로 기기 안 모델을 Swift에서 바로 부를 수 있다. @Generable을 붙인 구조체로 결과를 받는 구조화된 출력과 도구 호출을 지원하고, 서버 비용 없이 오프라인에서도 돌아간다.

다만 Apple 스스로 이 모델이 요약, 정보 추출, 짧은 대화 같은 작업용이며 세상 지식을 묻는 범용 챗봇으로 설계된 게 아니라고 밝힌다. SLM을 쓰는 감각이 이 문장에 담겨 있다. 무엇이든 물어보는 대상이 아니라, 정해진 일을 빠르고 싸게 처리하는 부품으로 쓰라는 것이다.

큰 모델과 일을 나누는 구조

SLM이 진가를 발휘하는 곳은 좁고 반복적인 작업이다. 2025년 NVIDIA 연구진은 에이전트가 실제로 하는 일의 상당수가 정해진 형식의 도구 호출, 분류, 추출처럼 범위가 좁은 반복 작업이라 SLM으로 충분하고 더 경제적이라고 주장했다. 그래서 큰 모델이 계획과 어려운 판단을 맡고, 작은 모델이 문의 분류, 개인정보 마스킹, 로그 요약, 요청 라우팅 같은 대량 작업을 처리하는 이기종 구성이 늘고 있다. 특정 작업에 대해 LoRA로 작은 모델을 미세조정하면 비용은 크게 줄이면서 그 작업만큼은 큰 모델에 가까운 품질을 얻는 경우가 많다. 데이터가 기기나 사내 서버 밖으로 나가지 않는다는 점도 의료, 금융처럼 민감한 데이터를 다루는 곳에서 큰 장점이다. 작은 모델이 큰 모델을 돕는 방식도 있다. 작은 모델이 다음 몇 토큰의 초안을 빠르게 써 두면 큰 모델이 한 번에 검증해 받아들이는 추측 디코딩은, 답의 품질은 큰 모델 그대로 두면서 생성 속도를 높이는 서빙 기법으로 널리 쓰인다.

한계도 분명하다. 파라미터가 적은 만큼 담을 수 있는 사실 지식이 적어 모르는 것을 지어내기 쉽고, 여러 단계를 거치는 긴 추론과 한국어 같은 비영어권 언어의 품질에서 큰 모델과 차이가 난다. 벤치마크 점수보다 자기 작업의 평가 세트로 직접 확인한 뒤 맡길 범위를 정하는 것이 SLM을 잘 쓰는 법이다.
