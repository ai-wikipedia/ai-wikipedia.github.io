바이브 코딩

Vibe Coding

원하는 결과를 말로 설명하면 AI가 코드를 만들어 주고, 사람은 실행 결과를 보며 말로 고쳐 나가는 개발 방식이다. 빠른 프로토타입이나 아이디어 검증, 내부 도구를 만들 때 쓴다.

한눈에 보기

바이브 코딩은 코드를 직접 짜지 않고 "이런 앱 만들어줘"라고 말로 시키는 방식이다. 코드는 읽지 않고 실행해 본 결과로 판단하며 대화로 고쳐 나간다. 용어를 만든 Andrej Karpathy는 이를 "보고, 말하고, 실행하고, 복붙하는 것"이라고 표현했다.

구분기존 코딩바이브 코딩
사람이 하는 일코드를 한 줄씩 직접 작성원하는 결과를 말로 설명
판단 기준코드를 읽고 판단동작을 보고 판단
수정 방법코드를 직접 고침"이 버튼 안 눌려"처럼 말로 요청

프로토타입은 말 한 줄로 시작한다

Cursor나 Claude Code에 "React로 드래그앤드롭 되는 칸반 보드, 데이터는 로컬스토리지에 저장"이라고 던지면 폴더 구조부터 컴포넌트, 스타일까지 한 번에 나온다. 결과를 실행해 보고 "여기 색 바꿔"처럼 다시 말해 방향을 잡으면 된다.

개발 환경 설정을 몰라도 된다면 Replit, Lovable, v0처럼 브라우저에서 설명만 하면 배포까지 해 주는 도구를 쓰면 된다.

이럴 때이렇게 쓴다
주말 아이디어 검증장난감 앱을 말로 만들어 바로 돌려 본다
기획 회의 준비스펙 문서 대신 동작하는 목업을 만든다
일회성 데이터 분석분석 스크립트를 말로 뽑아낸다
반복 작업 생략보일러플레이트는 맡기고 본론에 집중한다

"감"만으로 배포하면 위험하다

AI가 만든 코드에는 SQL 인젝션, 권한 검사 누락, 프런트엔드에 박힌 API 키 같은 흔한 보안 결함이 그대로 남기 쉽다. 코드를 안 읽는 만큼 이런 실수가 걸러지지 않고, 겉으로는 잘 돌아가 보여서 문제를 늦게 발견한다.

대화 흐름대로 즉흥적으로 자란 코드는 몇 주 뒤면 전체 구조를 아는 사람이 없어진다. 그때부터는 AI에게 고쳐 달라고 해도 한 곳을 고치면 다른 곳이 부서지기 쉽다.

영역바이브 코딩
UI 실험, 내부 도구가볍게 써도 된다
인증·결제·개인정보사람이 코드 리뷰 + 자동 보안 스캔 필수

프로덕션은 에이전틱 엔지니어링으로

Karpathy는 2026년 전문가의 작업에는 에이전틱 엔지니어링이라는 이름을 제안했다. 코드를 직접 쓰지 않는 건 같지만, 에이전트에게 일을 나눠 주고 결과를 검증하는 감독자로 일한다는 점이 다르다.

계획을 먼저 승인하고, 변경은 작게 나누고, 테스트로 확인하는 규율이 들어간다. 프로토타입은 바이브로, 프로덕션은 엔지니어링으로 나누는 것이 지금 실무에서 합의된 방식이다.
