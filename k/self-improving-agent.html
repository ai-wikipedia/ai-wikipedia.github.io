자기학습 에이전트

Self-Improving Agent

일을 마칠 때마다 결과를 돌아보고 잘된 방법은 스킬로, 실패는 교훈으로 저장해 쓸수록 더 잘하게 되는 에이전트다. 정해 둔 도구와 프롬프트 안에서만 움직이는 일반 에이전트와 달리 새 능력을 스스로 만들어 쌓기 때문에, 비슷한 작업을 자주 맡기는 반복 업무나 오래 쓰는 개인 에이전트에 잘 맞는다.

방식새 능력은 누가 만드나시간이 지나면
일반 에이전트사람이 프롬프트·도구 추가그대로
수동 스킬 (Claude Code 등)사람이 스킬 파일 작성사람이 손댄 만큼 좋아짐
자기학습 에이전트에이전트가 스스로쓸수록 좋아짐

Nous Research의 Hermes Agent가 이 방식을 구체적인 제품으로 보여 준 예다.

모델이 아니라 기억과 스킬이 자란다

보통 모델 자체를 다시 학습시키지 않는다. 바뀌는 건 모델 바깥에 쌓이는 기억, 스킬 파일, 작업 지침이다. 그래서 같은 모델을 쓰더라도 내 환경에 맞는 노하우가 쌓인 에이전트가 더 잘하게 된다.

단계에이전트가 하는 일
실행작업을 수행하고 기록을 남긴다
돌아보기무엇이 통했고 어디서 막혔는지 정리한다
저장반복되는 절차를 스킬로, 교훈을 메모로 남긴다
재사용비슷한 작업이 오면 저장한 스킬을 불러온다

직접 써 보려면: 반복 작업에서 시작

Claude Code에서는 스킬을 사람이 만드는 게 기본이지만, 같은 작업을 몇 번 시킨 뒤 "방금 한 절차를 스킬로 저장해 줘"라고 하면 반쯤 자동인 흐름을 만들 수 있다. 스킬은 .claude/skills 폴더의 SKILL.md 파일로 남아 다음 세션에서 다시 쓰인다. Hermes Agent 같은 자기학습 에이전트는 이 판단과 저장을 에이전트가 알아서 한다.

반복 업무엔 좋고, 일회성 작업엔 이득이 적다

상황잘 맞나
배포, 리포트 작성처럼 자주 하는 일잘 맞음
오래 쓰는 개인 비서형 에이전트잘 맞음
한 번 하고 끝나는 작업쌓을 게 없어 이득 적음
결과가 늘 같아야 하는 업무동작이 바뀌어 부적합

잘못 배운 것도 함께 쌓인다

한 번 우연히 통한 방법이 스킬로 굳으면 틀린 절차가 계속 반복된다. 스킬 수가 너무 늘면 엉뚱한 스킬을 불러오기도 한다. 스킬에는 실행 명령이 들어가므로 보안상으로도 확인이 필요하다.

그래서 새로 생긴 스킬은 가끔 읽어 보고, 틀린 것은 지우고, 스킬 폴더를 git으로 관리해 바뀐 내용을 추적하는 게 안전하다.

자주 반복하는 일에 붙여 두고 키운다

가장 흔한 방식은 매번 비슷하게 시키는 작업에 에이전트를 붙여 두고, 몇 번 돌린 뒤 쌓인 스킬을 다듬어 가는 것이다. 처음부터 완벽한 지침을 쓰는 대신, 실제로 일하면서 생긴 절차를 남겨 다음 번에 그대로 꺼내 쓴다.

어디서어떻게 쓰나
코딩 에이전트배포·테스트 수정처럼 자주 하는 절차를 몇 번 시킨 뒤 스킬로 저장해 다음 세션에서 불러온다
개인 비서형 에이전트오래 쓰면서 내 선호와 작업 방식을 기억·스킬로 쌓아 매번 다시 설명하지 않게 한다
정기 리포트 작성자료 모으기와 정리 순서를 스킬로 굳혀 주기마다 같은 흐름으로 반복한다
