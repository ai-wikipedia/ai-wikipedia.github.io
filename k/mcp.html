MCP

Model Context Protocol

MCP는 AI 앱이 외부 도구와 데이터에 연결할 때 쓰는 공통 규격이다. 서버를 한 번만 만들어 두면 Claude Code, Cursor, ChatGPT처럼 MCP를 지원하는 모든 AI 앱에서 같은 방식으로 쓸 수 있다.

한눈에 보기

MCP는 AI가 GitHub, DB, Slack 같은 외부 서비스에 연결하는 공통 규격이다. USB-C가 단자를 하나로 통일했듯, 서비스 쪽에 MCP 서버 하나만 두면 이를 지원하는 모든 AI 앱이 같은 방식으로 접근한다. 에이전트가 사내 시스템이나 외부 도구를 직접 다뤄야 할 때 쓴다.

구분MCP 이전MCP 이후
연동 방식앱마다, 서비스마다 따로 개발서버 하나로 모든 앱에 연결
필요한 연동 코드AI 앱 수 × 도구 수도구마다 서버 하나

서버가 주는 세 가지

AI 앱이 클라이언트가 되고, 외부 시스템 쪽에 MCP 서버를 둔다. 서버가 AI에게 내어 줄 수 있는 것은 세 가지다.

종류뜻예
도구모델이 실행하는 기능이슈 생성, 쿼리 실행
리소스모델이 읽는 데이터파일, 문서
프롬프트다시 쓰는 지시 템플릿자주 쓰는 요청 양식

내 컴퓨터에서 도는 서버도, 원격 서버도 붙일 수 있다. 원격 서버는 OAuth 인증 규격까지 정해져 있어서, 외부 SaaS가 공식 MCP 서버를 직접 내놓기도 한다.

쓰는 건 명령 한 줄, 만드는 건 함수 몇 개

쓸 때는 Claude Code에서 claude mcp add로 서버를 등록하면 에이전트가 그 서비스의 도구를 바로 쓴다. 파일시스템, GitHub, Slack, 구글 드라이브처럼 흔한 서비스는 공식 레지스트리에서 이미 만들어진 서버를 찾아 붙이면 된다.

붙이는 서버이럴 때 쓴다
Playwright MCP에이전트가 브라우저를 직접 열어 만든 UI를 확인할 때
PostgreSQL MCP실제 데이터를 조회하면서 코드를 짤 때

만들 때는 Python이나 TypeScript SDK로 함수에 데코레이터를 붙이면 사내 API가 MCP 서버가 된다. 사내 배포 시스템에 서버 하나를 얹어 두면 팀원마다 쓰는 AI 도구가 달라도 "스테이징에 배포하고 로그 보여줘"를 모두 같은 서버로 처리한다.

한 회사 규격에서 업계 표준으로

Anthropic이 2024년 11월에 공개했고, 2025년 OpenAI·Google DeepMind·Microsoft가 지원하면서 사실상 표준이 됐다. 2025년 12월에는 Linux Foundation 산하 재단에 기부돼 특정 회사가 아닌 커뮤니티가 관리한다. 그래서 어느 AI 앱을 쓰든 연동 코드는 한 번만 짜면 된다.

많이 붙일수록 토큰과 보안을 챙겨야 한다

서버를 붙일수록 도구 설명이 매 요청마다 컨텍스트에 실려 토큰을 많이 쓴다. 지금 작업에 필요한 서버만 켜 두는 게 낫다.

보안도 주의해야 한다. 출처가 불분명한 서버가 악의적인 도구 설명으로 에이전트를 조종하거나, 도구가 돌려준 내용에 프롬프트 인젝션이 숨어 있을 수 있다. 검증된 서버만 붙이고, 에이전트에게는 꼭 필요한 권한만 준다.
