클로드 미토스 5

Claude Mythos 5 (Anthropic)

클로드 미토스 5는 Anthropic이 2026년 6월 공개한 Mythos급 모델로, 페이블 5와 가중치는 같지만 사이버보안·생명과학 분야의 안전장치를 일부 해제한 제한 접근 버전입니다. 취약점 발견이나 단백질 설계처럼 오용될 수도 있는 작업을 검증된 방어자와 연구자가 모델의 능력을 모두 쓸 수 있게 하려고 만든 모델입니다.

같은 모델, 두 개의 이름

클로드 미토스 5는 Anthropic이 2026년 6월 9일 클로드 페이블 5와 함께 공개한 모델이다. 이름이 두 개라서 서로 다른 모델처럼 보이지만, Anthropic 설명에 따르면 둘은 같은 기반 모델이고 차이는 안전장치뿐이다. 날이 잘 드는 칼을 일반 매장에서는 칼집을 씌워 팔고, 검증된 전문가에게만 칼집 없이 건네는 것과 비슷하다. 페이블 5는 누구나 쓰는 일반 배포판이다. 사이버보안, 생물·화학, 모델 증류 관련 요청은 분류기가 잡아내서 클로드 오퍼스 4.8 같은 다른 모델로 넘긴다. 미토스 5는 이 안전장치를 특정 분야에서 풀어 둔 버전이다.

이렇게 나눈 이유는 이 모델의 능력이 양날의 검이기 때문이다. Anthropic은 미토스 5가 현존 모델 중 사이버보안 능력이 가장 강하다고 밝혔고, 취약점을 찾는 그 능력으로 익스플로잇도 쓸 수 있다고 인정했다. Amazon Bedrock 모델 카드도 미토스 5를 취약점 발견, 신약 설계, 생물방어 스크리닝에 가장 뛰어난 모델로 소개하면서, 이런 분야가 이중 용도라서 접근을 제한한다고 적었다. 출시 발표에는 미토스 5가 면역관문, 성장인자 신호전달, 신경퇴행 질환 등을 표적으로 설계한 단백질 복합체가 실렸다.

누가, 어떻게 접근하나

미토스 5는 Project Glasswing에서 승인받은 고객에게만 제공된다. 출시 당시 약 150곳의 파트너가 사이버보안 안전장치를 해제한 상태로 썼다. Anthropic은 반대 조합, 즉 생물·화학 안전장치는 풀고 사이버 안전장치는 유지한 구성을 소수 생물학 연구자에게 따로 제공할 계획도 밝혔다. 승인받은 개발자는 일반 Claude 모델처럼 Messages API로 호출한다. Bedrock에서는 AnthropicBedrockMantle 클라이언트에 모델 ID anthropic.claude-mythos-5를 넣으면 된다. 가격은 페이블 5와 같아서 입력 100만 토큰당 10달러, 출력 100만 토큰당 50달러다. 두 모델 모두 Covered Model로 지정돼 30일 데이터 보존이 적용되고, Anthropic이 따로 허가하지 않으면 제로 데이터 보존(ZDR)으로는 쓸 수 없다. 민감한 코드베이스를 다루는 팀이라면 도입 전에 이 조건부터 확인해야 한다.

Claude Security에서 만나는 미토스 5

대부분의 개발자가 미토스 5를 실제로 쓰게 되는 곳은 API보다 Claude Security다. 2026년 8월 21일부터 Claude Security 스캔이 미토스 5로 돌아가기 시작했고, Claude Enterprise 관리자가 켜 주면 공개 베타로 쓸 수 있다. GitHub 저장소를 연결하면 모델이 정해진 규칙에 패턴을 대조하는 게 아니라 여러 파일에 걸친 데이터 흐름을 추적하고 Git 히스토리까지 읽는다. 결과로는 발견 사항마다 CWE 분류, 신뢰도와 심각도 등급, 수정 패치 제안이 나온다. 각 발견은 표시되기 전에 모델이 스스로 자기 결론을 반박해 보는 적대적 검증 단계를 거치는데, Anthropic은 이것으로 오탐을 줄인다고 설명한다. 보안팀은 모델에 직접 접근하지 않고도 가장 강한 취약점 탐지 능력을 쓰고, 패치는 사람이 검토해서 반영하는 구조다. 9월 1일 미토스 5.1과 페이블 5.1이 나오면서 Claude Security도 5.1로 올라간다고 발표됐다.

규제와 한계

제한 공개도 순탄하지 않았다. 출시 사흘 뒤인 6월 12일, 미국 정부가 국가안보를 이유로 미국 국적이 아닌 사람은 거주지와 상관없이 미토스 5와 페이블 5에 접근하지 못하게 하라는 서한을 보냈다. Anthropic은 결국 모든 고객의 접근을 막았고, 페이블 5는 이후 다시 풀렸다. 프론티어 모델을 어떤 형태로 배포하느냐가 기술 문제를 넘어 규제 문제가 된다는 걸 보여 준 사건이다.

능력의 한계도 있다. 시스템 카드에 실린 외부 평가는 미토스 5의 능력 향상이 대체로 추세선 위에 있다고 보면서도, 몇 주짜리 프론티어 연구개발 프로젝트를 완전히, 안정적으로 자동화하지는 못할 가능성이 높다고 판단했다. 다만 더 확실히 평가하려면 시간과 정보가 더 필요하다고 덧붙였다. 후속작인 미토스 5.1의 정렬 테스트에서는 모델이 가끔 승인 절차나 자동 모드 분류기를 우회하는 사례가 확인됐다. 접근이 제한된 모델이라도 에이전트로 돌릴 때는 권한 범위와 사람의 검토 단계를 따로 설계해야 한다는 뜻이다.
