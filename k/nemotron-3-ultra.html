네모트론 3 울트라

NVIDIA Nemotron 3 Ultra

NVIDIA가 공개한 Nemotron 3 제품군의 최상위 오픈 모델이다. 전체 파라미터 550B 중 토큰마다 55B만 활성화하는 하이브리드 Transformer-Mamba MoE 구조이고, 수백 번씩 도구를 호출하는 장시간 에이전트 작업을 빠르고 싸게 돌리려고 만들었다.

오래 일하는 에이전트를 위한 엔진

네모트론 3 울트라(Nemotron 3 Ultra)는 NVIDIA가 2026년 6월 4일 공개한 오픈 대형 언어 모델이다. 전체 파라미터는 550B인데 토큰 하나를 처리할 때는 그중 55B만 쓰는 Mixture-of-Experts(MoE) 구조다. 2025년 12월 Nemotron 3 제품군을 발표할 때 Nano(30B, 활성 3B), Super(약 100B급, 활성 10B급)와 함께 예고했던 모델로, NVIDIA 스스로 이 제품군의 마지막이자 가장 성능이 좋은 모델이라고 소개한다. Nano가 가벼운 서브 에이전트 몫이고 Super가 여러 에이전트가 협업하는 시스템의 일꾼이라면, Ultra는 계획을 세우고 깊이 리서치하며 다른 에이전트를 지휘하는 자리를 맡는다.

왜 이런 모델이 필요한지는 에이전트가 실제로 일하는 모습을 보면 알 수 있다. 코딩 에이전트에게 버그 하나를 맡기면 파일을 읽고, 테스트를 돌리고, 로그를 보고, 다시 고치는 과정을 수십에서 수백 번 반복한다. 매 단계마다 모델이 추론 과정을 길게 생성하니 출력 토큰이 쌓이고, 속도와 비용이 곧 병목이 된다. 똑똑하기만 한 모델로는 부족하고 오래 버티면서 빨리 생각하는 모델이 필요하다는 게 이 모델이 겨냥한 지점이다. NVIDIA는 8k 토큰 입력에 64k 토큰 출력처럼 출력이 긴 조건에서 GLM-5.1(754B)보다 5.9배, Kimi-K2.6(1T)보다 4.8배, Qwen-3.5(397B)보다 1.6배 높은 추론 처리량을 냈다고 발표했다. 정확도는 최상위 오픈 모델들과 비슷한 수준이라고 밝혔다. 정답률에서 압도하기보다 같은 수준의 지능을 훨씬 빠르게 내는 것이 이 모델의 성격이다.

개발자가 붙여 쓰는 방법

가장 빨리 써 보는 길은 Ollama다. ollama launch claude --model nemotron-3-ultra:cloud처럼 실행하면 Claude Code의 모델 자리에 네모트론 3 울트라가 들어가고, 같은 방식으로 OpenCode나 Hermes Agent, OpenClaw에도 붙일 수 있다. 쓰던 코딩 에이전트 하네스는 그대로 두고 두뇌만 오픈 모델로 바꿔 보는 셈이라, 반복 작업이 많아 토큰 비용이 부담되는 프로젝트에서 비교 실험을 하기 좋다. 다만 Ollama 클라우드 버전의 컨텍스트는 256K로 표기되어 있어 모델의 최대치인 1M과 차이가 있다.

API로 쓰려면 OpenRouter의 nvidia/nemotron-3-ultra-550b-a55b, NVIDIA의 build.nvidia.com, Perplexity API 등을 이용한다. 사내 인프라에 직접 올려야 한다면 NVIDIA NIM 마이크로서비스로 패키징된 버전을 쓰거나 Amazon SageMaker JumpStart에서 원클릭으로 배포할 수 있고, Hugging Face에는 nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16 같은 가중치가 올라와 있다. 이 모델은 답하기 전에 추론 과정을 먼저 생성하고 마지막에 최종 답을 내는 방식이며, 추론에 쓸 토큰 양(reasoning budget)을 추론 시점에 조절할 수 있다. 에이전트 루프 안에서 단순한 도구 호출 단계는 예산을 줄이고, 계획 수립 단계는 넉넉히 주는 식으로 속도와 품질을 맞추는 것이다. 수십 개 문서를 한 번에 넣고 분석하는 긴 컨텍스트 RAG나, 여러 서브 에이전트의 결과를 모아 판단하는 오케스트레이터 역할에도 1M 컨텍스트가 쓰인다. NVIDIA는 1M 길이의 RULER 벤치마크에서 다른 오픈 모델보다 높은 점수를 냈다고 밝혔다.

빠른 속도를 만드는 설계

속도의 비밀은 여러 기법을 겹쳐 쓴 데 있다. 첫째는 하이브리드 Mamba-Attention 구조다. 모든 층을 어텐션으로 채우면 문맥이 길어질수록 연산과 KV 캐시가 불어나는데, 일부 층을 상태 공간 모델인 Mamba로 바꿔 긴 시퀀스를 더 가볍게 처리한다. 둘째는 MoE를 개량한 LatentMoE로, NVIDIA는 이것으로 정확도를 끌어올렸다고 설명한다. 셋째로 MTP(Multi-Token Prediction) 층을 넣어 모델이 스스로 다음 토큰 여러 개를 미리 예측하고 검증하는 네이티브 추측적 디코딩을 한다. 별도의 초안 모델 없이도 디코딩이 빨라지는 구조다.

학습 방식도 특이하다. 학습을 마친 뒤 4비트로 압축하는 보통의 양자화와 달리, 처음부터 Blackwell GPU용 4비트 형식인 NVFP4로 사전학습했다. 그래서 NVFP4로 서빙할 때 손실이 적고 메모리와 비용이 줄어든다. 사후 학습은 SFT, 강화학습에 더해 여러 교사 모델로부터 온폴리시로 지식을 증류하는 MOPD(Multi-teacher On-Policy Distillation)를 거쳤다. 이 모델은 Linux Foundation의 OpenMDW 라이선스로 가중치뿐 아니라 학습 데이터와 레시피까지 공개되어 있어, 도메인 데이터로 파인튜닝하거나 학습 과정을 재현해 볼 수 있다.

도입 전에 따져 볼 점

활성 파라미터가 55B라 해도 메모리에는 550B 전체를 올려야 한다. 개인 PC로 돌릴 모델이 아니고, 직접 호스팅하려면 여러 장의 데이터센터 GPU가 필요하다. 처리량 이점도 NVFP4와 Blackwell 하드웨어에 최적화된 결과라, 다른 GPU나 BF16 가중치로 서빙하면 발표된 수치만큼 나오지 않을 수 있다. 또 NVIDIA가 내세운 비교는 출력이 긴 에이전트 작업 기준이므로, 짧은 질의응답 위주의 서비스라면 더 작은 Super나 Nano가 비용 면에서 나을 수 있다. 결국 이 모델은 오래 돌아가는 에이전트의 토큰 비용을 오픈 모델로 낮추고 싶을 때 먼저 검토할 선택지다.
