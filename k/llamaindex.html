LlamaIndex

내 문서·DB·API 데이터를 LLM에 연결해 주는 오픈소스 프레임워크다. 사내 문서 Q&A처럼 내 데이터를 바탕으로 답하는 RAG 앱을 빠르게 만들 때 쓴다.

한눈에 보기

LlamaIndex는 PDF·웹페이지·데이터베이스 같은 내 데이터를 LLM이 답변에 쓸 수 있게 준비해 주는 프레임워크다. 문서를 읽고, 잘게 나누고, 임베딩해 인덱스로 만든 뒤 질문에 맞는 부분을 찾아 LLM에 넘기는 RAG 전 과정을 짧은 코드로 처리한다.

단계하는 일대표 구성요소
로딩파일·웹·DB에서 문서 읽기SimpleDirectoryReader, LlamaHub 커넥터
분할·임베딩문서를 청크로 나눠 벡터로 변환노드 파서, 임베딩 모델
인덱싱검색할 수 있는 구조로 저장VectorStoreIndex
질의관련 청크를 찾아 답변 생성쿼리 엔진, 챗 엔진

몇 줄이면 문서 Q&A가 된다

Python에서는 pip install llama-index로 설치한다. 문서 폴더를 SimpleDirectoryReader로 읽고, VectorStoreIndex로 인덱싱한 뒤 index.as_query_engine()으로 바로 질문하면 된다. 이전 대화를 이어 가는 챗봇이 필요하면 as_chat_engine()을 쓴다.

기본값은 OpenAI 모델을 쓰므로 API 키가 필요하다. 다른 LLM이나 로컬 모델을 쓰려면 Settings에서 LLM과 임베딩 모델을 바꾼다. 인덱스는 저장해 두고 다시 불러오면 같은 문서를 매번 임베딩하는 비용이 들지 않는다.

규모가 커지면 부품을 바꾼다

문서가 많아지면 메모리 인덱스 대신 Chroma·Pinecone 같은 외부 벡터 DB를 연결한다. 주제가 다른 문서 묶음이 여럿이면 RouterQueryEngine으로 질문마다 알맞은 인덱스를 고르게 한다. 표나 도표가 많은 PDF는 기본 리더로 읽으면 구조가 깨지기 쉬워 별도 파서를 쓰는 편이 낫다.

LangChain과는 강점이 다르다

항목LlamaIndexLangChain
중심데이터 연결·인덱싱·검색체인·에이전트·도구 연결
잘 맞는 일문서 기반 Q&A, 검색 품질 다듬기여러 도구를 부르는 작업 흐름
시작 방식RAG 기본값으로 빠르게 시작구성 요소를 직접 조립

두 프레임워크 모두 서로의 영역으로 기능을 넓혀 와서 경계가 뚜렷하지는 않다. 검색 품질이 핵심이면 LlamaIndex로 시작하고, 둘을 함께 쓰기도 한다.

기본값 그대로는 답이 아쉬울 수 있다

돌아가는 것과 정확한 답을 내는 것은 다르다. 청크 크기와 한 번에 가져올 청크 수(top-k)를 문서 특성에 맞게 조절하고, 실제 질문 몇 개로 답이 맞는지 확인해야 한다. 업데이트가 잦아 버전에 따라 import 경로가 바뀐 적이 있으니 예제 코드는 공식 문서 최신판에 맞춰 쓴다.
