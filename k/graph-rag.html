그래프 RAG

Graph RAG

문서에서 사람·조직·개념 같은 엔티티와 그 관계를 뽑아 지식 그래프로 만든 뒤, 그 그래프를 따라가며 답을 찾는 RAG 방식이다. 여러 문서에 흩어진 정보를 엮거나 "전체 주제가 뭐냐" 같은 큰 질문에 답해야 할 때 쓴다.

한눈에 보기

일반 RAG는 질문과 비슷한 문장 조각을 찾아 답한다. 그래서 "A와 B의 공통점은?"처럼 여러 곳에 흩어진 정보를 엮거나, "이 보고서들의 주요 테마는?"처럼 전체를 훑어야 하는 질문에는 약하다. Graph RAG는 문서에서 엔티티와 관계를 뽑아 그래프로 만들고, 그 연결을 따라가며 답한다.

구분일반 RAGGraph RAG
찾는 방식비슷한 조각 검색관계를 따라 탐색
잘하는 질문특정 사실 찾기여러 대상 연결, 전체 요약
준비 비용낮음 (임베딩만)높음 (LLM으로 그래프 생성)

그래프를 먼저 만들고 묶어서 요약한다

준비 단계에서 LLM이 문서를 읽으며 엔티티와 관계를 추출한다. 그다음 서로 촘촘히 연결된 노드들을 커뮤니티로 묶고, 커뮤니티마다 요약을 미리 써 둔다. 이 요약 덕분에 전체를 묻는 질문에도 답할 수 있다.

질문 종류에 따라 Local과 Global을 고른다

Microsoft가 2024년 공개한 GraphRAG는 두 가지 검색을 제공한다. 질문이 특정 대상을 가리키면 Local, 전체 흐름을 물으면 Global을 쓴다.

검색 방식동작이럴 때 쓴다
Local특정 엔티티 주변 관계 탐색"이 인물은 어떤 프로젝트와 연결되나?"
Global커뮤니티 요약들을 모아 종합"이 문서 모음의 주요 테마는?"

graphrag 패키지로 직접 써 보는 순서

pip install graphrag로 설치한 뒤, 작업 폴더를 초기화하고 그 안의 입력 폴더에 텍스트 문서를 넣는다. 설정 파일에 사용할 LLM과 API 키를 적고 인덱싱을 돌리면 그래프와 요약이 만들어진다. 이후 질의 명령에서 검색 방식을 local 또는 global로 지정해 묻는다.

처음에는 문서 몇 개로 작게 돌려 비용과 결과를 확인하는 게 좋다. 사내 문서, 논문 모음, 회의록처럼 인물·조직·개념이 서로 얽힌 자료에서 차이가 잘 드러난다.

인덱싱 비용과 갱신이 부담이다

그래프를 만들 때 문서 전체를 LLM이 읽으므로, 일반 RAG보다 준비 비용과 시간이 훨씬 크다. 문서가 자주 바뀌면 다시 인덱싱해야 하는 부담도 있다. 단순히 특정 사실을 찾는 질문이 대부분이라면 일반 RAG로 충분하고, 관계와 전체 요약이 중요할 때만 Graph RAG를 고르는 게 낫다.
