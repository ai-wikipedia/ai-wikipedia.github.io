GLM 5.2 (Z.ai)

Z.ai(구 Zhipu AI)가 개발한 오픈 웨이트 에이전틱 코딩 모델로, 744B 파라미터 MoE 구조와 1M 토큰 컨텍스트를 갖추고 장기 소프트웨어 엔지니어링 과제를 자율적으로 처리한다.

오래 걸리는 일을 위해 만든 GLM

GLM 5.2는 중국 Z.ai(옛 Zhipu AI)가 2026년 6월 중순 내놓은 오픈 웨이트 언어 모델이다. 자사 코딩 구독 상품인 GLM Coding Plan 이용자에게 먼저 열린 뒤 API와 가중치가 일반에 공개됐다. Z.ai가 이 모델을 소개하며 앞세운 말은 '장기 과제(long-horizon task)'다. 질문 하나에 답하는 능력보다, 수십 개 파일을 읽고 고치고 테스트를 돌리며 몇 시간씩 이어지는 작업을 중간에 흐트러지지 않고 끝내는 능력을 겨냥했다는 뜻이다.

구조는 전체 7,440억 파라미터 중 토큰당 약 400억 개만 활성화하는 MoE(전문가 혼합) 모델이고, 가중치는 MIT 라이선스로 Hugging Face에 올라와 상업적으로도 자유롭게 쓸 수 있다. 문맥 길이는 전작 GLM-5.1의 20만 토큰에서 100만 토큰으로 다섯 배 늘었고, 한 번에 최대 12만 8천 토큰까지 출력한다. 입력과 출력은 텍스트만 지원한다.

IndexShare: 고르는 비용까지 줄이기

GLM-5 계열은 DeepSeek이 만든 희소 어텐션(DSA)을 쓴다. 각 층에 작은 인덱서가 있어서, 새 토큰을 만들 때 앞의 모든 토큰을 다 보지 않고 중요한 토큰만 골라 보게 한다. 그런데 문맥이 100만 토큰까지 길어지면 '무엇을 볼지 고르는 일' 자체가 무거워진다. GLM 5.2가 도입한 IndexShare는 인덱서 하나를 희소 어텐션 네 개 층이 함께 쓰게 해서 이 비용을 줄였다. 층마다 따로 고르던 것을 가까운 층들이 한 번 고른 결과를 재사용하는 방식으로, Z.ai는 100만 토큰 기준 토큰당 연산량이 2.9배 줄었다고 밝혔다. 여기에 추측 디코딩용 MTP(다중 토큰 예측) 층을 개선해, 미리 맞혀서 한 번에 통과시키는 토큰 길이를 최대 20% 늘렸다.

숫자로 본 위치

Z.ai가 공개한 성적표에서 터미널 작업 능력을 재는 Terminal-Bench 2.1 점수는 81.0으로, GLM-5.1(62.0)보다 크게 올랐고 Claude Opus 4.8(85.0)에 몇 점 차로 따라붙었다. 실제 GitHub 이슈 해결을 재는 SWE-bench Pro는 62.1이다. 모두 제조사 발표 수치라는 점은 감안해야 하지만, 오픈 웨이트 모델이 폐쇄형 최상위 모델과 같은 표에서 비교되는 수준까지 왔다는 건 분명하다. 가격은 Z.ai API 기준 입력 100만 토큰당 1.4달러, 캐시된 입력 0.26달러, 출력 4.4달러다.

Z.ai가 이 모델의 쓰임새로 꼽는 장면도 성격을 잘 보여준다. 프로젝트 전체 코드베이스 분석, 여러 단계에 걸친 대규모 리팩토링, 팀의 코딩 규칙을 지키며 작업하기, 논문 재현 같은 일이다. 한 번의 정답보다 수많은 파일과 규칙을 오래 붙들고 있어야 하는 작업들이다. Terminal-Bench 2.1과 ProgramBench의 일부 결과는 Claude Code를 하네스로 써서 측정한 것이라, Claude Code에 붙여 쓸 개발자에게 특히 참고가 되는 숫자다.

API와 Claude Code에서 쓰기

API로 부를 때는 모델 ID glm-5.2를 쓰고, OpenAI 호환 주소 https://api.z.ai/api/paas/v4/를 지정하면 기존 OpenAI SDK 코드를 그대로 재사용할 수 있다. 추론 깊이를 정하는 reasoning_effort는 high와 max 두 단계뿐이고 기본값은 max다. Z.ai는 여러 단계를 거치는 복잡한 코딩에는 max를 권한다. 반대로 단순한 질의에서 응답 속도가 중요하면 thinking을 disabled로 꺼서 추론 과정을 생략할 수 있다.

Claude Code에서 쓰려면 ~/.claude/settings.json의 env 항목에 ANTHROPIC_BASE_URL을 https://api.z.ai/api/anthropic으로, ANTHROPIC_AUTH_TOKEN을 Z.ai 키로 넣고, ANTHROPIC_DEFAULT_OPUS_MODEL 같은 모델 매핑 변수에 쓸 GLM 모델명을 적는다. 공식 가이드의 기본 설정은 이제 후속 모델을 가리키므로, 5.2를 고정해서 쓰려면 모델명을 직접 지정해야 한다. 직접 서빙은 vLLM 0.23.0 이상이나 SGLang에서 지원되며 FP8 가중치도 함께 제공된다.

고르기 전에 알아둘 한계

이미지 입력이 안 되므로 화면 캡처를 보고 UI를 고치는 식의 작업에는 맞지 않는다. 또 오픈 웨이트라 해도 7,440억 개 파라미터를 메모리에 올려야 하므로 FP8로 줄여도 고성능 GPU 여러 장이 필요하고, 개인 개발자에게 현실적인 경로는 API나 추론 서비스다. 마지막으로 Z.ai는 이후 같은 가격의 후속 모델 GLM-5.3을 내놓았다. 새로 시작하는 프로젝트라면 두 모델을 자기 작업으로 비교해 보고 고르는 게 좋다.
