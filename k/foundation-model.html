파운데이션 모델

Foundation Model

방대한 데이터로 미리 학습해 두고 그 위에 여러 용도를 얹어 쓰는 범용 바탕 모델이다. 작업마다 따로 학습하던 전통적 모델과 달리 번역·요약·코딩·질문 답변을 모델 하나로 처리하고, 특정 용도에는 프롬프트나 파인튜닝으로 맞춰 쓴다.

구분전통적 모델파운데이션 모델
학습작업마다 따로한 번 크게 사전학습
할 수 있는 일한 가지여러 가지
새 용도 추가데이터 모아 새로 학습프롬프트·파인튜닝으로 적응
예스팸 분류기GPT-4, Claude, Llama

2021년 Stanford 연구진이 붙인 이름이다.

맞추는 방법은 가벼운 것부터

파운데이션 모델을 내 용도에 맞추는 방법은 여러 단계가 있다. 비용과 수고가 적은 쪽부터 시도하고, 부족할 때만 다음 단계로 넘어가는 게 기본 순서다.

방법하는 일이럴 때 쓴다
프롬프팅지시문·예시를 넣어 요청대부분의 일상 작업, 가장 먼저 시도
RAG(검색 결합)내 문서를 찾아 함께 전달사내 문서·최신 정보 기반 답변
파인튜닝(SFT)내 데이터로 추가 학습말투·형식 고정, 좁은 전문 작업 반복

API로 부르거나, 내려받아 돌리거나

쓰는 경로는 크게 두 가지다. Claude API·OpenAI API처럼 서비스로 호출하면 서버 없이 바로 쓸 수 있다. Llama 같은 공개 모델은 내려받아 직접 돌리므로 데이터를 밖으로 보내지 않아도 되고 파인튜닝도 자유롭지만, GPU와 운영 부담을 직접 진다.

항목API 호출공개 모델 직접 실행
시작키 발급 후 바로서버·GPU 준비 필요
데이터외부 서비스로 전송내부에 머묾
커스터마이즈제공 범위 안에서자유로움

처음부터 만드는 것보다 훨씬 싸다

모델을 처음부터 학습하려면 막대한 데이터와 계산 자원이 든다. 이미 학습된 파운데이션 모델을 가져와 프롬프팅하거나 파인튜닝하는 비용은 이보다 압도적으로 낮아서, 지금 대부분의 AI 서비스가 이 방식으로 만들어진다. 텍스트뿐 아니라 이미지(CLIP, Stable Diffusion), 코드(Codex), 과학(AlphaFold) 분야에도 같은 방식의 모델이 있다.

바탕의 약점도 그대로 물려받는다

여러 서비스가 같은 바탕 모델 위에 만들어지므로, 바탕 모델의 편향이나 잘못된 지식, 그럴듯한 오답(환각)이 그 위의 모든 앱에 함께 퍼진다. 이 개념을 처음 정리한 Stanford 보고서도 기회와 함께 이런 위험을 중요하게 다뤘다. 중요한 작업에는 출력을 검증하는 단계를 따로 두는 게 안전하다.

완성된 앱으로 쓰거나, 내 서비스의 바탕으로 깐다

가장 흔한 건 챗봇·코딩 도구처럼 이미 만들어진 서비스로 바로 쓰는 방식이다. 직접 만들 때는 API로 불러 프롬프트와 RAG를 얹는 것이 기본이고, 데이터를 밖으로 보낼 수 없을 때만 공개 모델을 내부에서 돌린다.

어디서어떻게 쓰나
대화형 AI 앱ChatGPT·Claude 같은 앱에서 질문, 글쓰기, 번역, 요약에 바로 사용
코딩 도우미에디터나 코딩 에이전트에서 코드 작성·수정·설명을 맡김
사내 문서 검색RAG로 내부 문서를 찾아 붙여 근거 있는 답변을 만듦
내부 전용 앱공개 모델을 사내 서버에 올리고 내 데이터로 파인튜닝
