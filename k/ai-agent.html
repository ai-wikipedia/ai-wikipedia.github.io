AI 에이전트

AI Agent

목표를 주면 스스로 계획을 세우고, 도구를 쓰고, 결과를 보며 다음 행동을 고쳐 가는 AI다. 순서를 미리 정할 수 없는 일, 예를 들어 원인 모를 버그 잡기 같은 일을 맡길 때 쓴다.

한눈에 보기

챗봇은 질문 하나에 답 하나를 내고 끝난다. 에이전트는 "이 버그 고쳐줘" 같은 목표를 받으면 생각하고, 실행하고, 결과를 확인하는 과정을 일이 끝날 때까지 반복한다. 머릿속으로 답을 지어내지 않고, 테스트 결과나 검색 결과 같은 실제 피드백을 보면서 한 단계씩 나아간다.

구분챗봇에이전트
하는 일질문에 답한다일을 끝낸다
진행 방식한 번 답하고 끝생각 → 실행 → 확인을 반복
도구 사용없거나 제한적검색, 코드 실행, 파일 수정

순서가 정해진 일이면 워크플로우로 충분하다

모든 자동화를 에이전트로 만들 필요는 없다. 처리 순서를 미리 정해 둘 수 있는 일은 워크플로우가 더 싸고 결과도 예측하기 쉽다. 에이전트가 필요한 건 어디부터 봐야 할지 미리 알 수 없는 일이다.

방식누가 순서를 정하나이럴 때 쓴다
워크플로우사람이 짠 코드문서 분류 후 유형별 템플릿으로 요약
에이전트모델이 스스로원인 모를 버그 찾기

가장 단순한 구조로 시작하고, 필요할 때만 복잡하게 만드는 게 좋다.

Claude Code로 바로 써 보고, API로 직접 만든다

바로 써 보려면 Claude Code가 가장 쉽다. "결제 모듈 테스트가 깨졌는데 원인 찾아서 고쳐줘"라고 하면 에러 로그를 읽고, 관련 파일을 찾아 코드를 고치고, 테스트를 다시 돌려 통과를 확인한다. 단계마다 지시하지 않아도 알아서 진행한다.

직접 만들려면 Claude API에 웹 검색, 코드 실행, DB 조회 같은 도구를 등록하면 된다. 반복 구조를 처음부터 짜기 부담스럽다면 Claude Agent SDK를 쓰면 도구 실행과 권한 관리가 이미 갖춰져 있다. GitHub이나 사내 DB 같은 외부 시스템은 MCP 서버로 같은 방식으로 붙일 수 있다.

큰 작업은 여러 에이전트에게 나눠 맡긴다

코드베이스 전체를 조사하는 것처럼 한 번에 다 담기지 않는 일은 역할을 나눈다. 총괄 에이전트가 일을 쪼개 여러 에이전트에게 맡기고 결과를 모은다. 다만 에이전트가 많아질수록 서로 손발이 안 맞을 위험도 커지므로, 에이전트 하나로 안 되는 게 확인됐을 때 도입한다.

자율에는 비용과 위험이 따른다

반복할 때마다 토큰이 쌓여 단순 호출보다 훨씬 비싸고, 처음에 방향을 잘못 잡으면 실수가 계속 쌓인다. 그래서 안전장치를 함께 둔다.

위험대비책
끝없이 반복하며 비용이 늘어남최대 반복 횟수를 정한다
파일 삭제, 외부 전송실행 전에 사람이 승인한다
프롬프트 인젝션으로 데이터 유출권한을 최소한으로 쪼갠다
잘한 건지 알기 어려움최종 결과를 검사하는 테스트를 둔다

비공개 데이터 접근, 믿을 수 없는 콘텐츠 읽기, 외부 통신 권한을 한 에이전트에 모두 주면 특히 위험하다.
