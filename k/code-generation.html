코드 생성

Code Generation

코드 생성은 AI가 자연어 설명이나 작성 중인 코드를 보고 코드를 대신 써 주는 기술로, 반복 코드 작성, 낯선 라이브러리 사용, 기능 추가와 테스트 작성에 쓴다. 자동완성·채팅·에이전트 세 방식 중 작업 크기에 맞춰 골라 쓰면 된다.

방식동작이럴 때 쓴다대표 도구
자동완성타이핑하는 동안 다음 코드를 제안반복 코드, 짧은 함수GitHub Copilot
채팅질문하면 코드 조각으로 답라이브러리 사용법, 오류 설명Copilot Chat, Cursor
에이전트여러 파일을 읽고 고치고 명령 실행기능 추가, 리팩토링, 테스트 작성Claude Code, Cursor

오픈소스 코드를 대량으로 학습한 모델이 요청을 코드로 바꾸거나, 다음에 올 코드를 예측하는 방식으로 동작한다.

짧은 코드는 에디터에서, 큰 작업은 에이전트에

VS Code 같은 에디터에 Copilot 확장을 켜면 코드를 치는 동안 회색 제안이 뜨고, Tab을 누르면 받아들인다. 함수 이름과 주석을 먼저 써 두면 의도가 분명해져서 제안이 더 정확해진다.

여러 파일에 걸친 일은 에이전트에 맡긴다. 터미널에서 Claude Code를 열고 "이 함수의 엣지 케이스 처리 추가해줘"라고 말하면 관련 코드를 읽고 고친 뒤 바뀐 내용을 보여 준다. 새 프로젝트의 파일 구조와 보일러플레이트를 만들 때도 이 방식이 빠르다.

맥락을 많이 줄수록 결과가 좋아진다

AI는 보이는 정보만으로 코드를 쓴다. 관련 파일을 지정하고 언어, 라이브러리, 코딩 규칙을 알려 주면 프로젝트에 맞는 코드가 나온다. 큰 요청 한 번보다 작은 단계로 나눠 요청하고 단계마다 테스트를 돌리면 실수가 줄어든다.

요청결과
"로그인 기능 만들어줘"기존 구조와 안 맞는 코드가 나오기 쉽다
"auth 폴더 방식대로 토큰 검증 함수를 추가하고 테스트도 작성해줘"기존 코드와 맞고 확인하기 쉽다

맡기기 좋은 일과 직접 챙길 일

정해진 패턴을 따르는 일일수록 AI가 잘한다. 반대로 실수 하나가 큰 문제로 이어지는 코드는 사람이 직접 꼼꼼히 봐야 한다.

맡기기 좋다직접 확인해야 한다
보일러플레이트, 반복 코드인증·결제 같은 보안 핵심 코드
테스트와 문서 초안성능이 중요한 부분
낯선 라이브러리 예제최근에 바뀐 API

생성된 코드는 항상 검토한다

돌아는 가지만 효율이 나쁘거나 보안 취약점이 있는 코드가 나올 때가 있다. 없는 함수나 패키지를 그럴듯하게 지어내기도 하니, 처음 보는 이름은 공식 문서에서 확인한다. 리뷰하고 테스트를 통과시킨 뒤에 커밋하는 것이 가장 확실한 안전장치다.

세 방식을 섞어 쓰는 게 보통이다

개발자들은 보통 에디터 자동완성을 켜 둔 채 일하다가, 막히는 부분은 채팅으로 묻고, 여러 파일에 걸친 일은 에이전트에 맡긴다. 개발자가 아니어도 채팅형 AI로 간단한 스크립트를 만들어 반복 업무를 줄이는 경우가 많다.

어디서어떻게 쓰나
에디터코드를 치는 동안 뜨는 제안을 Tab으로 받아 반복 코드를 줄인다
코딩 에이전트기능 추가·리팩토링·테스트 작성을 말로 맡기고, 바뀐 내용을 검토한 뒤 커밋한다
채팅형 AI오류 메시지를 붙여 넣어 원인과 수정 코드를 받거나, 파일 정리용 짧은 스크립트를 만든다
