오크

Oak (Agent-Native Version Control)

오크(Oak)는 AI 코딩 에이전트에 맞춰 새로 만든 버전 관리 시스템이다. 에이전트 여러 개가 한 저장소에서 동시에 작업할 때 Git의 클론 시간과 worktree 충돌을 줄이고 싶다면 쓴다.

한눈에 보기

오크는 Git 대신 쓰는 에이전트 전용 버전 관리 도구다. 작업 단위를 커밋이 아니라 세션으로 잡아서, 에이전트 여러 개가 한 저장소에서 서로 부딪히지 않고 병렬로 일하게 해 준다.

항목GitOak
시작할 때저장소 전체 클론필요한 파일만 그때그때
병렬 작업.git을 같이 쓰는 worktree작업마다 마운트·브랜치를 따로
중간 저장매번 커밋 메시지메시지 없는 체크포인트
대용량 파일LFS 따로 설정설정 없이 처리

파일은 열 때 가져오고, 메시지는 마지막에 한 번

지연 마운트(lazy mount)는 저장소를 통째로 내려받지 않고 작업 공간을 먼저 띄운 뒤, 에이전트가 파일을 처음 열 때 그 파일만 가져온다. 큰 저장소에서 클론을 몇 분씩 기다릴 필요가 없다.

중간 저장은 메시지 없는 체크포인트로 남고, 작업이 끝나면 작업 설명이 커밋 하나로 합쳐질 때의 메시지가 된다. 에이전트가 커밋 메시지를 쓰느라 토큰을 쓰지 않아도 되고, 최종 이력도 깔끔하다.

설치하고 "Git 대신 Oak를 써라"라고 말하면 끝

모델이나 IDE는 바꿀 필요가 없다. 설치한 뒤 저장소를 초기화하고, 에이전트에게 Git 대신 Oak를 쓰라고 지시하면 된다.

단계명령
설치curl -fsSL oak.space/install | sh
로그인oak login
저장소 준비oak init

예를 들어 Claude Code에 버그 수정 세 건을 동시에 맡기면 작업마다 자기 마운트와 브랜치에서 돌아가서 서로 건드리지 않는다. 모든 명령이 --json 출력을 지원하므로 에이전트가 결과를 바로 읽고 다음 행동을 정할 수 있다.

아직 베타, 사이드 프로젝트부터

지금은 공개 베타(v0.99.0)이고 Apache-2.0으로 공개돼 있다. 사용자 코드를 학습에 쓰지 않는다고 밝혔다. Git보다 최대 95% 빠르다는 수치는 제작진이 직접 잰 벤치마크다.

팀 전체가 옮기려면 리뷰 도구, CI, 기존 이력과 맞추는 비용이 든다. Git을 바닥에 두고 그 위에 에이전트용 계층을 얹는 쪽이 더 현실적이라는 시각도 있다. 클론 시간이나 worktree 충돌 때문에 고생하고 있다면 사이드 프로젝트에서 먼저 써 보고 판단하는 게 좋다.
