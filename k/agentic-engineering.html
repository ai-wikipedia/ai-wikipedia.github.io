에이전틱 엔지니어링

Agentic Engineering

AI 에이전트가 코드를 쓰고, 사람은 설계와 검증, 품질을 책임지는 개발 방식이다. 바이브 코딩처럼 '일단 돌아가면 OK'로 끝내지 않고, 테스트와 리뷰를 갖춘 채 에이전트에게 실제 개발을 맡길 때 쓴다.

한눈에 보기

에이전틱 엔지니어링은 코드 작성은 거의 다 AI 에이전트가 맡고, 사람은 설계·검증·품질 관리를 맡는 개발 방식이다. 바이브 코딩이라는 말을 만든 Andrej Karpathy가 "바이브 코딩은 이제 지났다"며 내놓은 개념이다. 에이전트가 짠 코드를 실제 서비스에 쓸 만큼 믿을 수 있어야 할 때 쓴다.

항목바이브 코딩에이전틱 엔지니어링
코드 작성AI가 생성AI 에이전트가 계획·구현·테스트
사람의 역할에러 메시지 다시 붙여넣기설계, 리뷰, 품질 책임
코드 읽기거의 안 읽음동료의 PR처럼 검토
믿을 수 있는 근거일단 돌아감테스트 통과

테스트가 있어야 맡길 수 있다

바이브 코딩과 가장 크게 다른 점은 테스트다. 테스트가 탄탄하면 에이전트가 테스트를 통과할 때까지 스스로 고치기를 반복할 수 있고, 그래야 결과를 믿을 수 있다. 테스트 없이 에이전트에게 맡기면 그냥 운에 기대는 것과 같다.

계획 → 실행 → 검증을 반복한다

작업은 Plan → Execute → Verify 루프로 돌아간다. 먼저 스펙 문서로 목표와 제약을 정확히 알려 주고, 일을 에이전트가 처리할 크기로 나눈다. 에이전트가 코드를 내놓으면 사람이 리뷰한다.

도구이렇게 쓴다
CLAUDE.md프로젝트 규칙을 에이전트에게 전달
훅린트·타입체크 같은 가드레일을 자동 실행
스킬반복하는 워크플로우를 명령 한 줄로 호출
멀티에이전트코드 작성과 테스트를 에이전트별로 나눠 동시에 진행

멀티에이전트로 나누면 에이전트 하나가 기억할 수 있는 양(컨텍스트)이 모자라는 문제도 피하면서 병렬로 작업할 수 있다.

매일 쓰기 좋은 세 가지 패턴

Simon Willison이 직접 매일 쓰는 패턴으로 정리한 것이다.

패턴방법
Red/Green TDD실패하는 테스트를 먼저 쓰고, 통과시키는 일은 에이전트에게 맡긴다
템플릿반복되는 작업 구조를 마크다운으로 정해 두고 재사용시킨다
호딩(Hoarding)관련 정보를 미리 컨텍스트에 모아 둬 에이전트가 맥락을 잃지 않게 한다

공학 역량을 대신하지 않고 키워 준다

감독 없이 에이전트에게 코드를 맡기면 기술 부채가 쌓이는 속도가 얻는 가치보다 빠르다. 에이전틱 엔지니어링은 CI/CD, 테스트 자동화, 아키텍처 감독 같은 기존 역량을 더 키워 주는 방식이지 그 역량을 대신해 주지 않는다.
