디시전 모델

Non-Autoregressive Decision Model

디시전 모델은 글을 쓰지 않고 정해진 선택지 가운데 하나를 고르거나 점수·확률만 돌려주는 AI 모델이다. 에이전트가 라우팅, 도구 선택, 분류, 가드레일처럼 빠르고 정형화된 판단을 내려야 할 때 LLM 대신 쓴다.

한눈에 보기

디시전 모델은 '상태'(텍스트나 JSON)와 코드로 정의한 질문을 받아 선택지·점수·확률만 돌려준다. 설명이나 문장은 만들지 않는다. 일반 LLM은 답을 토큰 하나씩 이어 쓰지만, 디시전 모델은 허용된 답 전체를 한 번에 나란히 채점한다. 그래서 답이 늘 스키마 안의 값으로 나온다.

구분일반 LLM디시전 모델
출력자유로운 텍스트선택지·점수·확률
생성 방식토큰을 하나씩한 번에 채점
잘 맞는 일추론, 코딩, 글쓰기분류, 라우팅, 검증

질문은 세 가지 형태로 던진다

Jev 기준으로 질문 유형은 세 가지다. 질문과 선택지 설명을 코드로 정의해 API로 보내면, 소프트웨어가 바로 쓸 수 있는 값이 돌아온다.

유형돌려주는 값이럴 때 쓴다
Choice선택지별 확률 + 확신도문의를 담당 팀에 배정
Score2~10단계 척도 위 위치티켓 우선순위 매기기
Noul0~1 사이 확률 하나"이 입력이 스팸인가?"

확률을 보고 사람에게 넘길지 정한다

보정된 확률이 함께 나오는 게 핵심이다. 확신도가 높으면 자동으로 처리하고, 애매하면 사람에게 검토를 맡기거나 다시 시도하는 제어 장치로 쓸 수 있다. 예를 들어 보험 청구라면 디시전 모델이 복잡도를 분류하고 빠진 정보를 표시한다. 서류 검토는 LLM이 하고, 분쟁 건은 담당자가 맡는다.

에이전트의 판단 단계에 끼워 넣는다

응답이 수백 밀리초 안에 오기 때문에 '상태 읽기 → 판단 → 실행 → 다시 판단'을 반복하는 루프 안에서 여러 번 불러도 된다. 입력 분류, 모델 라우팅, 도구 선택, 인자 검사, 출력 채점은 디시전 모델에게 맡긴다. 복잡한 분석·계획·추론만 고성능 LLM에게 넘기면 토큰 비용과 지연이 함께 줄어든다. Jev 같은 상용 API 말고도 가중치를 공개한 Laya와 AWS 스트랜즈 디사이더가 있어 직접 띄워 쓸 수도 있다.

입력이 부실하면 판단도 부실하다

판단의 질은 넘겨준 상태에 달려 있다. 문서를 통째로 넣기보다 질문과 관련된 필드만 골라 보내야 정확해진다. 또 예외 처리를 이미 코드로 다 해 둔 업무라면 LLM을 쓸 때와 차이가 크지 않다는 사용자 평가도 있다. 빠른 판단과 추가 추론 중 무엇이 필요한지 애매한 문제를 위해, 불확실할 때만 더 생각하는 '싱킹 디시전 모델'도 나와 있다.
