오픈 멀티 에이전트

Open Multi-Agent

목표 한 줄을 주면 할 일을 작업 그래프(task DAG)로 쪼개 여러 에이전트에게 나눠 맡기는 오픈소스 프레임워크다. 멀티 에이전트의 작업 순서를 손으로 엮지 않고 자동으로 돌리고 싶을 때 쓴다.

한눈에 보기

오픈 멀티 에이전트(Open Multi-Agent)는 목표 한 줄을 받으면 할 일을 잘게 쪼개 여러 에이전트에게 나눠 맡기는 오픈소스 프레임워크다. 멀티 에이전트를 만들 때 가장 귀찮은 "누가 무슨 일을 어떤 순서로 할지"를 손으로 엮지 않고 이 도구에 맡기고 싶을 때 쓴다. 개념을 설명하는 패턴이 아니라, 목표 입력부터 결과 취합까지 한 번에 돌려 주는 실행 도구다.

단계직접 짤 때오픈 멀티 에이전트
할 일 나누기사람이 설계코디네이터가 자동으로 분해
순서 정하기의존 관계를 코드로 연결task DAG로 자동 정리
실행하나씩 직접 호출독립 작업은 병렬, 이어진 작업은 순서대로
결과 모으기직접 취합런타임이 취합

task DAG: 작업 사이의 선후 관계를 화살표로 이은 그래프. 한 바퀴 돌아 제자리로 오는 순환은 없다.

목표만 넘기면 계획부터 실행까지

가장 간단한 사용법은 runTeam()에 "X를 만들어줘" 같은 목표를 넘기는 것이다. 코디네이터가 계획을 세우고 팀을 꾸려 실행까지 한 번에 처리하므로 그래프를 직접 그릴 필요가 없다.

진행 상황은 onProgress 이벤트와 onTrace 스팬으로 지켜본다. 어느 작업이 어디서 막혔는지 찾을 때 유용하다. 셸이나 CI에서 돌릴 때는 JSON 출력 위주의 oma CLI를 쓰면 된다.

모델과 도구를 작업마다 바꿔 낀다

특정 모델 회사에 묶이지 않아서 작업마다 Claude, GPT 같은 다른 모델을 끼울 수 있다. 외부 도구는 connectMCPTools()로 MCP 서버를 연결해 에이전트에게 통째로 열어 준다. 예를 들어 역할을 이렇게 나눌 수 있다.

에이전트맡는 일쓰는 도구
에이전트 AGitHub 이슈 읽기MCP 서버
에이전트 B코드 고치기파일시스템 샌드박스

잘못 쪼개면 엉뚱한 그래프가 된다

자동 분해가 편한 대신, 코디네이터가 목표를 잘못 쪼개면 엉뚱한 DAG가 만들어진다. 그래서 실제 서비스에 쓸 때는 아래 제어 장치를 함께 켜 두는 것이 권장된다.

장치하는 일
컨텍스트 관리슬라이딩 윈도우, 요약·압축
재시도·백오프실패한 작업을 간격을 두고 다시 시도
루프 감지·출력 자르기무한 반복과 너무 긴 도구 출력 막기

작업 흐름을 사람이 미리 정해 두고 싶다면 YAML로 흐름을 고정하는 결정론적 방식(예: Conductor)이 더 맞을 수 있다.

#오픈소스#task DAG#오케스트레이션#TypeScript
