양자화

Quantization

모델 가중치를 32비트 부동소수점에서 8비트, 4비트 정수 등 낮은 정밀도로 변환해 메모리와 연산 비용을 줄이는 기법. 큰 모델을 소비자 장치에서 실행할 수 있게 한다.

숫자를 덜 정밀하게 적어 모델을 줄이는 기술

양자화(Quantization)란 모델 가중치를 표현하는 숫자의 정밀도를 낮춰 모델 크기와 메모리 사용량, 연산 비용을 줄이는 기법이다. 큰 언어 모델은 수십억~수천억 개의 숫자로 이루어진 거대한 표라고 생각하면 된다. 이 숫자들은 보통 16비트(2바이트)로 저장되는데, 이를 8비트나 4비트로 줄이면 모델이 절반, 4분의 1로 작아진다. 사진을 원본 대신 적당히 압축한 JPG로 저장해도 눈으로는 차이를 거의 못 느끼듯, 모델도 정밀도를 어느 정도 깎아도 답변 품질이 대부분 유지된다는 게 출발점이다.

먼저 메모리 계산부터

양자화가 왜 필요한지는 계산 한 번이면 보인다. 70B(700억 파라미터) 모델을 16비트로 올리면 가중치만 약 140GB라 데이터센터용 GPU 여러 장이 필요하다. 8비트면 약 70GB, 4비트면 약 35GB로 줄고, 실행 중에 쌓이는 KV 캐시와 여유분까지 더하면 40GB대 메모리에서 돌릴 수 있는 수준이 된다. 같은 계산으로 8B 모델은 4비트에서 5GB 안팎이라 평범한 노트북에서도 돌아간다. 다만 실제 4비트 파일은 묶음마다 붙는 스케일 값 같은 부가 정보 때문에 가중치당 4.5~5비트 정도가 된다는 점을 감안해야 한다.

로컬에서 쓸 때: GGUF 이름표 읽기

로컬 실행에서는 llama.cpp 계열이 쓰는 GGUF 형식이 사실상 표준이다. Ollama로 ollama run을 하면 대개 4비트 양자화본이 기본으로 내려오고, 직접 고를 때는 Hugging Face에서 Q4_K_M, Q5_K_M, Q8_0 같은 이름이 붙은 파일을 받는다. 앞의 숫자가 비트 수라 클수록 크고 정확하다. Llama 3.1 8B 기준으로 Q8_0이 약 8GB, Q4_K_M이 약 4.6GB인데, 생성 속도는 오히려 4비트 쪽이 더 빠르다. 토큰 하나를 만들 때마다 메모리에서 읽어 와야 할 데이터가 줄기 때문이다. 메모리에 여유가 있으면 Q5_K_M이나 Q6_K, 빠듯하면 Q4_K_M이 무난한 출발점이다. 직접 만들 때는 llama-quantize로 16비트 원본에서 변환하고, 예시 텍스트로 가중치별 중요도를 미리 계산한 imatrix 파일을 함께 주면 같은 비트에서도 손실을 더 줄일 수 있다. 다만 이미 양자화된 파일을 다시 양자화하면 품질이 크게 떨어지니 피해야 한다.

서버에서 쓸 때: AWQ, GPTQ, 그리고 FP8·FP4

vLLM 같은 추론 서버에서는 GPTQ나 AWQ로 양자화한 체크포인트를 많이 쓴다. GPTQ는 소량의 예시 데이터로 양자화 오차를 층마다 보정하고, AWQ는 실제 입력이 지나갈 때 크게 반응하는 1% 남짓의 중요한 가중치 채널을 찾아 보호한다. 둘 다 이미 학습된 모델을 나중에 압축하는 PTQ(사후 학습 양자화)라 다시 학습할 필요가 없다. 아낀 GPU 메모리만큼 요청을 더 많이 묶어 처리할 수 있어 처리량이 오른다. 양자화된 체크포인트를 vllm serve로 띄우면 설정 파일에서 방식을 자동으로 읽어 들이고, 16비트 원본을 띄우면서 --quantization fp8을 주면 로딩 시점에 바로 FP8로 바꿔 올리는 것도 가능하다.

최신 GPU에서는 정수 대신 저정밀 부동소수점 형식이 대세가 되고 있다. H100 세대부터 FP8 연산이 하드웨어로 지원되고, Blackwell 세대는 값 16개마다 스케일을 따로 두는 4비트 형식 NVFP4를 지원해 FP8 대비 정확도 손실을 1% 안팎으로 묶으면서 메모리를 더 줄인다. 32개 값마다 스케일을 두는 비슷한 형식인 MXFP4도 있는데, OpenAI의 오픈 웨이트 모델 gpt-oss는 아예 MXFP4로 양자화된 상태로 공개돼 120B 모델이 80GB GPU 한 장에 올라간다. 가중치뿐 아니라 대화가 길어질수록 커지는 KV 캐시도 양자화할 수 있다. vLLM에서는 --kv-cache-dtype fp8 옵션 하나로 캐시 메모리를 절반으로 줄여 더 긴 컨텍스트와 더 많은 동시 요청을 받는다. 파인튜닝 쪽에서는 bitsandbytes로 모델을 4비트로 올린 뒤 LoRA 어댑터만 학습하는 QLoRA가 같은 원리를 쓴다.

얼마나 잃는지는 직접 재야 한다

양자화의 손실은 고르게 나타나지 않는다. 일상 대화에서는 4비트도 차이를 느끼기 어렵지만, 긴 문맥 추론이나 수학, 코드처럼 작은 오차가 쌓이는 작업에서 먼저 티가 난다. 작은 모델일수록 같은 비트에서 더 많이 손상되고, 3비트 아래로 내려가면 대부분의 모델에서 품질이 눈에 띄게 떨어지기 시작한다. 그래서 퍼플렉시티나 원본 모델과의 출력 분포 차이(KL 발산) 같은 지표로 1차 확인을 하고, 최종 판단은 내 서비스의 실제 질문으로 만든 평가 세트에서 원본과 나란히 비교해 내리는 게 안전하다. 학습 단계부터 낮은 정밀도를 겪게 하는 QAT(양자화 인지 학습)는 이런 손실을 더 줄이지만 다시 학습해야 해서, 개발자가 직접 하기보다는 모델 제작사가 공식 양자화본을 낼 때 주로 쓰인다.
