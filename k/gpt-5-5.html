GPT-5.5 (OpenAI)

OpenAI가 2026년 4월 공개한 플래그십 모델로, 복잡하고 여러 단계로 얽힌 실제 업무를 스스로 계획하고 도구를 쓰며 자기 결과를 검증해 끝까지 처리하도록 만들어졌다.

시키면 끝까지 해내는 모델

GPT-5.5는 OpenAI가 2026년 4월 23일 공개한 플래그십 모델이다. ChatGPT와 Codex에 먼저 풀렸고 API는 다음 날 열렸다. OpenAI는 이 모델을 '실제 업무와 에이전트를 위한 새로운 수준의 지능'이라고 소개했다. 핵심은 질문에 답을 잘하는 것보다, 지저분하고 여러 갈래로 얽힌 작업을 맡겼을 때 스스로 계획을 세우고, 도구를 쓰고, 자기 결과를 확인하며 끝까지 밀고 나가는 능력이다. GPT-4.5 이후 처음으로 기반 모델을 새로 학습한 모델이며, 엔비디아의 랙 단위 시스템과 함께 설계했다는 점도 OpenAI가 강조한 부분이다.

비싸졌지만 덜 쓴다

API 모델 ID는 gpt-5.5이고, 문맥은 약 105만 토큰, 최대 출력은 12만 8천 토큰이며 텍스트와 이미지를 입력으로 받는다. 가격은 입력 100만 토큰당 5달러, 캐시된 입력 0.5달러, 출력 30달러로 GPT-5.4의 정확히 두 배다. 다만 같은 Codex 작업을 끝내는 데 GPT-5.4보다 출력 토큰을 40% 가까이 적게 쓴다는 분석이 있고, OpenAI는 이를 반영한 실제 작업당 비용 증가가 20% 안팎이라고 설명한다. 토큰 단가보다 작업 하나를 끝내는 데 드는 총비용으로 비교해야 하는 이유다.

주의할 요금 규칙도 있다. 입력이 27만 2천 토큰을 넘으면 그 세션 전체에 입력 2배, 출력 1.5배 요금이 붙는다. 100만 토큰 문맥을 쓸 수 있다고 해서 매번 코드베이스를 가득 채워 넣으면 비용이 급격히 뛴다. 실시간 응답이 필요 없는 대량 작업은 배치 API로 돌리면 절반 가격이다. 데이터를 특정 지역에서만 처리하도록 하는 지역 처리 엔드포인트를 쓰면 10%가 더 붙는다.

지식 기준 시점은 2025년 12월 1일이다. 현재 gpt-5.5는 gpt-5.5-2026-04-23 스냅샷을 가리키는데, 프롬프트를 정교하게 맞춰 둔 프로덕션 서비스라면 스냅샷 이름을 직접 적어 고정해야 나중에 모델이 바뀌어도 동작이 흔들리지 않는다. 출력이 매번 똑같아야 하는 파이프라인이나 비용 제약이 큰 서비스는 굳이 서둘러 옮기지 말고 GPT-5.4에 머물라는 조언도 있다.

추론 강도 조절과 Codex에서 쓰기

추론 강도는 reasoning_effort로 none, low, medium, high, xhigh 중에서 고르고 기본값은 medium이다. GPT-5.5는 이전 모델보다 답이 간결해서 medium에서도 GPT-5.4의 high와 비슷한 결과를 내는 경우가 많으니, 기존 설정을 그대로 옮기기보다 한 단계 낮춰 비교해 보는 게 좋다. Responses API에서는 함수 호출, 웹 검색, 파일 검색, 코드 인터프리터, 셸, 패치 적용, 컴퓨터 사용, MCP 같은 도구를 붙일 수 있다.

Codex CLI에서는 ~/.codex/config.toml에 model = "gpt-5.5"를 적거나, 실행할 때 codex -m gpt-5.5, 세션 중에는 /model gpt-5.5로 바꾼다. 추천되는 운영 방식은 프로필을 나누는 것이다. 평소 작업은 GPT-5.5에 medium, 계획 수립은 high, 단순 반복 작업은 더 작은 모델에 low를 걸어 둔 프로필을 만들고 작업마다 골라 쓰면 비용을 크게 아낄 수 있다. 이전 모델용으로 써 둔 '수정 전에 파일이 있는지 꼭 확인하라' 같은 방어적 지시는 빼도 되는 경우가 많다. 참고로 출시 직후 Codex에서는 API 키가 아니라 ChatGPT 계정으로 로그인한 경우에만 GPT-5.5를 고를 수 있었다.

어디서 강하고 어디서 아닌가

OpenAI가 발표한 수치로는 명령줄 작업을 계획하고 도구를 조율하는 능력을 재는 Terminal-Bench 2.0에서 82.7%로, GPT-5.4(75.1%)와 Claude Opus 4.7(69.4%)을 앞섰다. 100만 토큰 길이에서 정보를 찾아내는 MRCR v2 점수도 GPT-5.4의 두 배 수준으로 올랐다. 반면 실제 GitHub 이슈 해결을 재는 SWE-bench Pro에서는 58.6%로 Claude Opus 4.7(64.3%)에 뒤졌다. 그래서 터미널 중심의 자동화는 GPT-5.5에, 오래 걸리는 이슈 해결은 다른 모델과 섞어 쓰라는 조언도 나온다. 정확도가 더 필요한 작업에는 gpt-5.5-pro가 있지만 입력 30달러, 출력 180달러로 여섯 배 비싸니 꼭 필요한 단계에만 쓰는 게 맞다.
