코덱스 시큐리티

Codex Security (OpenAI)

코덱스 시큐리티는 OpenAI가 만든 애플리케이션 보안 에이전트다. 코드베이스에 맞는 위협 모델을 세워 취약점을 찾고, 격리된 환경에서 실제로 재현되는지 검증한 다음 사람이 검토할 패치를 제안한다. 오탐을 줄여서 보안 리뷰가 개발 속도를 붙잡는 병목이 되지 않게 하려고 쓴다.

경보만 울리는 스캐너 대신 보안 연구자처럼

코덱스 시큐리티(Codex Security)는 OpenAI가 2026년 3월 리서치 프리뷰로 공개한 애플리케이션 보안 에이전트다. 2025년 10월에 발표한 에이전트형 보안 연구 도구 Aardvark를 발전시킨 것으로, 코드 속 취약점을 찾고 실제로 공격이 되는지 확인한 뒤 고칠 패치까지 제안한다. 기존 정적 분석 도구(SAST)를 써 본 개발자라면 겪어 봤을 문제가 있다. 규칙에 걸리는 패턴마다 경고가 쏟아지는데, 대부분은 실제로는 위험하지 않거나 영향이 미미하다. 보안팀은 그 경고를 하나하나 걸러 내느라 시간을 다 쓰고, 정작 진짜 위험한 버그는 그 사이에 묻힌다. 코딩 에이전트 덕분에 코드가 쏟아져 나오는 지금은 이 선별 작업이 더 큰 병목이 됐다. 코덱스 시큐리티는 경고를 기계적으로 내뱉는 스캐너가 아니라 보안 연구자처럼 움직이도록 설계됐다. 코드를 읽고, 테스트를 돌리고, 현실적인 공격 경로를 따라가 본 다음 확인된 것만 보고하는 방식이다.

위협 모델에서 출발해 패치로 끝나는 흐름

일반적인 SAST가 규칙, 오염 추적(taint tracking), 데이터 흐름 분석에서 시작한다면 코덱스 시큐리티는 저장소 전체의 맥락에서 시작한다. GitHub 저장소를 연결하면 먼저 그 코드베이스에 맞춘 위협 모델을 만든다. 공격자가 들어올 수 있는 진입점, 신뢰 경계, 민감한 데이터, 영향이 큰 코드 경로를 정리한 일종의 지도다. 팀은 이 위협 모델을 직접 보고 고칠 수 있다. 예를 들어 어떤 관리자 API가 실제로는 사내망에서만 열려 있다면 그 배포 가정을 반영해서, 에이전트가 현실과 동떨어진 시나리오에 매달리지 않게 할 수 있다.

그다음은 탐색과 검증이다. 저장소 전체를 훑는 전체 스캔과 새로 들어온 변경만 보는 커밋 스캔 중에서 고를 수 있다. 의심 지점을 찾으면 공격자가 제어하는 입력이 진입점에서 민감한 결과까지 어떻게 흘러가는지 공격 경로를 분석하고, 가능성과 영향을 기준으로 점수를 매긴다. 결과를 보여 주기 전에는 격리된 환경에서 실제 재현을 시도한다. 검증기는 재현 결과, 실행 세부 정보, 개념 증명(PoC) 산출물을 기록하므로 리뷰어는 "이게 진짜 터지는가"를 증거로 판단할 수 있다. 검증된 취약점에는 근본 원인을 고치는 최소한의 패치를 제안한다. 코드를 자동으로 고치지는 않는다. 패치는 사람이 검토하도록 표시되고, 평소 워크플로대로 풀 리퀘스트로 만들어 반영한다. OpenAI는 같은 저장소들에서 이 방식으로 오탐률이 절반 넘게 줄었다고 밝혔다.

터미널과 CI에서 직접 돌리기

처음에는 ChatGPT의 Codex 웹에서 Pro, Enterprise, Business, Edu 사용자에게 제공됐지만, 지금은 쓰는 경로가 여러 갈래다. Codex 데스크톱의 Security 워크벤치와 Codex CLI에서는 플러그인으로 설치해서 쓰고, 클라우드 버전은 Codex cloud에 연결된 GitHub 저장소를 커밋 단위로 스캔한다. CLI와 TypeScript SDK는 Apache 2.0 라이선스로 @openai/codex-security 패키지로 공개되어 있어서, npx @openai/codex-security --help로 바로 실행해 볼 수 있다.

SDK를 쓰면 스캔을 코드로 제어할 수 있다. security.run("/path/to/directory", { mode: "deep", workers: 2, maxTimeHours: 1.5 })처럼 깊이, 병렬 워커 수, 새 발견이 없을 때 몇 번 만에 멈출지, 최대 실행 시간을 지정하고, 끝나면 리포트 경로를 받는다. 그래서 릴리스 전 야간 배치로 핵심 서비스 저장소를 deep 모드로 돌리고, 평소 PR에는 커밋 스캔만 걸어 두는 식으로 비용과 깊이를 나눠 운영할 수 있다. 여러 저장소를 한꺼번에 검사할 때는 컨테이너 기반 대량 스캔을 쓰고, npx @openai/codex-security dedupe로 저장소 사이에 겹치는 발견을 로컬에서 독립 리뷰를 거쳐 하나로 묶을 수 있다. 공유 라이브러리 하나의 결함이 열 개 서비스에서 열 번 보고되는 일을 줄여 준다.

소스 코드만으로 보이지 않는 것

한계도 분명하다. 코덱스 시큐리티는 소스 코드와 저장소 맥락을 근거로 판단하므로, 실제로 배포되어 돌아가는 시스템의 설정, 인프라, 런타임 동작에서 생기는 문제까지 다 잡아 주지는 못한다. 동적 테스트 도구를 만드는 쪽에서 "소스 코드에서 찾는 것만으로 운영 중인 시스템이 안전해지는가"라는 질문을 던지는 이유다. 위협 모델이 실제 배포 구조와 다르면 분석 방향도 틀어지므로, 사람이 위협 모델을 점검하는 단계를 건너뛰면 안 된다. 접근 권한도 신경 써야 한다. 관리형 워크스페이스에서는 관리자가 접근을 제한할 수 있고, 공개 패키지는 ChatGPT 인증과 API 키 인증을 모두 지원하지만 인증만 한다고 모든 스캔 기능을 쓸 수 있는 것은 아니다. Anthropic의 Claude Code Security와 비슷한 흐름에 있는 도구로, 결국 기존 보안 체계를 대신하기보다는 그 위에서 선별과 수정을 빠르게 하는 역할이라고 보는 게 맞다.
