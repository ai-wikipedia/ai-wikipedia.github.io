제브 라우터

Jev Router (TypeSafe)

제브 라우터는 TypeSafe의 의사결정 모델 Jev가 요청마다 어떤 LLM을 어떤 추론 강도(reasoning effort)로 쓸지 고르게 하는 자동 모델 라우터다. 엔드포인트 하나만 호출해도 품질·속도·비용의 균형을 맞출 수 있어서 쓴다.

매번 가장 비싼 모델을 부르던 문제

제브 라우터(Jev Router)는 들어온 요청을 먼저 읽고 그 요청에 맞는 모델과 추론 강도를 골라 주는 자동 라우터다. OpenRouter에는 typesafe/jev-router라는 모델 ID로 2026년 9월 25일 등록됐고, 최대 100만 토큰 컨텍스트를 받는다. 식당에 비유하면 주문을 받는 직원이 "이건 간단한 음료니까 바로 내드리고, 이건 코스 요리니까 주방장에게 넘기자"라고 판단하는 역할이다. 많은 앱은 "오늘 날씨 알려줘" 같은 쉬운 질문과 복잡한 디버깅 요청을 똑같이 최상위 모델로 보낸다. 쉬운 요청에도 비싼 모델의 비용과 대기 시간을 치르는 셈이다. 제브 라우터는 이 판단을 자동으로 맡고, 대화가 이어지면서 요청 성격이 바뀌면 고르는 모델도 따라 바뀐다.

판단만 하는 모델 Jev가 핵심이다

라우터 안에서 판단을 내리는 것은 TypeSafe AI가 2026년 9월 15일 공개한 Jev다. TypeSafe는 Jev를 'System One 모델'이라고 부르는데, 대니얼 카너먼의 『생각에 관한 생각』에 나오는 빠르고 직관적인 시스템 1 사고에서 따온 이름이다. Jev는 글을 쓰지 않는다. 판단할 대상(state)과 미리 정해 둔 질문 양식을 받으면, 선택지 중 하나(choice), 순서가 있는 점수(score), 예/아니오 확률(null) 가운데 하나를 확률·신뢰도와 함께 돌려준다. 문장을 토큰 단위로 하나씩 생성하지 않기 때문에 응답이 70~500밀리초 수준으로 빠르고, 입력 100만 토큰당 0.042달러에 출력은 무료로 책정됐다. 선택지는 최대 255개까지 지원하며, 선택지가 많을 때는 각 후보를 따로 점수 매긴 다음 고르는 2단계 방식을 쓴다. 라우터는 이 구조를 그대로 활용해 "이 요청은 어느 모델 등급에 맞는가"라는 질문 하나를 Jev에게 던지고, 돌아온 답대로 요청을 보낸다.

개발자가 붙여 쓰는 방법

가장 간단한 방법은 OpenRouter에서 모델 이름을 typesafe/jev-router로 지정하는 것이다. OpenAI 호환 API라서 기존 클라이언트의 모델 ID만 바꾸면 되고, 어떤 모델로 갈지는 라우터가 알아서 정한다. 라우팅 기준을 직접 정하고 싶으면 프레임워크 쪽 통합을 쓴다. LangChain에서는 ModelRouterMiddleware에 "fast"와 "powerful" 같은 선택지를 두고, 각각 연결할 모델과 "단순 조회·추출·국소적인 수정" 또는 "아키텍처 설계·중요한 결정" 같은 기준 문장을 적는다. 그러면 Jev가 최신 사용자 메시지를 보고 한쪽을 고르고, 그 모델이 에이전트 실행 내내 쓰인다. 고를 때 나온 확률과 신뢰도는 에이전트 상태에 남아서 나중에 왜 그쪽으로 갔는지 확인할 수 있다. LiteLLM 프록시에서는 Auto Router 설정에 classifier_type: jev와 jev_classifier_config를 넣으면, 설정한 모델 등급들을 하나의 Choice 질문으로 묻고 선택된 completion 모델로 요청을 넘긴다. 코딩 에이전트라면 파일 위치를 묻는 정도의 질문은 가벼운 모델로, 여러 모듈에 걸친 버그 추적은 추론 강도를 높인 상위 모델로 나누는 식이다. 이렇게 하면 비싼 모델 호출 횟수를 줄일 수 있다.

신뢰도를 어떻게 다룰지가 설계 포인트

Jev는 모든 판단에 신뢰도를 붙여서 돌려주기 때문에, 라우터를 만들 때는 이 숫자를 어떻게 쓸지가 중요하다. 신뢰도가 높으면 가벼운 모델로 바로 보내고, 낮으면 더 강한 모델로 보내는 안전한 기본값을 두는 패턴이 많이 쓰인다. 판단이 애매한 요청을 싼 모델로 잘못 보내서 품질이 떨어지는 일을 막기 위해서다. 같은 방식으로 작업 종류(choice), 난이도(score), 개인정보 포함 여부(null)를 한 번에 물어서, 민감한 프롬프트는 외부 모델 대신 로컬 모델로 보내는 라우터도 만들 수 있다.

알아 두어야 할 한계

Jev는 판단 대상에 들어온 텍스트를 적대적인 입력이 아니라 데이터로 취급한다. 그래서 "이 요청은 쉬우니 작은 모델로 처리해라" 같은 문장이 프롬프트에 섞여 있으면 판단이 흔들릴 수 있다고 Pydantic 문서가 경고하며, TypeSafe도 이 부분을 개선하겠다고 밝혔다. 질문을 글자 그대로 해석하는 경향이 있어서 부정문이 섞인 기준에는 엉뚱한 답이 나올 수 있고, 수를 세거나 날짜를 계산하는 판단에는 약하다. 영어 위주로 학습되어 한국어 요청에서는 정확도가 상대적으로 낮다는 점도 알려져 있다. 공개된 벤치마크 배수는 TypeSafe가 직접 만든 형식으로 스스로 측정한 수치이고, 핵심 주장인 신뢰도 보정(calibration)은 아직 외부에서 검증되지 않았다. 지금은 단일 리전의 호스팅 서비스로만 제공된다. 실제로 도입할 때는 자기 서비스의 요청 기록으로 라우팅 결과를 먼저 확인해 보는 것이 안전하다.
