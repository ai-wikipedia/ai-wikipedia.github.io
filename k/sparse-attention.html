희소 어텐션

Sparse Attention

모든 토큰끼리 다 비교하는 대신 중요한 일부 토큰만 골라 어텐션을 계산해, 긴 글을 훨씬 싸고 빠르게 처리하는 방법.

다 보지 않고 골라서 본다

희소 어텐션(Sparse Attention)이란 트랜스포머가 모든 토큰 쌍을 비교하는 대신, 관련 있을 법한 일부 토큰만 골라 어텐션을 계산하는 방식이다. 기본 어텐션은 토큰이 1,000개면 100만 번, 10만 개면 100억 번 비교한다. 입력이 길어질수록 계산이 제곱으로 불어나니 책 한 권 분량부터는 감당하기 어렵다. 그런데 사람이 소설 300쪽째를 읽을 때 앞의 299쪽 문장을 전부 다시 떠올리지는 않는다. 바로 앞 몇 문장과, 주인공이 처음 등장한 장면 같은 핵심 몇 군데만 참조한다. 희소 어텐션은 모델에게 이런 독서법을 가르친다. 모든 칸이 채워진(dense) 비교표에서 대부분의 칸을 비워두고(sparse) 계산한다는 뜻에서 이름이 붙었다.

규칙으로 고르기: 창문과 이정표

가장 단순한 방법은 미리 정한 규칙이다. 각 토큰이 바로 앞 N개만 보게 하는 슬라이딩 윈도우가 대표적이다. 2020년 나온 Longformer와 BigBird는 여기에 띄엄띄엄 멀리 보는 패턴과, 모든 토큰이 공통으로 참조하는 소수의 전역 토큰을 더해 긴 문서를 처리했다. 창문만으로는 멀리 있는 정보를 못 보니, 이정표 역할을 하는 토큰을 따로 둔 것이다.

이 아이디어는 지금의 오픈 모델에도 흔하다. Google의 Gemma 3는 1,024토큰 창문만 보는 층 다섯 개마다 전체 문맥을 보는 층 하나를 끼워 넣고, OpenAI의 gpt-oss는 128토큰 창문 층과 전체 어텐션 층을 번갈아 쌓는다. 창문 층은 KV 캐시를 창문 크기만큼만 들고 있으면 되니, 대화가 길어져도 메모리가 훨씬 덜 늘어난다. Gemma 3 보고서에 따르면 이렇게 섞어도 언어 모델링 성능 저하는 거의 없었다.

학습으로 고르기: 모델이 직접 찍는다

규칙은 단순하지만, 정말 중요한 토큰이 창문 밖에 있으면 놓친다. 그래서 최근에는 무엇을 볼지 모델이 학습으로 정하게 한다. DeepSeek과 베이징대 연구진이 2025년 2월 발표한 NSA(Native Sparse Attention)는 문맥을 블록 단위로 압축해 대략적인 지도를 만들고, 그중 중요해 보이는 블록만 원본으로 다시 읽고, 가까운 토큰은 창문으로 보는 세 갈래를 합친다. 학습이 끝난 뒤 덧붙이는 게 아니라 처음부터 희소한 상태로 학습시킬 수 있다는 점을 인정받아 ACL 2025 최우수 논문상을 받았다.

같은 해 9월 DeepSeek-V3.2-Exp에 들어간 DSA(DeepSeek Sparse Attention)는 더 직접적이다. 라이트닝 인덱서라는 가벼운 채점기가 지난 토큰 전부에 빠르게 점수를 매기고, 상위 2,048개만 골라 본 어텐션에 넘긴다. 문맥이 10만 토큰이든 50만 토큰이든 꼼꼼히 들여다보는 건 2,048개뿐이라, 무거운 계산이 길이의 제곱이 아니라 길이에 비례하는 수준으로 줄어든다. DeepSeek은 성능을 이전 모델과 비슷하게 유지하면서 API 가격을 절반 이상 내렸다.

개발자 입장에서 달라지는 것

API 사용자에게 희소 어텐션은 주로 가격표와 속도로 체감된다. 긴 코드베이스나 문서 묶음을 매번 통째로 넣는 에이전트를 돌린다면, 희소 어텐션 모델은 같은 작업을 훨씬 싸게 처리한다. 모델을 고를 때 최대 컨텍스트 길이 숫자만 보지 말고, 긴 입력에서의 토큰 단가와 응답 속도를 함께 비교해야 하는 이유다.

직접 서빙한다면 사정이 다르다. 희소 패턴은 전용 GPU 커널이 있어야 제 속도가 난다. vLLM은 DeepSeek-V3.2를 위해 인덱서 전용 캐시와 FlashMLA의 희소 커널을 따로 붙였고, vllm serve deepseek-ai/DeepSeek-V3.2-Exp --tensor-parallel-size 8처럼 GPU 여러 장에 나눠 띄운다. 새로운 희소 구조의 모델이 나오면 추론 엔진 지원이 따라올 때까지 기다려야 하는 경우가 많고, 지원되더라도 특정 GPU 세대에서만 최적화돼 있기도 하다.

버린 토큰에 답이 있었다면

희소 어텐션의 대가는 놓침이다. 중요해 보이지 않아 건너뛴 토큰에 핵심 정보가 있었다면 답이 틀린다. 특히 긴 문서 곳곳에 흩어진 단서를 모두 모아야 하는 질문에서 약점이 드러나기 쉽다. 또 이론상 계산을 줄여도 메모리를 띄엄띄엄 읽으면 GPU가 비효율적으로 움직여 실제 속도는 기대만큼 안 나온다. NSA가 토큰 하나하나가 아니라 블록 단위로 고르는 것도 이 때문이다. 참고로 희소 어텐션은 계산 순서를 재배치하는 Flash Attention, 캐시 자체를 압축하는 MLA와 겨냥하는 지점이 달라서, 최신 모델들은 이 기법들을 한꺼번에 겹쳐 쓴다.
