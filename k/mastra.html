Mastra

TypeScript로 AI 에이전트를 만드는 오픈소스 프레임워크다. Next.js나 Node.js 앱에 에이전트·워크플로우·RAG를 붙이고 싶은데 Python으로 옮기고 싶지 않을 때 쓴다.

한눈에 보기

Mastra는 TypeScript로 AI 에이전트를 만드는 오픈소스 프레임워크다. Gatsby 웹 프레임워크를 만든 팀이 만들었고, 에이전트·워크플로우·RAG·평가(Evals)·MCP를 하나의 스택으로 묶었다. 웹 앱이나 Node.js 서버에 에이전트를 붙여야 하는데 언어를 Python으로 바꾸고 싶지 않을 때 고르면 된다.

프레임워크주 언어이럴 때 쓴다
MastraTypeScript웹 앱·Node 서버에 에이전트 붙이기
LangChainPython 중심기존 Python ML 코드와 연결
CrewAIPython역할을 나눈 여러 에이전트 협업

웹 개발자의 언어로 에이전트를 만든다

에이전트 도구는 오랫동안 Python 생태계에 몰려 있었다. 그런데 웹 개발자 대다수는 TypeScript를 쓰기 때문에, Next.js 앱에 에이전트를 붙이려면 Python 서버를 따로 두거나 언어를 바꿔야 했다. Mastra는 이 간극을 메우려고 나왔고, Y Combinator W25 배치를 거쳐 2026년 1월 v1.0을 냈다.

에이전트와 워크플로우를 나눠 쓴다

필요한 부품이 한곳에 들어 있어서, 일의 성격에 따라 골라 조합하면 된다.

구성 요소하는 일이럴 때 쓴다
에이전트LLM이 도구를 골라 스스로 판단질문마다 검색·API 호출이 달라질 때
워크플로우여러 단계를 그래프로 정의요약→검토→발송처럼 순서가 정해진 일
RAG지식베이스를 붙여 답하게 함사내 문서·매뉴얼 기반 답변
Evals답변 품질 측정프롬프트·모델을 바꾼 뒤 확인

순서가 분명한 일을 에이전트에게 통째로 맡기면 결과가 들쭉날쭉해진다. 정해진 흐름은 워크플로우로 고정하고, 판단이 필요한 단계에만 에이전트를 넣는 편이 안정적이다.

명령 하나로 시작, MCP는 양방향

npm create mastra@latest로 프로젝트를 만들면 에이전트·도구·워크플로우를 정의할 기본 구조가 생긴다. 사용할 모델과 도구를 코드로 지정하고, 로컬 개발 서버를 띄워 에이전트가 도구를 제대로 부르는지 확인한 뒤 앱에 연결하는 순서로 진행한다.

MCP 지원도 양방향으로 내장돼 있다. 외부 MCP 서버의 도구를 내 에이전트에 불러올 수 있고, 반대로 내가 만든 에이전트를 MCP 서버로 열어 Claude Code 같은 클라이언트가 바로 쓰게 할 수도 있다.

Python ML 파이프라인과는 거리가 있다

TypeScript/Node.js에 맞춰져 있어서 Python으로 짠 학습·데이터 파이프라인과 직접 붙이기는 어렵다. 이런 경우엔 Python 쪽을 API로 감싸 호출하거나, 처음부터 Python 프레임워크를 고르는 게 낫다. 또 v1.0이 2026년 1월에 나온 만큼 LangChain에 비해 프로덕션 사례가 적으니, 중요한 서비스라면 작은 기능부터 붙여 보고 넓히는 게 안전하다.
