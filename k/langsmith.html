LangSmith

LangSmith는 LangChain이 만든 LLM 앱 기록·평가·모니터링 플랫폼이다. 이상한 답이 나온 원인을 찾거나, 프롬프트를 고친 뒤 품질이 떨어지지 않았는지 확인할 때 쓴다.

한눈에 보기

LangSmith는 LangChain이 만든 LLM 앱 관찰·평가 플랫폼이다. 앱이 모델을 부를 때마다 입력, 출력, 중간 단계를 기록해 둔다. 이 기록으로 디버깅을 하고, 데이터셋으로 품질을 시험하고, 운영 중인 앱의 상태를 지켜본다. 프롬프트나 에이전트를 감으로 고치지 않고 기록과 비교를 보며 고치고 싶을 때 쓴다.

기능하는 일이럴 때 쓴다
트레이싱단계별 입력·출력·소요 시간 기록이상한 답의 원인 찾기
데이터셋·평가같은 질문 묶음으로 버전끼리 비교프롬프트 수정 전후 회귀 테스트
모니터링운영 중 지연·오류·비용 추적배포 후 품질 감시
프롬프트 관리프롬프트 저장·버전 관리, 플레이그라운드여럿이 함께 프롬프트를 다듬을 때

환경변수만 넣으면 기록이 시작된다

LangSmith 사이트에서 API 키를 발급받은 뒤, 환경변수로 추적을 켜고 키를 넣는다. 예전 이름인 LANGCHAIN_TRACING_V2=true, LANGCHAIN_API_KEY와 새 이름인 LANGSMITH_TRACING=true, LANGSMITH_API_KEY가 함께 쓰인다. LangChain이나 LangGraph 코드라면 코드를 고치지 않아도 모든 호출이 대시보드에 쌓인다.

LangChain을 쓰지 않아도 된다. Python SDK의 @traceable 데코레이터를 함수에 붙이거나 OpenAI 클라이언트를 래퍼로 감싸면, 직접 짠 코드도 같은 방식으로 기록된다.

운영에서 실패한 사례를 테스트로 바꾼다

평가 기능은 아래 순서로 쓸 때 효과가 가장 크다. 실제 사용자가 겪은 실패가 쌓일수록 테스트 세트가 쓸모 있어진다.

순서할 일방법
1잘못된 답 찾기운영 트레이스를 걸러서 보기
2데이터셋에 추가입력과 기대하는 답을 같이 저장
3채점 기준 정하기정답 비교, 규칙 검사, LLM 채점
4바꿀 때마다 실험이전 버전과 점수 비교

LLM에게 채점을 맡기면 편하지만 채점이 틀릴 때도 있다. 중요한 기준은 사람이 일부 결과를 직접 보고 채점과 맞는지 확인하는 게 좋다.

프레임워크가 아니라 관찰 도구다

도구성격고를 때
LangSmithLangChain 공식 관리형 서비스LangChain·LangGraph를 쓰면 연동이 가장 쉽다
Langfuse오픈소스 관찰 도구내 서버에 직접 설치하고 싶을 때
LangChain·LangGraph앱을 만드는 프레임워크지켜보는 도구가 아니라 만드는 도구다

기록이 외부로 나간다는 점을 확인한다

트레이스에는 사용자 입력과 모델 출력이 그대로 담긴다. 개인정보나 사내 데이터를 다루는 앱이라면 기록을 외부 서비스로 보내도 되는지 먼저 확인한다. 필요하면 민감한 값을 가리는 설정이나 기업용 자체 설치 방식을 검토한다. 호출이 많으면 기록이 늘어나는 만큼 비용도 커지므로, 운영 환경에서는 일부만 골라 기록하는 것도 고려한다.
