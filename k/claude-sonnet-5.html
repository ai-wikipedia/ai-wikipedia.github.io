클로드 소네트 5

Claude Sonnet 5 (Anthropic)

Anthropic이 2026년 6월 내놓은 중간 등급 모델로, Opus에 가까운 에이전트 작업을 Sonnet 가격에 처리한다. 2026년 9월 후속작 Sonnet 5.5가 나와 지금은 레거시 모델이다.

한눈에 보기

Claude Sonnet 5는 Opus와 Haiku 사이에 있는 중간 등급 모델이다. 계획을 세우고 도구를 쓰며 긴 작업을 스스로 이어가는 능력이 당시 최상위 Opus 4.8에 가까운데, 값은 Opus의 절반 이하다. 지금은 후속작 Sonnet 5.5가 같은 가격으로 나와 레거시 모델이 됐다.

모델위치이럴 때 쓴다
Opus 4.8최상위기획, 까다로운 설계 판단, 보안 작업
Sonnet 5중간에이전트의 일꾼, 일상 코딩
Haiku경량빠르고 싼 작업

이전 Sonnet보다 오히려 싸다

직전 Sonnet 4.6보다 가격이 내려갔다. 반복되는 시스템 프롬프트는 캐시하면 훨씬 싸고, 급하지 않은 대량 작업은 배치 API로 돌리면 절반 가격이다.

Opus 4.8$25
Sonnet 4.6$15
Sonnet 5$10

출력 100만 토큰당 가격. Sonnet 5 입력은 $2, 캐시 읽기는 $0.2다. 문맥은 100만 토큰, 최대 출력은 12만 8천 토큰이다.

다만 토크나이저가 바뀌어 같은 입력이 4.6보다 최대 1.35배 많은 토큰으로 계산될 수 있다. 실제 청구액은 자기 프롬프트로 직접 재 봐야 한다.

Opus가 기획하고 Sonnet 5가 일한다

API 모델 ID는 claude-sonnet-5이고, Amazon Bedrock에서는 anthropic.claude-sonnet-5로 부른다. Claude Code 같은 에이전트에서는 기획은 Opus에 맡기고, 파일 탐색이나 테스트 작성처럼 양이 많은 하위 작업은 Sonnet 5 서브에이전트에 나눠 주면 품질은 유지하면서 비용을 크게 줄일 수 있다.

얼마나 깊이 생각할지는 모델이 문제 난도에 맞춰 스스로 정하고, 개발자는 effort로 그 깊이를 조절한다. 기본값은 high다. temperature나 top_p를 기본값이 아닌 값으로 보내면 오류가 나니 주의한다.

작업effort
일상적인 기능 구현medium
버그 원인 끝까지 파고들기high 이상
최대치 max비용 대비 효율이 가장 나쁨

꼼꼼하지만 느리고 과하게 만든다

테스트를 먼저 쓰고 직접 돌려본 뒤에야 완료를 보고하며, 긴 작업도 끈질기게 붙잡고 해낸다. 대신 4.6보다 느리고 토큰을 더 쓰며, 작은 요청에도 보조 함수와 긴 테스트를 덧붙이는 경향이 있다. 써 본 사람들은 중간 정도 effort에서 이점 대부분을 얻는다고 평가한다.

프롬프트 인젝션에 더 잘 버티고 환각과 아첨하는 답변도 줄어, 외부 웹페이지를 읽는 에이전트에 붙이기 좋다. 반면 사이버 안전장치가 기본으로 켜져 있어 정당한 보안 작업도 거절될 수 있다. 그런 작업에는 Opus 4.8이 권장된다.

새로 시작한다면 5.5와 비교하자

Sonnet 5는 2027년 6월 30일 전에는 종료되지 않으므로 기존 시스템은 그대로 돌려도 된다. 새로 만든다면 같은 가격인 Sonnet 5.5와 함께 비교해 보고 고르는 게 맞다.
