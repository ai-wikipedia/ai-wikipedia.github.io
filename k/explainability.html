설명가능성

Explainability

설명가능성은 AI가 왜 그런 결정을 내렸는지 사람이 이해할 수 있게 보여주는 능력이다. 대출 심사, 의료, 법률처럼 판단의 근거를 대야 하는 곳에서 신뢰를 얻고 규제를 지키려고 쓴다.

한눈에 보기

설명가능성은 AI가 왜 그런 답을 냈는지 사람이 알아볼 수 있게 보여주는 능력이다. 정확도가 높다는 것만으로는 믿고 맡기기 어려운 곳에서 필요하다. 대출 심사, 의료 판단, 채용처럼 결과에 책임이 따르는 일이 대표적이다. 설명하는 방식은 무엇을 알고 싶은지에 따라 달라진다.

알고 싶은 것설명 방식예
어떤 입력이 결과를 좌우했나특성 중요도대출 거절에 소득이 가장 크게 작용
이미지의 어디를 봤나히트맵X선 사진에서 특정 부위 강조
무엇을 근거로 답했나출처 표시챗봇 답변 옆 참고 문서 링크
무엇이 바뀌면 결과가 달라지나반사실 설명소득이 조금 더 높았다면 승인

블랙박스라서 설명을 따로 만들어야 한다

결정트리나 선형회귀 같은 단순한 모델은 구조만 봐도 판단 이유가 보인다. 하지만 파라미터가 수없이 많은 딥러닝은 내부를 들여다봐도 이유를 읽어낼 수 없다. 이것을 블랙박스 문제라고 부르고, 그래서 모델 바깥에서 결과를 해석하는 도구가 따로 발전했다.

표 데이터는 SHAP, LLM 앱은 출처 표시

표 형태 데이터로 만든 예측 모델에는 파이썬 shap 라이브러리를 많이 쓴다. 학습된 모델과 데이터를 넣으면 예측 하나마다 각 특성이 결과를 얼마나 올리고 내렸는지 보여준다. 데이터 전체에서 어떤 특성이 중요했는지도 그래프로 그려준다. LIME도 비슷한 도구인데, 예측 하나 주변을 단순한 모델로 흉내 내서 설명한다.

LLM 앱에서는 RAG로 참고한 문서를 답과 함께 보여주는 방법이 가장 쉽다. 사용자가 원문을 눌러 직접 확인할 수 있고, 틀린 답이 어디서 나왔는지 추적하기도 쉬워진다.

상황추천 방법
신용평가, 이탈 예측 같은 표 데이터 모델SHAP 값
이미지 분류히트맵(Grad-CAM 등)
사내 문서 질의응답 챗봇RAG 출처 표시
규제가 엄격해 설명이 최우선처음부터 해석 가능한 단순 모델

그럴듯한 설명이 진짜 이유는 아닐 수 있다

SHAP 값이나 히트맵은 모델의 동작을 근사해서 해석한 결과이고, 모델 내부를 그대로 옮긴 것이 아니다. LLM이 "이렇게 생각했다"며 보여주는 추론 과정도 실제 계산 과정과 다를 수 있다. 출처를 붙여도 모델이 내용을 잘못 요약할 수 있다. 그래서 중요한 판단은 원문과 데이터로 직접 확인해야 한다.
