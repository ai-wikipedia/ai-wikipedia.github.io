커서

Cursor

커서(Cursor)는 VS Code를 바탕으로 만든 AI 코드 편집기다. 프로젝트 전체 맥락을 아는 AI와 함께 편집기 안에서 코드를 쓰고 고치고 싶을 때 쓴다.

한눈에 보기

커서는 VS Code를 포크해 만든 AI 코드 편집기다. 프로젝트 전체를 색인해 두기 때문에 AI가 내 코드 구조를 이해한 상태로 자동완성부터 여러 파일 수정까지 도와준다. 작업 크기에 따라 기능 세 가지를 골라 쓰면 된다.

기능하는 일이럴 때 쓴다
Tab다음에 쓸 코드를 예측해 자동완성타이핑 중 반복되는 패턴
인라인 편집 (Cmd+K)선택한 부분만 지시대로 수정함수 하나, 몇 줄 고치기
Agent대화로 여러 파일을 읽고 고치고 명령도 실행기능 추가, 큰 리팩토링

VS Code 그대로, 모델은 골라서

VS Code 기반이라 확장·단축키·설정을 처음 실행할 때 그대로 가져올 수 있다. 화면 구성도 거의 같아서 익히는 데 시간이 적게 든다. AI 모델은 Claude, GPT, Gemini 계열과 커서 자체 모델 가운데 작업에 맞게 고른다.

작은 수정은 Cmd+K, 큰 작업은 Agent

한 함수의 버그 수정처럼 범위가 좁으면 코드를 선택하고 Cmd+K(Windows는 Ctrl+K)로 지시하는 게 빠르다. 여러 파일에 걸친 일은 Agent에 맡긴다. 예를 들어 "기존 /users 패턴과 똑같이 /products CRUD 엔드포인트를 추가해줘"라고 하면 라우터·컨트롤러·서비스 파일을 한 번에 만든다. 예전 Composer 기능은 지금 이 Agent 모드로 합쳐졌다.

질문할 때 @로 참고할 파일·폴더·문서를 직접 지정하면 AI가 엉뚱한 코드를 보고 답하는 일이 줄어든다. 바뀐 내용은 변경 비교(diff)로 보여주므로 확인한 뒤 수락하면 된다.

규칙 파일로 매번 같은 말 안 하기

코딩 스타일, 폴더 구조, 쓰면 안 되는 라이브러리 같은 프로젝트 규칙을 파일로 적어 두면 AI가 매번 따른다. 예전에는 루트의 .cursorrules 파일을 썼고, 지금은 .cursor/rules 폴더에 규칙 파일을 나눠 두는 방식을 권장한다. 팀이 함께 쓰면 누가 요청해도 결과물 스타일이 맞춰진다.

비슷한 도구와의 차이, 그리고 주의할 점

도구형태잘 맞는 경우
커서AI가 통합된 별도 편집기편집기 안에서 AI와 계속 주고받으며 작업
VS Code + Copilot기존 편집기에 붙는 확장지금 쓰는 환경을 바꾸고 싶지 않을 때
Claude Code터미널 중심 에이전트명령줄에서 길게 맡기는 자율 작업

코드가 AI 모델 서버로 전송되므로 회사 코드라면 프라이버시 모드 설정과 사내 정책을 먼저 확인한다. 무료 플랜은 사용량 제한이 있어 많이 쓰려면 유료 구독이 필요하다. AI가 만든 코드는 diff 검토와 테스트를 거친 뒤 반영하는 게 안전하다.
