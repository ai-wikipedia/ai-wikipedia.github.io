백그라운드 에이전트

Background Agent

클라우드의 격리된 환경에서 혼자 돌아가는 코딩 에이전트다. 작업을 맡겨 두고 다른 일을 하다가 끝나면 PR을 리뷰하는 방식이라, 범위가 분명한 작업을 여러 개 동시에 처리할 때 쓴다.

한눈에 보기

백그라운드 에이전트는 내 컴퓨터가 아니라 클라우드의 격리된 환경에서 비동기로 일하는 코딩 에이전트다. 작업을 맡기면 에이전트가 혼자 코드를 읽고 고치고 테스트를 돌린 뒤 PR까지 만든다. 그동안 나는 다른 일을 하거나 노트북을 덮어도 된다.

구분일반 에이전트백그라운드 에이전트
실행 위치내 터미널·IDE클라우드 격리 환경
나는옆에서 지켜보며 기다림다른 일을 함
결과 확인실시간으로 바로끝난 뒤 PR로
동시 작업보통 하나여러 개 병렬

맡기고, 다른 일 하고, PR로 받는다

쓰는 순서는 단순하다. 할 일을 구체적으로 적어 에이전트를 띄우면, 에이전트가 레포를 클론해 별도 브랜치에서 작업한다. 끝나면 PR이 열려 있고, 나는 일반 코드 리뷰처럼 확인해서 합치거나 수정을 다시 요청한다.

작업마다 환경이 따로 떨어져 있어서 서로 충돌하지 않는다. 그래서 버그 수정, 테스트 추가, 문서 정리를 에이전트 여러 개에 동시에 나눠 맡길 수 있다.

도구마다 방식이 조금 다르다

Cursor에서는 에디터에서 에이전트를 클라우드로 보내면 원격 VM에서 작업하고 PR을 열어 둔다. Claude Code에서는 서브에이전트나 작업을 백그라운드로 돌려 두고 메인 대화를 이어 갈 수 있다. 여기에 Git Worktree를 쓰면 에이전트마다 코드의 독립된 복사본에서 일하게 돼 파일이 엉키지 않는다.

범위가 분명한 일에 맡긴다

목표와 완료 조건이 분명하고 테스트로 확인할 수 있는 일이 잘 맞는다. 방향을 같이 잡아 가야 하는 일은 옆에서 대화하며 하는 편이 낫다.

상황추천
이슈 하나 고치기, 테스트 추가백그라운드
여러 작은 작업을 한꺼번에백그라운드
설계를 함께 고민하는 작업로컬에서 대화하며
UI를 눈으로 보며 다듬기로컬에서 대화하며

중간에 못 잡으니 작게 쪼갠다

결과를 나중에 보는 방식이라, 에이전트가 엉뚱한 방향으로 가도 중간에 잡기 어렵다. 작업을 작고 명확하게 쪼개고, 완료 조건을 미리 적어 두는 게 가장 중요하다.

클라우드 환경에서 의존성 설치와 테스트가 제대로 돌아가도록 미리 설정해 둬야 결과를 믿을 수 있다. 또 에이전트가 레포와 비밀값에 접근하므로 권한은 필요한 만큼만 주고, 병렬로 많이 돌릴수록 사용량 비용도 늘어난다는 점을 기억해야 한다.
