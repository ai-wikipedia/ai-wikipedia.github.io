Copilot SDK

GitHub Copilot의 에이전트 기능을 내 프로그램 안에서 코드로 불러 쓰게 해 주는 GitHub 공식 SDK다. 원래 지원 IDE 안에서만 쓰던 Copilot을 사내 CLI, 자체 에디터, 웹 앱에 붙여 코드 질문이나 작업 실행을 맡기고 싶을 때 쓴다.

방법무엇을 하나이럴 때 쓴다
IDE용 Copilot에디터 안에서 완성·채팅내가 직접 코딩할 때
Copilot SDKCopilot 에이전트를 내 코드에서 호출내 도구에 Copilot을 넣을 때
LLM API 직접 호출모델만 빌려 쓰고 나머지는 직접 구현도구·흐름을 모두 직접 짜고 싶을 때

에이전트를 직접 만들지 않아도 된다

LLM API만으로 코딩 에이전트를 만들려면 계획 세우기, 파일 읽기·수정, 도구 호출, 대화 기록 관리를 모두 직접 구현해야 한다. SDK는 Copilot이 이미 쓰는 이 실행 엔진을 그대로 빌려준다. 개발자는 무엇을 시킬지와 어떤 도구를 줄지만 정하면 된다.

쓰는 순서: 설치, 세션, 도구

먼저 Copilot CLI를 설치하고 GitHub 계정으로 로그인해 둔다. SDK는 이 CLI를 뒤에서 실행해 연결하는 방식이다. 그다음 언어에 맞는 SDK 패키지를 설치한다. Node.js, Python, Go, .NET용이 공식 저장소에 있다.

코드에서는 클라이언트를 만들고 세션을 연 뒤 프롬프트를 보내고, 답을 스트리밍으로 받는다. 사내 API 조회처럼 Copilot이 쓸 수 있어야 하는 기능은 직접 도구로 등록하거나 MCP 서버로 연결한다.

하고 싶은 일SDK로 하는 방법
코드 리뷰 도구에 설명 붙이기변경 내용을 프롬프트로 보내고 답을 표시
내부 문서에 코드 질의응답문서 검색을 도구로 등록
사내 CLI에 자동 수정 기능세션에 작업을 맡기고 결과를 확인

Copilot Studio와는 다른 제품이다

이름이 비슷한 Microsoft Copilot Studio는 코드를 거의 쓰지 않고 업무용 챗봇·에이전트를 만드는 도구다. Copilot SDK는 개발자가 코드로 GitHub Copilot 에이전트를 붙이는 라이브러리라서 대상과 쓰임이 다르다.

구독과 공개 범위를 먼저 확인한다

SDK를 써도 Copilot 구독이 필요하고, 사용량은 구독 한도에서 차감된다. 아직 프리뷰 단계라 인터페이스가 바뀔 수 있으므로, 중요한 서비스에 넣기 전에 공식 저장소에서 최신 상태를 확인하는 게 좋다. 에이전트가 파일을 고치거나 명령을 실행할 수 있으니 허용할 도구와 권한 범위도 좁게 정해 둔다.

개발팀이 이미 쓰는 도구에 Copilot을 붙인다

가장 흔한 쓰임은 팀이 매일 쓰는 사내 도구 안에 Copilot 에이전트를 넣는 것이다. 에이전트 실행 흐름은 SDK에 맡기고, 개발자는 프롬프트와 허용할 도구만 정한다.

어디서어떻게 쓰나
사내 CLI·스크립트반복되는 코드 수정을 세션에 맡기고 사람이 결과만 검토
코드 리뷰 흐름변경 내용을 보내 설명이나 리뷰 코멘트 초안을 받아 표시
자체 에디터·웹 앱채팅 창을 붙여 코드 질문에 스트리밍으로 답
사내 개발 문서 검색문서 검색을 도구나 MCP 서버로 연결해 코드 질의응답
