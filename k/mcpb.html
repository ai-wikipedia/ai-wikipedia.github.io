MCP Bundle (MCPB)

MCPB(MCP Bundle)는 로컬 MCP 서버와 설명서 manifest.json을 ZIP 파일 하나(.mcpb)로 묶은 배포 포맷이다. 터미널이나 설정 파일을 몰라도 MCP 서버를 설치하게 하고 싶을 때 쓴다.

한눈에 보기

MCPB는 로컬 MCP 서버를 파일 하나로 포장한 설치 패키지다. 확장자는 .mcpb이고 속은 ZIP 파일이다. 크롬 확장이나 VS Code 확장처럼, 이 파일을 Claude 데스크톱 앱 같은 AI 앱에 끌어다 놓으면 그 앱이 새 도구를 쓸 수 있게 된다.

DXT의 새 이름, 이제 MCP 공식 포맷

처음엔 Anthropic이 Claude 데스크톱용 Desktop Extensions(DXT)로 내놓았고, 이후 이름만 MCPB로 바뀌었다. 기존 .dxt도 계속 동작하지만 새로 만든다면 .mcpb를 쓰면 된다.

2025년 11월부터는 Model Context Protocol 프로젝트의 공식 포맷이다. 한 번 만든 번들이 Claude 데스크톱, Claude Code, Windows의 MCP 지원 등 사양을 따르는 클라이언트 어디서나 동작하는 것을 목표로 한다.

폴더 하나에 모으고 명령 두 번

이미 돌아가는 로컬 MCP 서버가 있다면 필요한 파일을 한 폴더에 모은 뒤, mcpb init으로 manifest.json을 만들고 mcpb pack으로 묶으면 끝이다. .NET 개발자는 dotnet tool install -g mcpb.cli로 같은 흐름을 쓸 수 있다. Claude에게 MCPB 사양 문서와 예제를 읽힌 뒤 매니페스트와 서버를 만들게 하는 방법도 안내돼 있다.

상황이렇게 한다
Python 서버 배포소스와 의존성 선언만 넣고, UV 런타임(MCPB 0.4)으로 설치 때 환경 준비. 첫 설치엔 인터넷 필요
Windows에 등록manifest.json의 _meta 아래 com.microsoft.windows에 전용 속성 작성
무거운 도구는 클라우드에번들엔 가벼운 프록시만 넣고 클라우드 엔드포인트에 연결

설치가 쉬워질 뿐, 안전해지지는 않는다

ZIP 파일이라 ZIP의 오래된 위험도 그대로 가진다. 경로에 ../를 넣어 폴더 밖에 파일을 쓰는 Zip Slip, 기존 파일 덮어쓰기, 심볼릭 링크 공격이 대표적이다. 클라이언트에서 압축 해제를 직접 구현한다면 경로 검증을 꼭 해야 한다.

MCPB는 포장 형식일 뿐이라 인증, 권한 관리, 감사 기능을 더해 주지 않는다. 설치가 쉬운 만큼 출처를 모르는 번들도 쉽게 들어오므로, 믿을 수 있는 배포자의 번들만 설치하고 서버가 닿는 시스템의 권한은 따로 설계해야 한다.
