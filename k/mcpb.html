MCP Bundle (MCPB)

MCPB(MCP Bundle)는 로컬 MCP 서버와 그 설명서인 manifest.json을 ZIP 파일 하나(.mcpb)에 묶은 배포 포맷이다. 사용자가 터미널이나 설정 파일 없이 클릭 한 번으로 MCP 서버를 설치할 수 있게 해 준다.

설정 파일 앞에서 멈추던 사용자를 위한 포장지

MCPB란 로컬에서 돌아가는 MCP 서버를 파일 하나로 포장해 배포하는 형식이다. 확장자는 .mcpb이고, 열어 보면 그냥 ZIP 압축 파일이다. 안에는 서버 코드와 필요한 파일 전체, 그리고 이 서버가 무엇이며 어떤 기능을 제공하는지 적어 둔 manifest.json이 들어 있다. 크롬 확장 프로그램(.crx)이나 VS Code 확장(.vsix)을 떠올리면 된다. 확장 파일을 받아 설치하면 브라우저나 에디터에 기능이 붙듯, .mcpb 파일을 AI 앱에 넣으면 그 앱이 새 도구를 쓸 수 있게 된다.

이런 포맷이 나온 이유는 단순하다. MCP 서버는 쓸모가 많지만, 예전에는 설치하려면 Node.js나 Python 환경을 직접 준비하고, 의존성을 깔고, 클라이언트 설정 파일을 손으로 고쳐야 했다. 개발자에겐 익숙한 일이어도 비개발자에겐 사실상 진입 장벽이었다. MCPB는 의존성을 포함한 서버 전체를 하나의 설치 패키지로 묶어서, Claude 데스크톱 앱 같은 클라이언트에 파일을 끌어다 놓는 것만으로 설치가 끝나게 만들었다.

DXT에서 MCP 공식 포맷이 되기까지

처음에는 Anthropic이 Claude 데스크톱용 Desktop Extensions, 줄여서 DXT라는 이름으로 내놓았다. 이후 확장자가 .dxt에서 .mcpb로, npm 패키지도 @anthropic-ai/dxt에서 @anthropic-ai/mcpb로 이름이 바뀌었다. 기능은 그대로이고 이름만 바뀐 것이라 기존 .dxt 확장도 계속 동작하지만, 새로 만드는 확장은 .mcpb를 쓰도록 권장된다. 2025년 11월에는 이 포맷이 Model Context Protocol 프로젝트로 넘어가 공식 일부가 됐다. 그 결과 하나의 번들이 Claude 데스크톱 앱, Claude Code, Windows의 MCP 지원 등 사양을 구현한 클라이언트라면 어디서든 동작하는 것을 목표로 하게 됐다. 개발자는 한 번 포장해서 생태계 전체에 배포할 수 있고, mcpb CLI와 관련 라이브러리도 커뮤니티에 열려 있어 클라이언트 개발자가 번들 로딩과 검증 코드를 표준화된 방식으로 가져다 쓸 수 있다.

번들을 직접 만들어 배포하는 장면

만드는 과정은 생각보다 짧다. 이미 동작하는 로컬 MCP 서버가 있다면 필요한 파일을 한 폴더에 모으고, mcpb init으로 manifest.json을 만든 뒤 mcpb pack으로 압축하면 .mcpb 파일이 나온다. .NET 개발자라면 dotnet tool install -g mcpb.cli로 .NET용 CLI를 설치해 같은 흐름으로 빌드할 수 있다. Windows의 MCP 지원과 온디바이스 에이전트 레지스트리(ODR)에 서버를 등록하려면 매니페스트의 _meta 섹션 아래 com.microsoft.windows 객체에 Windows 전용 속성을 적어야 하고, 서버 쪽 값이 바뀌면 이 설정도 맞춰 고쳐야 기본 모드로 실행된다. 번들은 기존 Windows 앱 안에 포함시켜도 되고 단독 파일로 나눠 줘도 된다.

Python 서버도 다루기 쉬워졌다. 예를 들어 과학 도구 1,000여 개를 제공하는 ToolUniverse는 Python 소스와 의존성 선언만 번들에 넣고, MCPB 0.4의 UV 런타임을 지원하는 클라이언트가 설치 시점에 플랫폼에 맞는 Python 환경을 준비하게 한다. 사용자는 가상환경을 몰라도 되지만, 첫 설치 때는 의존성을 받아야 하므로 인터넷 연결이 필요하다. 또 번들 안에 꼭 무거운 서버가 들어갈 필요는 없어서, 로컬에서는 가벼운 프록시만 돌고 실제 도구는 클라우드 쪽 엔드포인트에 연결하는 형태의 번들도 배포되고 있다. Anthropic은 Claude에게 MCPB 사양 문서와 예제를 읽히고 매니페스트와 서버 구현을 생성하게 하는 프롬프트까지 제공해서, 에이전트에게 번들 제작을 맡기는 방식도 안내한다.

ZIP이라서 생기는 위험과 포맷이 해주지 않는 것

MCPB는 결국 ZIP 파일이기 때문에 ZIP의 오래된 보안 문제를 그대로 물려받는다. 악의적으로 만든 번들이 ../ 같은 경로를 이용해 압축 해제 대상 폴더 밖에 파일을 쓰는 Zip Slip, 기존 파일을 경고 없이 덮어쓰기, 심볼릭 링크를 이용한 공격이 대표적이다. 실제로 공식 도구의 압축 해제 함수에서 Zip Slip을 막는 수정이 v0.2.6에 들어갔다. 자체 클라이언트에서 번들 압축 해제를 직접 구현한다면 이런 경로 검증을 반드시 해야 한다.

또 하나 기억할 점은 MCPB가 포장과 배포를 위한 형식일 뿐이라는 것이다. 설치를 쉽게 해 줄 뿐, 안에 든 MCP 서버에 인증, 권한 관리, 거버넌스, 감사 기능을 더해 주지 않는다. 번들을 풀어 모든 파일을 들여다볼 수 있다는 점에서 검토는 가능하지만, 설치가 쉬워진 만큼 출처를 모르는 번들도 쉽게 들어온다. 번들로 묶었다고 서버가 안전해지는 것은 아니므로, 신뢰할 수 있는 배포자의 번들만 설치하고 그 서버가 접근하는 시스템의 권한은 따로 설계해야 한다.
