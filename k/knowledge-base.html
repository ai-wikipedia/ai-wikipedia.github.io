지식 베이스

Knowledge Base

지식 베이스는 회사 문서·매뉴얼·FAQ처럼 AI가 답할 때 찾아볼 자료를 모아 검색하기 쉽게 정리한 저장소다. AI가 최신 정보나 내부 정보를 근거로 답해야 할 때 쓰며, RAG의 핵심 재료가 된다.

한눈에 보기

지식 베이스는 AI가 답하기 전에 찾아볼 수 있도록 회사 문서, 제품 매뉴얼, FAQ 같은 자료를 모아 둔 저장소다. LLM은 학습 시점 이후의 정보나 조직 내부 정보를 모른다. 이 빈틈을 채우려고 지식 베이스를 쓰고, 질문이 오면 관련 문서를 먼저 찾아 근거로 붙여 답하는 RAG의 재료가 된다.

방법이럴 때 쓴다약점
지식 베이스(RAG)자주 바뀌는 문서, 출처가 필요한 답검색이 빗나가면 답도 틀린다
파인튜닝말투·형식·작업 방식을 익힐 때새 정보 반영이 느리고 비용이 크다
프롬프트에 직접 붙이기문서가 몇 개뿐일 때문서가 많으면 길이 한도와 비용 문제

문서를 잘게 나눠 뜻으로 찾게 한다

일반 문서 저장소는 키워드가 맞아야 찾지만, AI용 지식 베이스는 문서를 임베딩 벡터로 바꿔 저장하므로 뜻이 비슷한 내용도 찾아낸다. "환불 규정"을 물어도 "반품 정책" 문서가 나오는 식이다. 만드는 순서는 대체로 같다.

단계하는 일
1. 수집위키, Notion, Confluence, PDF, 코드 저장소를 모은다
2. 분할(청킹)긴 문서를 문단 크기 조각으로 나눈다
3. 임베딩·저장조각을 벡터로 바꿔 벡터 DB에 넣는다
4. 검색·답변질문과 가까운 조각을 찾아 LLM에 넘긴다

실제 서비스에서는 의미 검색에 키워드 검색을 섞어 정확도를 높이는 경우가 많다.

규모에 맞춰 만드는 방식을 고른다

혼자 일할 때 문서 몇십 개를 참고시키는 정도라면 채팅 앱의 프로젝트 기능에 파일을 올리는 것으로 충분하다. 자사 챗봇이나 앱에 붙일 때는 관리형 서비스나 직접 구축을 검토한다.

방식예맞는 경우
채팅 앱에 파일 올리기ChatGPT·Claude 프로젝트개인, 소규모 팀
업무 도구에 들어 있는 AINotion AI, Confluence AI문서가 이미 그 도구에 모여 있을 때
관리형 서비스Amazon Bedrock Knowledge Bases자사 앱에 빠르게 붙일 때
직접 구축임베딩 API + 벡터 DB청킹·검색을 세밀하게 조정할 때

품질은 문서 관리가 좌우한다

지식 베이스에 오래된 문서가 남아 있으면 AI는 틀린 내용을 자신 있게 답한다. 문서가 바뀌면 임베딩을 자동으로 다시 만드는 동기화 파이프라인이 꼭 있어야 하고, 폐기된 문서는 지워야 한다.

권한도 조심해야 한다. 인사·급여 문서까지 한곳에 넣으면 누구나 AI를 거쳐 그 내용을 볼 수 있게 되므로, 사용자 권한에 맞춰 검색 대상을 거르는 설정이 필요하다. 답변에 출처 문서를 함께 보여주면 사용자가 내용을 직접 확인할 수 있어 믿고 쓰기 쉬워진다.
