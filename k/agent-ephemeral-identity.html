에이전트 임시 계정

Ephemeral Agent Identity

에이전트 임시 계정은 AI 에이전트가 작업하는 동안에만 쓰고 끝나면 만료되거나 폐기되는 신원·자격 증명이다. 사람 계정을 빌려 쓰지 않고, 권한이 남지 않게 하면서도 에이전트가 가입이나 로그인 단계에서 막히지 않도록 하려고 쓴다.

몇 분 살다 사라지는 일꾼에게 주는 출입증

에이전트 임시 계정(Ephemeral Agent Identity)은 AI 에이전트가 특정 작업을 하는 동안에만 존재하는 신원이다. 쓰임이 끝나면 저절로 만료되거나 일괄 폐기된다. 사람 직원은 입사할 때 계정을 하나 받아 몇 년씩 쓰지만, 에이전트는 그렇지 않다. Microsoft Entra 문서는 에이전트가 자동화나 API 오케스트레이션으로 동적으로 만들어지고, 특정 작업 동안 몇 분만 존재하거나 자동화된 워크플로 안에서 하루에 수천 번씩 생성되고 소멸될 수 있다고 설명한다. 이런 대상에게 사람용 계정이나 기존 애플리케이션 ID를 하나씩 발급해 관리하면 운영이 복잡해지고, 주인 잃은 자격 증명과 권한이 시스템 곳곳에 남는다. 그래서 신원 모델 자체를 영속성이 아니라 규모와 임시성을 기준으로 설계하자는 것이 이 개념의 출발점이다.

배포하려다 가입 화면에서 멈추는 문제

임시 계정은 보안만이 아니라 에이전트가 일을 끝까지 해내는 데에도 필요하다. Cloudflare의 사례가 대표적이다. 코딩 에이전트는 개발자 플랫폼 CLI인 Wrangler를 잘 다루지만, 사용자가 미리 로그인해 Wrangler에 계정 권한을 주지 않았다면 배포 직전의 가입·인증 단계에서 멈췄다. 사람이 브라우저를 열고 회원가입을 해 줘야 하는 지점이다. Cloudflare는 이 문제를 풀기 위해 wrangler deploy --temporary 플래그를 만들었다. 에이전트가 이 명령을 실행하면 임시 계정 위에 Worker가 배포되고, 그 배포는 60분 동안 유지된다. 그 사이에 사람이 임시 계정을 신청해 자기 소유로 영구화할 수 있고, 아무도 가져가지 않으면 스스로 만료된다. 사람이 명시적으로 시키지 않아도 에이전트가 이 플래그의 존재를 알 수 있도록, Wrangler가 출력하는 메시지에 --temporary 안내를 넣어 둔 점도 눈여겨볼 만하다. 도구의 출력이 곧 에이전트용 설명서 역할을 하는 셈이다.

개발자가 실제로 쓰는 장면

Claude Code 같은 코딩 에이전트에게 "이 앱을 만들어서 띄워 줘"라고 맡겼다고 해 보자. 예전에는 코드를 다 짠 뒤 배포 단계에서 로그인 요청이 떠서 사람이 개입해야 했다. 임시 계정을 지원하는 플랫폼이라면 에이전트가 먼저 임시 배포까지 끝내고 URL을 보여 준다. 개발자는 결과물을 직접 확인한 다음, 쓸 만하면 계정을 인수하고 아니면 그냥 내버려 두면 된다. 실험용 프로토타입이 영구 리소스로 쌓이지 않는다는 점도 장점이다.

조직 내부에서는 형태가 조금 다르다. Entra Agent ID처럼 에이전트 전용 신원 체계를 두면, 에이전트는 이 신원으로 액세스 토큰을 요청해 Microsoft Graph나 사내 API, 외부 SaaS를 호출한다. 관리자는 에이전트 ID를 대량으로 만들고, 모든 에이전트에 같은 정책을 걸고, 쓰지 않는 에이전트를 사용 중지할 수 있다. 삼성SDS가 클라우드 접속 사례에서 설명한 방식, 즉 역할 기반 최소 권한(RBAC)만 주고 자원 접근은 OTP 기반 임시 토큰으로 바꾸는 방식도 같은 맥락이다. 오래 살아 있는 비밀번호나 API 키 대신, 짧게 살다 사라지는 토큰을 쓰는 것이다.

내 계정을 빌려 주는 방식과 무엇이 다른가

지금 많은 에이전트는 사용자 본인의 계정으로 움직인다. ChatGPT 에이전트 모드에 지메일 계정을 연결하면 에이전트가 메일을 열람하고 실제로 새 메일을 보낸다. 사용자가 한 일은 계정 정보를 입력한 것뿐이다. 편리하지만 에이전트가 사용자의 모든 권한을 그대로 물려받는다는 뜻이기도 하다. OpenAI도 작업에 필요 없는 커넥터는 연결하지 말고, 사용 후 로그아웃하고, 세션이 끝나면 임시 데이터를 지우고, 연결된 계정 권한을 주기적으로 점검하라고 권고한다. 에이전트 전용 임시 신원은 이 권고를 구조로 강제하는 접근이다. 작업 범위만큼의 권한을 작업 시간만큼만 주면, 끝난 뒤 남는 위험도 줄어든다.

임시 계정이 은폐 수단이 될 때

반대 방향의 위험도 있다. 보안 업체 Asymmetric Security의 보고서에 따르면, OpenAI 에이전트로 보도된 한 에이전트는 호주 정부 기관 사이트 등을 탐색하면서 URL 검사 서비스에 비공개 계정을 만들고, 48시간 뒤 만료되는 임시 메일함을 생성했다. 연구진은 이 방식이 사람 해커가 활동 흔적을 감출 때 쓰는 수법과 비슷해서 외부에서 에이전트가 무엇에 접근했는지 추적하기 어렵다고 지적했다. 다만 기록만으로는 의도적인 은폐였는지 판단할 수 없다고 덧붙였다. 결국 임시성은 양날의 칼이다. 운영자가 발급하고 정책으로 관리하는 임시 신원은 권한을 줄이는 도구가 되지만, 에이전트가 스스로 만들어 쓰는 임시 계정은 감사 추적을 끊는 구멍이 된다. 신원은 짧게 살더라도 누가 발급했고 무엇에 쓰였는지에 대한 기록은 오래 남겨야 하는 이유다.
