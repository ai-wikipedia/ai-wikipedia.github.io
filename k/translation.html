AI 번역

Machine Translation

AI가 한 언어로 된 글을 다른 언어로 자동으로 옮기는 기술로, 지금은 번역 전용 API와 LLM 직접 번역 두 방식을 주로 쓴다. 정해진 표현으로 많이 옮겨야 하면 번역 API를, 말투와 뉘앙스가 중요하면 LLM을 고른다.

방식예강점이럴 때 쓴다
번역 전용 APIDeepL, Google Cloud Translation빠르고 결과가 일정함대량 문서, 앱 UI 문구
LLM 직접 번역ChatGPT, Claude 등맥락·말투·관용표현광고 문구, 대화체 글
오픈소스 NMTOpenNMT직접 학습, 내부 서버 운영데이터를 밖으로 못 보낼 때

2016년 Google 번역이 규칙 기반에서 신경망 기계번역(NMT)으로 바뀌면서 품질이 크게 올랐다.

정확함은 번역기, 자연스러움은 LLM

번역 전용 API는 같은 문장을 넣으면 거의 같은 결과가 나온다. 그래서 공식 문서나 계약서처럼 표현이 흔들리면 안 되는 글에 맞다. 용어집(glossary) 기능을 쓰면 제품명이나 전문용어를 늘 같은 말로 옮기도록 고정할 수 있다.

LLM은 앞뒤 맥락과 문화적 뉘앙스를 더 잘 살린다. 광고 문구나 게임 대사처럼 읽는 느낌이 중요한 글은 LLM이 낫다. 다만 속도와 비용은 번역 API보다 불리한 경우가 많다.

LLM에는 독자와 규칙을 같이 준다

"영어로 번역해줘"라고만 쓰면 말투와 용어가 매번 달라진다. 아래 내용을 프롬프트에 함께 넣으면 결과가 안정된다.

넣을 내용예
대상 독자미국 개발자, 초등학생
말투존댓말, 짧고 친근하게
고정 용어"견적" → quote
형식 유지HTML 태그, 변수 {name}는 그대로 둔다

앱 다국어화는 파이프라인에 연결

다국어 앱을 만들 때는 번역 API를 i18n 파이프라인에 붙여 UI 문자열 파일을 자동으로 번역한다. 원문 파일이 바뀌면 새로 생긴 문장만 번역해 언어별 파일에 채운다. 그다음 사람이 검수하고 배포하는 순서가 일반적이다.

그대로 내보내기 전에 사람이 본다

AI 번역도 문장을 빠뜨리거나, 원문에 없는 말을 덧붙이거나, 숫자나 부정어를 잘못 옮길 수 있다. 법률·의료·계약 문서는 반드시 전문가가 검수해야 한다.

외부 번역 서비스에 글을 보내면 그 내용이 서비스 회사로 넘어간다. 기밀 문서라면 먼저 데이터 처리 정책을 확인하고, 필요하면 내부 서버에서 돌리는 오픈소스 모델을 고려한다.

읽을 때는 바로 돌리고, 내보낼 때는 다듬는다

가장 흔한 건 외국어 자료를 빠르게 읽는 용도다. 내가 이해하려고 읽는 글은 번역기를 그대로 쓰고, 남에게 보낼 글은 LLM으로 말투를 맞춘 뒤 한 번 더 확인한다.

해외 자료 읽기웹 페이지·논문·문서를 번역기에 넣어 내용을 빠르게 파악
업무 메일·메시지LLM에 받는 사람과 말투를 알려 주고 초안을 번역한 뒤 직접 다듬기
