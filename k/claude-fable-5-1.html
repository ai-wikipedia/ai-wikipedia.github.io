클로드 페이블 5.1

Claude Fable 5.1 (Anthropic)

클로드 페이블 5.1은 2026년 9월 Anthropic이 공개한 모델로, 일반 사용자가 쓸 수 있는 클로드 모델 중 가장 성능이 높다. 며칠씩 걸리는 장기 에이전트 작업과 고난도 추론에 맞춰져 있고, 캐시 읽기 가격을 4분의 1로 내려 에이전트를 반복 실행할 때 드는 비용을 줄였다.

맡겨 두고 퇴근해도 되는 모델

클로드 페이블 5.1은 Anthropic이 2026년 9월 1일 공개한 모델로, 일반 사용자가 쓸 수 있는 클로드 중 가장 성능이 높다. 페이블 5의 후속이며 클로드 5 제품군에서 오퍼스 5보다 위에 있다. 질문 하나에 빠르게 답하는 용도보다는 일을 통째로 맡기는 용도에 맞춰져 있다. 코드베이스 전체에 걸친 기능 구현, 여러 단계로 이어지는 리서치, 문서·스프레드시트·슬라이드 작업처럼 계획을 세우고 도구를 쓰고 결과를 스스로 검증하고, 실패하면 복구해서 다시 이어 가야 하는 일들이다. Anthropic은 이 모델을 길고 비동기적인 작업에 가장 잘 맞는 모델로 소개한다. API에서는 claude-fable-5-1로 호출하고, 지식 컷오프는 2026년 6월이며 출력은 텍스트만 나온다.

같은 모델이 이름 두 개로 나왔다는 점도 알아 둘 만하다. 클로드 미토스 5.1은 페이블 5.1과 똑같은 모델인데, 생물학과 사이버보안처럼 위험한 이중 용도 분야의 안전장치만 더 느슨하게 설정했다. 미토스는 Project Glasswing을 통해 초대받은 기관만 쓸 수 있고, 일반 개발자가 쓰는 것은 페이블 5.1이다.

가격표는 그대로인데 청구서가 줄어드는 이유

입력 100만 토큰당 10달러, 출력 50달러로 페이블 5와 같다. 바뀐 것은 캐시 읽기 가격으로, 1달러에서 0.25달러로 75% 내려갔다. 에이전트는 루프를 돌 때마다 시스템 프롬프트와 지금까지의 대화, 읽은 파일을 다시 모델에 넣는다. 이 반복되는 부분은 대부분 캐시에서 읽히기 때문에 캐시 읽기 단가가 사실상 에이전트 작업 비용을 좌우한다. Anthropic은 이번 인하로 일반 작업 비용이 약 25%, 에이전트 비중이 높은 작업은 최대 약 45%까지 줄어든다고 추산한다. 기본 단가로는 여전히 가장 비싼 클로드지만, 캐시 읽기만 놓고 보면 토큰당 가격이 오퍼스 5보다 낮다.

사고(thinking)는 적응형이라 항상 켜져 있고, 얼마나 깊게 생각할지는 effort 값으로 정한다. 기본값은 API와 Claude Code에서 high, Claude.ai와 Cowork에서 medium이다. Anthropic은 low나 medium으로 두어도 페이블 5와 비슷하거나 더 나은 성능을 훨씬 낮은 비용으로 내도록 설계했다고 밝혔다. 그래서 같은 모델을 effort만 바꿔 저렴한 일상 작업용으로도, 깊게 파고드는 작업용으로도 쓸 수 있다. 다만 공식 문서는 대부분의 작업에는 오퍼스 5.5로 시작하라고 권한다. 고난도 추론이나 장기 에이전트 작업이 필요할 때, 또는 오퍼스 5.5를 높은 effort로 돌려도 평가 기준에 못 미칠 때 페이블 5.1로 넘어가라는 것이다. 응답 속도도 하위 모델보다 느리다.

Claude Code에서 실제로 달라지는 점

Claude Code에 페이블 5.1을 걸어 두면 차이가 가장 크게 보이는 곳은 무인으로 길게 돌리는 작업이다. 모델이 직접 테스트를 작성해 자기 결과물을 확인하고, 화면을 보고(비전) 구현한 UI가 디자인과 맞는지 대조한다. 오래 돌아가는 워크플로에서도 스스로 작업 기록을 남기고, 상황이 바뀌면 우선순위를 다시 정하고, 중단된 지점부터 이어서 한다는 사용자 후기가 나왔다. 빌드가 깨진 저장소를 넘기면 원인을 찾아내고, 진행 상황도 이전 모델보다 짧고 읽기 쉽게 보고한다는 평가도 있다.

API로 직접 에이전트를 만드는 경우에는 새 기능이 몇 가지 생겼다. 메시지마다 effort를 다르게 줄 수 있는 per-message effort, 특정 턴에만 적용되는 system 메시지, 도구 호출 사이에 사람이 읽을 수 있는 진행 업데이트를 보여 주는 display: "updates" 옵션이 베타로 추가됐다. 예를 들어 계획 단계에는 effort를 높게 주고 반복적인 파일 수정 단계에는 낮게 주면, 품질은 유지하면서 비용을 아낄 수 있다.

페이블 5에서 옮길 때 깨지는 것들

기존에 페이블 5를 쓰던 코드에는 호환되지 않는 변경이 세 가지 있다. 첫째, 특정 도구 호출을 강제하는 forced tool use는 이제 에러를 반환한다. 둘째, 페이블 5.1은 이전 클로드 모델의 사고 블록을 읽을 수 있지만, 이전 모델은 페이블 5.1의 사고 블록을 읽지 못한다. 여러 모델을 오가는 라우팅 구조라면 이 부분을 확인해야 한다. 셋째, 대화의 이전 턴을 수정하면 그 턴의 사고 블록이 무효가 된다. Anthropic은 이 변경이 모델의 추론 내용을 빼내는 데 쓰이던 방법을 막기 위한 것이라고 설명한다.

보안 정책도 바뀌었다. 페이블 5와 달리 페이블 5.1은 사람이 읽을 수 있는 소스 코드에서 취약점을 찾는 방어 목적의 작업은 수행한다. 반면 컴파일된 바이너리 분석, 침투 테스트, 익스플로잇 작성처럼 위험하다고 판단한 요청은 오퍼스 4.8이나 오퍼스 5로 넘긴다. 벤치마크 측정에서는 이렇게 다른 모델로 넘어간 요청이 출력 토큰의 약 4%를 차지했다. Claude Code 세션당 안전장치 개입은 페이블 5보다 약 60% 줄었지만, Anthropic은 정상적인 요청이나 경계선에 있는 요청도 일부 차단될 수 있다고 인정했다. 또 하나 알아 둘 점은, 일부 코딩 벤치마크에서 effort를 높일수록 점수가 오히려 떨어졌다는 것이다. 모델이 요청받지 않은 수정을 덧붙이는 경향 때문인데, 정해진 범위만 고쳐야 하는 작업이라면 프롬프트로 수정 범위를 명확히 정해 주는 편이 안전하다.
