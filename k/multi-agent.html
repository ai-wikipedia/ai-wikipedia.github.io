멀티 에이전트

Multi-Agent System

여러 AI 에이전트가 조사·코딩·검증처럼 역할을 나눠 하나의 작업을 함께 처리하는 시스템이다. 에이전트 하나로는 컨텍스트가 모자라는 복잡한 작업을 나눠서 동시에 처리할 때 쓴다.

한눈에 보기

멀티 에이전트는 AI 에이전트 여러 개를 한 팀처럼 움직이게 하는 방식이다. 에이전트 하나가 조사·코딩·검증·문서 작성을 다 맡으면 컨텍스트가 모자라고 놓치는 부분이 생긴다. 그래서 일을 나눠 맡기고 결과를 합친다. 단순한 작업이라면 에이전트 하나로 충분하다.

구분단일 에이전트멀티 에이전트
일하는 방식혼자 모든 단계를 처리역할별로 나눠 병렬 처리
컨텍스트하나를 모두가 나눠 씀에이전트마다 따로 가짐
이럴 때 쓴다단순하고 짧은 작업여러 단계가 얽힌 복잡한 작업

Claude Code에서는 파일 하나로 시작한다

.claude/agents/ 폴더에 에이전트 역할을 마크다운으로 적어 두면, Claude가 작업 내용에 맞는 에이전트를 알아서 골라 부른다. Agent Teams 기능을 쓰면 리드 에이전트가 팀원 에이전트를 여러 개 띄운다. 팀원들은 각자 따로 컨텍스트를 쓰면서 동시에 일하고, 서로 메시지도 주고받는다.

에이전트마다 다른 도구를 쥐여 줄 때 효과가 가장 크다. 한 에이전트는 MCP로 GitHub 이슈를 읽고, 다른 하나는 DB 스키마를 조회하고, 마지막 에이전트가 둘의 결과를 모아 코드를 짜는 식이다.

협업 방식은 세 가지

일을 어떻게 나누고 넘길지에 따라 고르면 된다. 처음이라면 감독자 패턴이 가장 무난하다.

패턴방식이럴 때 쓴다
감독자메인 에이전트가 일을 나눠 주고 결과를 모은다가장 흔한 기본형
파이프라인정리 → 구현 → 테스트 순서로 넘긴다단계가 정해진 작업
스웜감독자 없이 각자 일을 가져가고 서로 넘긴다일감이 많고 유동적일 때

직접 만든다면 프레임워크부터 고른다

직접 구축할 때는 얼마나 세밀하게 제어하고 싶은지, 얼마나 빨리 시작하고 싶은지를 보고 고른다.

프레임워크특징잘 맞는 경우
LangGraph워크플로를 그래프로 설계, 코드가 많다조건 분기·병렬 실행을 세밀하게 제어할 때
CrewAI리서처·라이터 같은 역할만 정하면 된다, MCP·A2A 지원빠르게 시작할 때
AutoGen에이전트끼리 대화하는 구조토론·협의가 필요한 작업

에이전트는 많을수록 좋은 게 아니다

에이전트가 4개를 넘으면 서로 소통하는 비용이 실제 작업보다 커질 수 있다. 회의가 너무 많아서 일이 안 되는 회사와 같다. 실제 서비스에 붙이면 보안상 공격받을 수 있는 지점이 늘고 관리도 복잡해진다. 그래서 에이전트에게 결과물을 제출할 권한은 주되 최종 반영(머지) 권한은 주지 않는 식으로, 마지막 검토는 사람이 하는 구조를 유지해야 한다.
