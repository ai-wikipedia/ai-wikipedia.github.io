Open Memory Protocol

여러 AI 도구가 하나의 로컬 메모리 저장소를 함께 읽고 쓰게 하는 MCP 기반 오픈소스 프로토콜이다. Claude에서 쌓은 프로젝트 맥락을 다른 도구에서 다시 설명하지 않고 이어 쓰고 싶을 때 쓴다.

방식메모리 위치다른 도구와 공유
각 서비스의 기억 기능각 서비스 안안 됨
OMP내 컴퓨터(로컬)연결된 도구끼리 공유
Mem0 OpenMemory MCP로컬MCP 지원 도구끼리 공유

도구를 바꿀 때마다 처음부터 다시 설명하는 문제

AI 도구를 여러 개 쓰면 같은 배경 설명을 계속 되풀이하게 된다. Claude에게 프로젝트 구조와 규칙을 알려 줬어도 ChatGPT나 Cursor로 넘어가면 처음부터 다시 시작이다. 각 서비스의 기억 기능은 그 서비스 안에서만 통하기 때문이다.

OMP는 메모리를 도구 밖, 사용자 컴퓨터에 따로 둔다. 메모리가 클라우드로 나가지 않고 사용자가 직접 소유하고 관리한다는 점이 핵심이다.

설치하고 로컬 서버를 띄운 뒤 도구를 연결한다

순서는 간단하다. 패키지를 설치하고 로컬 서버를 띄운 다음, AI 클라이언트마다 어댑터 URL을 넣는다.

단계할 일
1. 설치pip install open-memory-protocol
2. 서버 실행로컬에서 메모리 서버를 띄운다
3. 연결클라이언트마다 어댑터 URL 설정

지금 실제로 쓸 수 있는 연결 경로는 세 가지다. Claude는 MCP 통합으로, 브라우저에서 쓰는 도구는 OMP Bridge 확장으로, 직접 만든 스크립트는 REST 클라이언트로 연결한다.

지금은 Claude를 주로 쓸 때 쓸 만하다

OpenAI Assistants, Cursor, Copilot, VS Code, Gemini 어댑터는 아직 완성되지 않았다. 그래서 여러 도구를 매끄럽게 오가는 경험은 아직 제한적이다. 지금은 Claude를 주로 쓰면서 맥락을 로컬에 모아 두고 싶을 때 가장 쓸모가 있다.

Cursor나 Copilot을 중심으로 작업한다면 당장 효과를 보기 어렵다. 이럴 때는 각 도구의 자체 메모리나 프로젝트 설정 파일을 쓰는 편이 현실적이다.

로컬 저장이어도 읽힌 내용은 밖으로 나간다

메모리는 로컬에 있지만, 연결된 AI 도구가 메모리를 읽으면 그 내용은 해당 서비스로 전송된다. 비밀번호나 고객 정보처럼 민감한 내용은 메모리에 넣지 않는 게 안전하다.

Mem0의 OpenMemory MCP처럼 같은 목표를 가진 프로젝트가 여럿 있고, 어느 방식이 표준이 될지는 아직 불확실하다. 한 프로젝트에 메모리를 깊이 묶어 두기 전에 저장된 내용을 직접 보고 지울 수 있는지 먼저 확인해 두면 좋다.

주로 Claude 작업 맥락을 모아 두는 데 쓴다

가장 흔한 쓰임은 Claude로 하는 프로젝트의 규칙과 배경을 로컬에 쌓아 두고 새 대화에서 다시 꺼내 쓰는 것이다. 다른 도구는 지금 열려 있는 연결 경로로만 붙인다.

어디서어떻게 쓰나
Claude (MCP 통합)프로젝트 구조·코딩 규칙·결정 사항을 저장해 두고, 새 대화마다 다시 설명하지 않는다
브라우저 AI 도구 (OMP Bridge)웹에서 쓰는 AI 채팅에 같은 메모리를 불러와 Claude에서 쌓은 맥락을 이어 쓴다
직접 만든 스크립트 (REST)자동화 스크립트가 작업 결과나 메모를 메모리에 기록하고, 필요할 때 읽어 온다
