브라우저 에이전트

Browser Agent

브라우저 에이전트는 AI가 웹 브라우저를 직접 조작해 검색·클릭·입력·정보 수집을 대신하는 에이전트로, Playwright 같은 브라우저 자동화 도구에 LLM을 붙인 구조다. API가 없는 사이트도 말로 지시해서 자동화하거나 여러 사이트를 돌며 정보를 모을 때 쓴다.

방식동작 원리사이트가 바뀌면
API 연동공식 데이터 통로 사용안정적이지만 API가 있어야 함
기존 스크래핑HTML 구조를 코드에 직접 적음코드가 깨진다
브라우저 에이전트LLM이 화면을 보고 판단스스로 맞춰 간다

채팅창, Claude Code, 코드 중에 고른다

가장 쉬운 방법은 채팅 서비스에 들어 있는 에이전트를 쓰는 것이다. OpenAI가 Operator로 선보인 방식처럼, 할 일을 말하면 AI가 가상 브라우저를 열어 처리하고 사용자는 그 과정을 지켜본다.

개발자라면 Claude Code에 Playwright MCP를 연결하는 방법이 간단하다. 터미널에서 claude mcp add playwright npx @playwright/mcp@latest로 추가한 뒤 "이 사이트에서 오늘 항공권 가격 찾아줘"처럼 지시하면 된다. 반복 작업을 프로그램으로 만들 때는 Browser Use나 Stagehand 같은 라이브러리를 쓴다. 브라우저를 서버에 여러 개 띄워야 하면 Browserbase 같은 클라우드 브라우저를 붙인다.

방법대상이럴 때
채팅 서비스 내장 에이전트일반 사용자가끔 하는 예약·검색
Claude Code + Playwright MCP개발자웹앱 테스트, 즉석 조사
Browser Use, Stagehand개발자반복 수집을 코드로 만들 때
Browserbase운영브라우저를 서버에서 여러 개 돌릴 때

API가 있으면 API부터 쓴다

브라우저 에이전트는 단계마다 화면을 읽고 판단한다. 그래서 느리고 토큰 비용도 많이 든다. 공식 API나 구조가 고정된 스크래핑으로 해결되는 일이라면 그쪽이 더 빠르고 정확하다.

상황추천
API가 없고 화면 구조가 자주 바뀜브라우저 에이전트
여러 사이트를 돌며 가격·재고·채용 공고 비교브라우저 에이전트
공식 API를 제공하는 서비스API
같은 페이지를 자주, 대량으로 수집일반 스크래핑 코드

결제·로그인은 사람이 확인한다

에이전트도 버튼을 잘못 누르거나 엉뚱한 페이지로 갈 수 있다. 결제, 메일 발송, 계정 설정 변경처럼 되돌리기 어려운 동작은 실행 직전에 사람이 확인하도록 해 둔다. Operator도 로그인이나 결제 정보 입력 단계에서는 사용자에게 제어권을 넘기게 만들어졌다.

웹페이지 속 숨겨진 문장이 AI에게 엉뚱한 지시를 내리는 프롬프트 인젝션도 조심해야 한다. 중요한 계정에 로그인된 브라우저를 그대로 맡기지 말고 작업용 프로필을 따로 쓴다. 사이트 이용약관과 CAPTCHA 같은 자동화 차단 정책도 지켜야 한다.

조사, 웹앱 테스트, 반복 입력에 주로 쓴다

가장 흔한 건 여러 사이트를 돌며 정보를 모아 정리하게 하는 방식이다. 개발자는 코딩 에이전트가 만든 화면을 직접 열어 확인하는 테스트 도구로도 많이 쓴다.

어디서어떻게 쓰나
가격·정보 비교 조사쇼핑·예약·채용 사이트 여러 곳을 돌며 조건에 맞는 항목을 모아 표로 정리
웹앱 테스트코딩 에이전트가 만든 화면을 직접 열어 클릭해 보고, 깨진 버튼이나 오류를 찾아 고침
반복 입력 업무API가 없는 관리 화면에 같은 양식을 여러 번 채우고, 제출 직전만 사람이 확인
개인 일 처리예약·장바구니 담기처럼 가끔 하는 일을 말로 맡기고, 로그인·결제는 직접 함
