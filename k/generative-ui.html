생성형 UI

Generative UI / Intelligent UI

AI가 답을 글로만 쓰지 않고, 질문에 맞는 차트·폼·버튼 같은 화면을 그 자리에서 만들어 보여주는 방식이다. 개발자가 모든 화면을 미리 코딩하는 대신 모델이 의도와 맥락을 보고 화면을 구성하며, 비교·계산처럼 손으로 만져 봐야 이해되는 답을 줄 때 쓴다.

방식AI가 하는 일특징
정적 (Static)미리 만든 컴포넌트 하나를 고른다통제 높음, 자유도 낮음
선언형 (Declarative)정해진 카탈로그로 화면 명세를 조합한다통제와 자유의 균형
개방형 (Open-Ended)HTML 같은 코드를 직접 쓴다자유도 높음, 관리 부담 큼

AI에게 화면 구성의 자유를 얼마나 주느냐에 따라 나눈 세 가지 구현 방식.

'텍스트 벽'을 손으로 만지는 답으로

초기 LLM 앱은 복잡한 계획을 세워도 결과를 긴 문단이나 마크다운으로만 보여줬다. 생성형 UI에서는 같은 답이 슬라이더, 폼, 표, 지도, 차트로 나온다. 개념 설명을 요청하면 입력값을 바꿔 보며 결과를 확인하는 다이어그램이, 여행 질문에는 지도와 일정표가 함께 나오는 식이다.

ChatGPT의 Intelligent UI가 대표 사례다. GPT-6가 DIL이라는 언어로 마크다운 글, JSX 비슷한 컴포넌트 태그, 상태 로직을 섞어 쓰면 서버가 이를 컴파일해 ChatGPT 자체 디자인 시스템으로 그린다. 컴포넌트는 추가 모델 호출 없이 입력에 반응하고, 응답이 끝나기 전부터 화면이 조금씩 나타난다.

내 앱에 넣을 때는 카탈로그부터 정한다

ChatGPT도 대부분 선언형으로 동작하고, 필요할 때만 개방형을 쓴다. 내 서비스에 넣을 때도 먼저 버튼·카드·차트처럼 쓸 컴포넌트 카탈로그를 정하고, 모델은 그 안에서만 조합하게 하는 것이 출발점이다. 그래야 응답마다 디자인이 흔들리지 않는다.

화면 성격맞는 방식
결제·예약처럼 틀리면 안 되는 화면정적: 정해진 컴포넌트만 선택
대시보드, 비교표, 상품 카드선언형: 카탈로그 조합
시뮬레이션, 게임, 학습용 시각화개방형: 코드 생성 허용

직접 만들기 부담스럽다면 CopilotKit이 공개한 오픈소스 Open Intelligent UI를 쓸 수 있다. AG-UI 프로토콜로 원하는 에이전트와 모델을 연결하고, 기존 디자인 시스템과 컴포넌트를 그대로 쓴다.

자유를 줄수록 안정성 관리가 필요하다

생성형 UI에서 가장 중요한 것은 안정성과 신뢰다. 모델이 코드를 직접 쓰는 개방형은 표현력이 크지만 브랜드 일관성과 보안을 지키기 어렵고, 정적 방식은 안전한 대신 새로운 질문에 맞는 화면을 만들지 못한다. 어느 쪽을 고를지는 내 서비스가 브랜드 안전성과 보안을 얼마나 엄격하게 요구하는지에 따라 정하면 된다.

대화 답변을 조작하는 화면으로 바꾸는 곳

가장 흔한 건 챗봇·AI 어시스턴트의 답변 화면이다. 글로 길게 풀던 답을 표·차트·폼으로 바꿔, 사용자가 값을 바꿔 보거나 바로 선택하게 한다.

어디서어떻게 쓰나
ChatGPT개념 질문엔 값을 바꿔 보는 다이어그램, 여행 질문엔 지도와 일정표가 답으로 나온다
서비스 내 AI 어시스턴트정해 둔 카탈로그 안에서 비교표·상품 카드·대시보드를 조합해 보여준다
학습·설명 도구개방형으로 시뮬레이션이나 인터랙티브 시각화를 그 자리에서 만든다
직접 만든 에이전트 앱Open Intelligent UI와 AG-UI로 에이전트를 연결해 기존 컴포넌트로 화면을 그린다
