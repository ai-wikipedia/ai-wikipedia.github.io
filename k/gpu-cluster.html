GPU 클러스터

GPU Cluster

GPU 클러스터는 수십에서 수천 개의 GPU를 빠른 네트워크로 묶어 하나처럼 쓰는 컴퓨팅 인프라다. GPU 한 대로 감당할 수 없는 대형 모델의 학습이나 대규모 추론에 쓴다.

한눈에 보기

GPT-4나 Claude 같은 대형 모델은 GPU 한 대에 올라가지도 않고, 한 대로 학습하면 끝나지도 않는다. 그래서 A100·H100 같은 GPU를 수백에서 수천 개 묶은 GPU 클러스터에 모델과 데이터를 나눠 싣고 함께 계산한다. 규모에 따라 필요한 구성은 이렇게 달라진다.

규모구성이럴 때 쓴다
GPU 1대개인 PC·단일 인스턴스작은 모델 추론, LoRA 파인튜닝
서버 1대보통 GPU 8개중형 모델 학습·추론
클러스터서버 여러 대를 네트워크로 연결LLM 사전학습, 대형 모델 전체 학습

연결 속도가 성능을 정한다

GPU를 많이 모아도 서로 결과를 주고받는 속도가 느리면 대부분의 시간을 기다리는 데 쓴다. 그래서 클러스터는 GPU 개수만큼 연결 방식이 중요하다.

구간쓰는 기술역할
서버 안 GPU끼리NVLink가장 빠른 직접 연결
서버와 서버 사이InfiniBand 등 고속 네트워크노드 간 대량 데이터 교환
소프트웨어 통신NCCLGPU 간 데이터 합치기·나누기

모델과 데이터를 나눠 싣는 세 가지 방법

클러스터를 쓸 때는 일을 어떻게 나눌지 정해야 한다. 큰 모델일수록 아래 방식을 섞어 쓴다.

방식나누는 것언제 쓰나
데이터 병렬화학습 데이터모델이 GPU 한 대에 들어갈 때
텐서 병렬화한 층의 계산층 하나도 너무 클 때, 주로 서버 안에서
파이프라인 병렬화층 묶음모델 전체가 서버 한 대를 넘을 때

직접 짓기보다 클라우드에서 빌린다

H100 한 개가 수만 달러이고 대형 클러스터는 이를 수천 개 운영하므로, 대부분의 팀은 AWS·GCP·Azure의 GPU 인스턴스를 빌려 쓴다. 예를 들어 AWS에서는 p4d.24xlarge(A100 8개)나 p5.48xlarge(H100 8개)를 여러 대 띄운다.

순서는 보통 이렇다. 인스턴스를 고속 네트워크가 되는 같은 영역에 띄우고, Slurm이나 Kubernetes로 작업을 나눠 배치한 뒤, DeepSpeed나 PyTorch FSDP로 분산 학습 코드를 돌린다. 통신은 NCCL이 맡는다.

필요 없는 경우와 주의할 점

모델을 쓰기만 한다면 API로 충분하고, 오픈 모델 파인튜닝도 LoRA처럼 가벼운 방식이면 GPU 한두 개로 되는 경우가 많다. 클러스터는 정말 큰 모델을 처음부터 학습하거나 전체 파라미터를 학습할 때 고려한다.

GPU가 많을수록 한 대만 고장 나도 전체 작업이 멈출 수 있다. 체크포인트를 자주 저장해 중간부터 다시 시작할 수 있게 하고, 작은 규모로 먼저 돌려 통신 병목이 없는지 확인한 뒤 늘리는 게 안전하다.
