Docker Agent

Docker Agent는 역할이 다른 AI 에이전트 여러 개를 YAML 파일 하나로 팀으로 묶고 `docker agent` 명령으로 실행하는 Docker의 오픈소스 프레임워크다. 코드를 짜지 않고 에이전트 팀을 만들고, 그 구성을 컨테이너 이미지처럼 팀원과 공유하고 싶을 때 쓴다.

한눈에 보기

Docker Agent는 모델 하나에 모든 일을 맡기지 않고 역할이 다른 에이전트 여러 개를 팀으로 묶어 돌리는 도구다. 조사 담당, 수정 담당처럼 분업 구조를 YAML에 적으면 에이전트끼리 일을 넘기는 조율은 프레임워크가 맡는다. 원래 이름은 cagent였고, 지금은 Docker Desktop에 기본으로 들어 있다.

이름정체차이
Docker Agent에이전트 팀 프레임워크내가 직접 팀을 만들어 돌린다

YAML에 역할을 적고 명령 한 줄로 실행

에이전트마다 쓸 모델, 설명, 지침, 도구를 YAML에 적는다. 특정 업체에 묶이지 않아서 여러 클라우드 모델과 로컬 모델을 섞어 쓸 수 있다. 예를 들어 디버깅 팀이라면 루트 에이전트가 원인을 조사하다가, 원인을 찾으면 fixer 에이전트에게 수정을 넘기게 짜면 된다.

상황명령
처음 만들 때 (대화로 생성)docker agent new
직접 쓴 설정 실행docker agent run agent.yaml
Docker Desktop 없이 설치brew install docker-agent

brew로 설치했다면 바이너리를 ~/.docker/cli-plugins/에 연결해야 docker agent 명령을 쓸 수 있다.

도구는 역할별로 나눠 준다

에이전트가 할 수 있는 일은 연결한 도구로 정해진다. 내장 도구 외에 MCP 서버를 붙일 수 있어서, 조사 담당에게는 이슈 트래커 읽기만, 수정 담당에게는 파일 편집 도구만 주는 식으로 권한을 나누면 된다. 문서를 찾아 봐야 하는 에이전트라면 설정에서 RAG 검색을 켜면 된다.

이미지처럼 레지스트리로 공유한다

가장 Docker다운 부분이다. 에이전트 설정을 OCI 레지스트리에 올리면 팀원은 docker agent run myorg/agent:tag로 컨테이너 이미지를 받듯 그대로 실행한다. 사내에서 다듬은 코드 리뷰 에이전트 팀을 올려 두면 다른 개발자도 같은 구성을 똑같이 재현할 수 있고, 같은 실험을 여러 번 반복해야 할 때도 편하다.

샌드박스는 아직 실험 단계

에이전트에 셸과 파일 접근을 주면 내 컴퓨터가 망가질 수 있다. 이럴 때는 docker sandbox run agent ~/path/to/workspace로 격리된 마이크로VM 안에서 돌리면, 에이전트가 안에서 컨테이너를 빌드해도 내 컴퓨터는 건드리지 못한다. 다만 아직 실험 단계라 Docker Desktop 버전이 바뀌면 동작이 깨질 수 있고, macOS와 Windows에서만 된다.

격리만 필요하다면 샌드박스 위에 Claude Code나 Codex를 바로 올려도 된다. YAML로 팀을 짜는 방식과 레지스트리 공유가 필요할 때 Docker Agent를 고르면 된다.
