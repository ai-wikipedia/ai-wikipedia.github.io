위브 라우터

Weave Router

위브 라우터는 코딩 에이전트와 모델 제공사 사이에 두는 프록시로, 요청마다 난이도를 보고 감당할 수 있는 가장 싼 모델로 자동으로 보낸다. Claude Code 같은 에이전트를 많이 돌려서 비용을 줄이고 싶을 때 쓴다.

한눈에 보기

코딩 에이전트는 작업 하나를 하면서 모델을 수십, 수백 번 부른다. 그런데 대부분은 파일 훑기처럼 단순한 요청이다. Weave Router는 이런 요청을 하나씩 보고 제대로 해낼 수 있는 가장 싼 모델로 보낸다. 에이전트 입장에서는 API 주소만 바뀌고, 평소처럼 Anthropic이나 OpenAI와 통신한다고 여긴다.

요청 종류예시보내는 곳
단순하고 짧은 작업파일 목록 훑기, 짧은 코드 채우기저렴한 오픈소스 모델
어려운 작업설계 판단, 수정안 작성상위 프론티어 모델

대화 턴 단위가 아니라 API 요청 하나하나를 따로 판단한다. 같은 턴 안에서도 요청마다 난이도가 다르기 때문이다.

명령 한 줄로 설치하고 언제든 끈다

npx @weave-os/router를 실행하면 Claude Code, Codex, opencode 설정을 찾아서 라우터 주소와 키를 대신 넣어 준다. 라우터 없이 쓰고 싶으면 off로 제공사에 바로 연결하고, 다시 쓰려면 on을 실행한다. Cursor는 설정에서 OpenAI 기본 주소를 라우터 주소로 바꿔야 하는데, 아직 초기 베타다.

운영 방식특징
관리형Weave가 제공사 계정을 대신 관리하고 잔액 하나로 청구
셀프호스팅같은 서비스를 내 서버에 띄우고 내 키를 사용

오픈소스 모델은 OpenRouter 키 하나로 연결된다. 대시보드에서는 요청마다 비용, 지연, 그 모델을 고른 이유를 볼 수 있다.

캐시가 아까우면 모델을 바꾸지 않는다

에이전트 대화는 앞부분이 계속 반복된다. 그래서 프롬프트 캐시 덕분에 싸게 돌아가는데, 모델을 바꾸면 캐시를 처음부터 다시 쌓아야 한다. 그래서 라우터는 세션을 처음 고른 모델에 붙여 둔다. 캐시를 새로 쌓는 비용까지 따져 봤을 때 갈아타는 쪽이 이득일 때만 바꾼다. 모델을 고를 때는 가격 말고도 첫 응답이 나오는 속도와 답이 얼마나 긴지를 함께 본다.

절감 효과는 직접 확인하고 켠다

Weave는 실제 Claude Code 트래픽에서 품질은 거의 그대로 두고 비용을 크게 줄였다고 말한다. 하지만 자체 측정이고 평가 방법도 자세히 공개하지 않았다. 내 코드베이스에서도 오픈소스 모델이 같은 품질을 낸다는 보장은 없다.

안전하게 시작하려면 /v1/route 엔드포인트부터 쓴다. 이 엔드포인트는 실제로 요청을 보내지 않고 어떤 모델을 고를지만 알려 준다. 이렇게 판단만 기록해 보면서 도구 호출이 많은 작업에서 실패율이 오르지 않는지 확인한다. 문제가 없으면 그때 실제 라우팅을 켠다.
