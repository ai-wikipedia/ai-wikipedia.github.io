Weave Router

에이전트 코딩 도구의 요청을 하나씩 분석해 작업 난이도에 맞는 모델로 자동 라우팅하는 프록시다. 간단한 요청은 저렴한 모델로 보내고 어려운 요청만 상위 모델에 맡겨, 같은 예산으로 더 많은 작업을 돌릴 수 있게 해준다.

모든 요청에 가장 비싼 모델이 필요할까

Claude Code나 Codex 같은 코딩 에이전트는 작업 하나를 처리하면서 수십, 수백 번 모델을 호출한다. 그중에는 설계 판단처럼 어려운 요청도 있지만, 파일 목록을 훑거나 짧은 코드 조각을 채우는 단순한 요청이 훨씬 많다. 그런데 보통은 이 모든 호출이 사용자가 고른 하나의 프론티어 모델로 간다. Weave Router는 에이전트와 모델 제공사 사이에 끼어드는 프록시로, 요청 하나하나를 보고 '이걸 제대로 해낼 수 있는 가장 싼 모델'로 보내준다. 2026년 5월 Weave가 공개했고, 에이전트 쪽에서는 API 주소만 바뀔 뿐 평소처럼 Anthropic이나 OpenAI와 통신한다고 생각한다.

Weave가 Claude Code 실제 트래픽을 분석해 보니 요청의 60~70%는 구조가 단순한 짧은 작업이었고, 이런 요청은 오픈소스 모델이 프론티어 모델과 같은 품질을 약 40분의 1 비용으로 처리했다고 한다. 이 차이를 요청마다 자동으로 잡아내는 게 라우터의 일이다.

요청을 어떻게 분류하나

라우터 안에는 작은 ONNX 임베딩 모델이 들어 있어 외부 호출 없이 프롬프트를 벡터로 바꾼다. 이 벡터를 미리 학습해 둔 여러 '의도 클러스터'의 중심점과 비교해 요청이 어떤 종류인지 판단하고, 그 클러스터에서 과거에 프론티어급 품질을 냈던 모델 중 가장 싼 것을 고른다. 고를 때는 가격뿐 아니라 첫 토큰이 나오기까지의 시간과 답변이 얼마나 장황한지도 함께 따진다. 이 방식은 질문을 클러스터로 나누고 클러스터마다 모델의 성능과 비용을 점수화해 최적의 모델을 고르는 Avengers-Pro 연구에서 출발했고, Weave는 이를 실제 서비스 트래픽으로 다시 학습시켰다. 라우팅 판단이 더하는 지연은 수 밀리초 수준이라고 한다. 판단 단위는 대화 턴이 아니라 에이전트가 보내는 API 요청 하나하나다. 한 턴 안에서도 파일을 훑는 호출과 수정안을 쓰는 호출은 난도가 전혀 다를 수 있기 때문이다.

캐시를 깨지 않는 라우팅

요청마다 모델을 바꾸면 생기는 문제가 있다. 에이전트 대화는 앞부분이 계속 반복되기 때문에 제공사의 프롬프트 캐시 덕분에 싸게 돌아가는데, 모델을 갈아타면 새 제공사에서 캐시를 처음부터 다시 쌓아야 한다. 그래서 Weave Router는 세션을 처음 고른 모델에 붙여 두고, 캐시를 새로 데우는 비용까지 계산해 갈아타는 쪽이 전체적으로 이득일 때만 바꾼다. Anthropic, OpenAI, Gemini처럼 형식이 다른 API 사이를 오갈 때도 캐시 표시, 사고 블록, 도구 호출 내용, Gemini의 사고 서명 값을 보존한다고 설명한다.

설치와 운영 방식

가장 간단한 시작은 npx @weave-os/router다. 설치 도구가 Claude Code, Codex, opencode의 설정을 찾아 라우터 주소와 키를 대신 써 넣고, off와 on 명령으로 언제든 제공사 직결 모드로 되돌릴 수 있다. Cursor는 설정에서 OpenAI 기본 주소를 라우터로 바꾸는 방식인데 아직 초기 베타다. 관리형 서비스는 Weave가 제공사 계정을 대신 들고 하나의 잔액으로 청구하고, 셀프호스팅은 Go로 작성된 같은 서비스를 자기 서버에 띄워 자기 키를 쓴다. 오픈소스 모델은 OpenRouter 키 하나로 DeepSeek, Kimi, GLM, Qwen 등에 연결된다.

실제 요청을 보내지 않고 어떤 모델이 선택될지만 돌려주는 /v1/route 엔드포인트도 있다. 대시보드에서는 요청별 비용, 지연, 선택 이유를 볼 수 있고, OpenTelemetry 추적을 Honeycomb이나 Grafana 같은 기존 관측 도구로 내보낼 수도 있다.

믿기 전에 확인할 것

절감 효과와 품질 동등성 주장은 모두 Weave의 자체 측정이고, 주로 Claude Code 트래픽에서 나온 숫자다. 공개 블로그는 프로덕션 Claude Code 트래픽에서 비용을 80~85% 줄이면서 눈에 띄는 품질 저하가 없었다고 하지만, 평가 방법은 자세히 공개하지 않았다. 공개 라우터 비교 리더보드인 RouterArena에서 1위를 했다는 주장도 회사 발표다. 내 코드베이스에서 오픈소스 모델이 같은 품질을 낸다는 보장은 없다. 그래서 처음에는 /v1/route로 판단만 기록하는 섀도 모드로 돌려 보고, 도구 호출이 많은 작업에서 실패율이 오르지 않는지 확인한 뒤 실제 라우팅을 켜는 순서가 안전하다.
