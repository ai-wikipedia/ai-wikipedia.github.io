툴 콜링

Tool Calling

LLM이 외부 함수나 API를 직접 호출할 수 있게 하는 기능. AI가 검색, 계산, DB 조회 같은 실제 작업을 수행하는 방법이다.

말만 하던 모델에게 손을 달아 주는 방식

툴 콜링(Tool Calling)이란 LLM이 대화 도중 '이건 내가 아는 것만으로는 답할 수 없으니 이 함수를 이 인자로 불러야겠다'고 판단해, 호출 요청을 정해진 형식으로 내놓는 기능이다. 함수 호출(function calling)이라고도 부른다. 중요한 점은 모델이 직접 아무것도 실행하지 않는다는 것이다. 모델은 "get_weather를 location=서울로 호출해 주세요"라는 구조화된 쪽지를 쓸 뿐이고, 실제로 날씨 API를 부르는 건 개발자의 코드다. 비서가 전화를 직접 걸 수는 없지만 누구에게 무슨 내용으로 걸어야 하는지 정확히 적어 주는 것과 비슷하다. 이 단순한 구조 덕분에 LLM은 최신 정보 조회, 계산, DB 검색, 파일 수정처럼 혼자서는 못 하던 일을 할 수 있게 됐다.

한 번의 호출이 오가는 순서

Anthropic API 기준으로 흐름은 이렇다. 먼저 요청의 tools 배열에 도구마다 이름, 설명, 입력 형식을 정의한 JSON 스키마(input_schema)를 넣어 보낸다. 모델이 도구가 필요하다고 판단하면 응답의 stop_reason이 tool_use가 되고, 본문에 호출할 도구 이름과 인자가 담긴 tool_use 블록이 들어 있다. 개발자 코드는 이 블록을 읽어 실제 함수를 실행한 뒤, 결과를 같은 호출 ID를 붙인 tool_result 블록에 담아 다음 요청으로 보낸다. 그러면 모델이 결과를 읽고 최종 답을 쓰거나 다른 도구를 또 부른다. 도구 실행이 실패했을 때도 예외를 삼키지 말고 오류 내용을 tool_result에 담아 is_error로 표시해 돌려주면, 모델이 인자를 고쳐 다시 시도하거나 다른 방법을 찾는다.

OpenAI도 이름만 tool_calls와 tool 역할 메시지로 다를 뿐 같은 왕복 구조이고, 서로 독립적인 호출 여러 개를 한 번에 요청하는 병렬 호출도 지원한다. "서울과 부산 날씨 비교해 줘"라는 요청이면 두 도시 조회를 동시에 요청하는 식이다. 이 왕복을 목표를 이룰 때까지 반복하는 루프가 곧 AI 에이전트의 뼈대다.

모델이 도구를 잘 고르게 만들려면

Anthropic 문서는 도구 성능을 좌우하는 가장 중요한 요소로 상세한 설명을 꼽는다. 이 도구가 무엇을 하는지, 언제 써야 하고 언제 쓰면 안 되는지, 각 인자가 무슨 의미인지, 무엇을 돌려주는지까지 적어야 모델이 비슷한 도구 사이에서 헷갈리지 않는다. 도구가 많아지면 github_list_prs, slack_send_message처럼 서비스 이름을 앞에 붙이고, 비슷한 동작을 여러 도구로 쪼개기보다 하나로 묶는 편이 선택 오류를 줄인다. 날짜 형식처럼 까다로운 인자가 있다면 input_examples에 올바른 입력 예시를 넣어 줄 수도 있다.

호출 여부도 조절할 수 있다. 기본값인 tool_choice auto는 모델이 판단하게 두고, none은 도구 사용을 막는다. 특정 도구 호출을 강제하는 옵션도 있지만 일부 최신 Claude 모델은 이를 지원하지 않고, 대신 auto와 스키마에 맞는 인자를 보장하는 strict: true 조합을 쓰도록 안내한다. 도구 정의도 매 요청 입력 토큰으로 과금된다는 점을 기억해야 한다. 도구가 수십 개면 정의만으로 컨텍스트가 무거워지므로, 필요한 도구만 그때그때 찾아 불러오는 도구 검색 기능을 쓰기도 한다.

어디서 실행되느냐, 그리고 MCP

도구는 실행 위치로도 나뉜다. 개발자가 정의하고 자기 서버에서 실행하는 클라이언트 도구가 기본이고, 웹 검색이나 코드 실행처럼 모델 제공사 인프라에서 돌아가 결과만 받아 보는 서버 도구도 있다. Claude Code가 파일을 읽고, 셸 명령을 실행하고, 코드를 고치는 것도 전부 이런 도구 호출의 연속이다. 도구가 늘면서 같은 GitHub 연동을 앱마다 다시 정의하는 낭비가 생겼고, MCP는 도구를 한 번 서버로 만들어 두면 여러 AI 앱이 같은 방식으로 불러 쓰도록 표준화했다. 툴 콜링이 '모델이 도구를 부르는 문법'이라면 MCP는 '도구를 배포하는 규격'인 셈이다.

실행 권한이 언제나 개발자 코드에 있다는 점은 안전장치로 활용해야 한다. 모델이 고른 인자를 그대로 믿지 말고 검증하고, 결제나 삭제처럼 되돌릴 수 없는 작업은 사람의 확인을 거치게 하며, 도구 결과로 들어오는 웹 페이지나 문서 속 프롬프트 인젝션에도 대비해야 한다. 모델에게는 작업에 꼭 필요한 도구와 권한만 쥐여 주는 것이 기본이다.
