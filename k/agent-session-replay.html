에이전트 세션 리플레이

Agent Session Replay

AI 에이전트가 한 번 실행되는 동안 남긴 프롬프트, 응답, 도구 호출, 결과를 원래 순서대로 다시 펼쳐 보는 디버깅 방식이다. 에이전트가 왜 같은 일을 반복했는지, 어디서 엉뚱한 길로 빠졌는지 찾을 때 쓴다.

한눈에 보기

에이전트는 생각하고, 도구를 부르고, 결과를 읽고, 다시 생각하는 과정을 되풀이한다. 이 단계마다 이벤트가 남는데, 세션 리플레이는 이 이벤트를 실제로 일어난 순서대로 타임라인에 다시 배치한다. 로그 파일에서 실행 ID를 grep해 머릿속으로 순서를 맞추는 대신, 세션 하나를 열고 처음부터 끝까지 따라가 볼 수 있다.

구분기존 세션 리플레이에이전트 세션 리플레이
기록 대상사람의 클릭·스크롤·입력프롬프트, 응답, 도구 호출, 에러
보여주는 방식화면 녹화처럼 재생스팬이 이어진 트레이스 타임라인
답하는 질문사용자가 어디서 막혔나에이전트가 실제로 무엇을 했나

다시 돌리는 게 아니라 기록을 다시 본다

리플레이는 프롬프트를 다시 보내거나 도구를 다시 실행하지 않는다. 같은 입력에도 매번 다르게 움직이는 에이전트는 재실행으로 같은 실패를 다시 만들기 어렵다. 그래서 실제로 있었던 실행을 그대로 보는 것이 무슨 일이 일어났는지 정직하게 확인하는 방법이다. 기록은 앞뒤로 넘겨 보거나 내보내서 분석할 수 있고, 다른 실행과 나란히 놓는 비교 기준으로도 쓴다.

스팬을 펼쳐 꼬인 지점을 찾는다

워터폴 타임라인을 훑다가 이상한 스팬을 펼치면, 그때 실제로 나간 요청과 돌아온 응답 원문이 보인다. 실패했다는 사실만 아는 것과, 에이전트의 작업 순서 안에서 어디가 틀어졌는지 보는 것은 다르다.

증상리플레이에서 볼 곳
같은 도구를 계속 부른다반복되는 스팬과 그 직전 도구 결과
요청과 다른 일을 한다방향이 바뀐 첫 모델 호출
중간에 멈췄다훅 발동이나 에러 스팬

코딩 에이전트 세션은 HTML 하나로 공유

오픈소스 claude-replay는 Claude Code, Cursor, Codex CLI, Gemini CLI 등의 세션 로그(~/.claude/projects/ 등)를 외부 파일 없이 열리는 HTML 하나로 만들어 준다. 메일로 보내거나 문서에 넣어 동료와 리뷰할 때 좋다. --serve --watch로 돌아가는 세션을 실시간으로 볼 수 있고, 계획을 승인해 새 세션이 생겼다면 세션 여러 개(최대 20개)를 하나로 이어 전체 흐름을 볼 수 있다.

공유 전에 민감 정보부터 확인

리플레이 파일에는 소스 코드, 파일 경로, 도구 입출력, 생각 과정까지 전부 들어간다. 기본 비밀값 가림 기능은 흔한 인증 정보 패턴만 잡고 코드나 파일 내용은 거르지 않는다. 공개하기 전에 생성된 파일을 직접 읽어 보는 게 안전하다.
